# 가상 여행 Timeline 4종

사용자가 지정한 국가·도시·날짜를 바탕으로 만든 **가상의 이동 기록**입니다. 실제 사진·위치 원본·개인 여행 경로는 읽지 않았습니다. 날짜와 지역은 요청값이며, 방문 시각·머문 위치·이동 방식·경유점·관측값은 창작입니다. 실제 여행이나 당시 교통 운행을 복원한 자료가 아닙니다.

## 실행과 사용

Node.js 24에서 프로젝트 루트의 다음 명령을 실행합니다.

```bash
node scripts/write-travel-examples.mjs
```

`private/travel-demo/`에 아래 4개 파일을 만듭니다. 기존 파일은 덮어쓰지 않습니다. 변경한 일정을 다시 생성하려면 기존 생성 파일을 다른 곳으로 옮긴 뒤 실행하세요. 생성기는 입력 파일을 읽거나 네트워크에 접근하지 않습니다.

| 파일 | 현지 날짜 | 일정 |
| --- | --- | --- |
| `fully-synthetic.austria.json` | 2023.08.03–08.10 | 비엔나, 08.08 잘츠부르크 당일 왕복 |
| `fully-synthetic.france.json` | 2024.07.31–08.06 | 안시, 08.03 샤모니 이동, 08.06 아침 출발 |
| `fully-synthetic.italy.json` | 2024.08.06–08.14 | 샤모니에서 볼차노로 이동, 08.13 밀라노 이동 |
| `fully-synthetic.japan.json` | 2025.10.22–10.29 | 후쿠오카, 10.24 사가 왕복, 10.25 구마모토 이동, 10.28 후쿠오카 복귀 |

[프로덕션](https://footprint-globe.vercel.app/) 또는 로컬 앱에서 **JSON 올리기**로 하나씩 선택합니다. 현재 앱이 읽는 `rawSignals[].position.LatLng/timestamp` 형식이며 가상 방문 이름을 실제 기록 필드로 추가하지 않았습니다. 현재 작업 브랜치에서는 등록 시 동의 후 주변 장소를 조회하며, 완료 후 장소별 보기로 전환할 수 있습니다. 배포 반영 여부와는 별개입니다.

유럽 파일의 시각은 해당 여름 기간 현지 시각 `+02:00`, 일본은 `+09:00`입니다. 현재 앱에는 UTC/KST 전환만 있어 유럽 현지 시각 표시와는 다릅니다. 프랑스의 마지막 점과 이탈리아의 첫 점은 같은 08.06 08:00 샤모니 위치입니다. 향후 파일들을 합칠 때 이 경계점의 중복을 고려해야 합니다.

## 도시 간 가상 이동 시간

이동에는 대기·시내 접근 등을 포함할 수 있도록 여유를 두었습니다. 다음은 **시연용으로 정한 시간**이며 실제 운행 시간표가 아닙니다.

| 날짜·구간 | 현지 시각 | 가상 소요 시간 |
| --- | --- | --- |
| 08.08 비엔나 → 잘츠부르크 | 07:00–10:00 | 3시간 |
| 08.08 잘츠부르크 → 비엔나 | 18:00–21:00 | 3시간 |
| 08.03 안시 → 샤모니 | 09:00–11:40 | 2시간 40분 |
| 08.06 샤모니 → 볼차노 | 08:00–16:30 | 8시간 30분 |
| 08.13 볼차노 → 밀라노 | 09:00–13:00 | 4시간 |
| 10.24 후쿠오카 ↔ 사가 | 09:00–10:00 / 18:00–19:00 | 편도 1시간 |
| 10.25 후쿠오카 → 구마모토 | 09:00–10:15 | 1시간 15분 |
| 10.28 구마모토 → 후쿠오카 | 09:00–10:15 | 1시간 15분 |

대략적인 이동 가능성을 검토할 때 참고한 공식 자료:

- [ÖBB 안내](https://www.oebb.at/dam/jcr%3A4b93792c-82d3-42ac-bb1d-bb32300bfbf9/oesterreich-mit-der-bahn-entdecken.pdf): 비엔나–잘츠부르크 철도 이동 안내. 가상 일정은 편도 3시간으로 구성했습니다.
- [샤모니 관광청](https://en.chamonix.com/plan-my-stay/usual-information-services/how-to-get-here): 안시–샤모니 접근 안내의 2시간 40분 참고.
- [샤모니–쿠르마유르 운송사](https://aosta.arriva.it/courmayeur-chamonix/): 몽블랑 터널을 통한 연결 참고. 이탈리아 구간은 쿠르마유르·아오스타·이브레아·밀라노·베로나·트렌토 방면의 가상 경유점으로 구성하고 8시간 30분을 배정했습니다. 실제 연계편 검증은 아닙니다.
- [Trenitalia](https://www.trenitalia.com/it/frecciarossa/collegamenti-frecciarossa/raggiungi-bolzano-con-frecciarossa.html): 밀라노–볼차노 연결 참고. 4시간은 접근·대기를 고려한 시연 가정입니다.
- [규슈 관광기구](https://www.visit-kyushu.com/en/destinations/saga/): 후쿠오카–사가 열차 약 40분 안내 참고. 가상 일정은 편도 1시간으로 구성했습니다.
- [JR 규슈 주요 역](https://www.jrkyushu.co.jp/english/guide/station.html): 연결 지역 확인용. 구마모토 이동 1시간 15분은 시연 가정이며 특정 열차의 소요 시간 주장이 아닙니다.

## 장소와 테스트 상황

`src/fixtures/travel.ts`의 `areas`에서 도시별 가상 거점과 방문 후보 영역 3곳을 관리합니다. 좌표는 도심·관광 지역의 대략적인 위치이며 실제 랜드마크의 입구나 건물 경계로 검증하지 않았습니다. 명칭을 알게 되면 이 위치와 하루 일정만 바꿔 다시 생성할 수 있습니다. 실제 호텔·사용자 방문 장소로 해석하지 마세요.

- 약 2분 간격 관측과 몇 m 수준의 정지 위치 흔들림
- 한 장소에 20–90분 머물기, 거점 복귀·다음 날 재방문
- 약 72m 떨어진 별도 정지 지점과 머물지 않고 통과하는 지점
- 야간 기록 공백과 도시 간 장거리 이동
- 도심에 모인 후보 영역, 인접한 후보 영역, 도시 사이 명소 없는 구간

이동은 가상 경유점 사이를 보간합니다. 도로·철도에 맞춘 경로가 아니므로 일부 선은 건물·지형을 가로지를 수 있습니다. 정지 위치의 흔들림은 실제 GPS 오차 모델이 아니며, 가상 데이터로 실제 방문 판별 정확도를 입증할 수 없습니다. 랜드마크 API 응답·장소 ID·방문 확정 정보는 넣지 않았습니다.

생성 JSON은 Git에서 제외하며 생성 소스와 테스트만 관리합니다. 테스트는 실제 앱 파서의 전체 수용, 날짜·시간대·정렬·범위, 도시 이동 시간, 순간 이동 방지, 프랑스–이탈리아 경계 연결을 확인합니다. `npm run check`로 실행합니다.
