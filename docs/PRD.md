# Footprint Globe — MVP PRD

> 최신 UI 결정: MapTiler가 스크롤 없는 전체 화면을 차지한다. 초기에는 한반도 전체를 표시하며 JSON 등록 시 기존 확대 수준을 유지한 채 첫 관측을 화면 중앙으로 이동한다. 상단 왼쪽에 JSON 올리기·지우기·UTC/한국 시간 버튼 전환·포인트 목록·시간별/거리별 분포를 가로 배치한다. 목록과 분포는 중앙 모달 창에서 확인하며 긴 내용은 창 안에서만 스크롤한다. 합성 예제 버튼과 드롭다운 UI는 제거한다. 관측 상세 말풍선과 실선 전용 연결을 유지하고 점선 정책은 제품 소유자가 추후 결정한다. 아래 이전 UI 설명은 이 결정 이전의 이력이다.

> 현행 결정: 방문은 사용자가 위치 관측점을 선택해 직접 지정한다. 원시 위치를 자동으로 방문으로 추론하지 않는다. 사진 첨부·미리보기·교체·제거는 MVP에서 제외하고 추후 확장 기능으로 남긴다. 사용자는 실제 원본을 로컬에서 보며 전체 연결 실선과 긴 공백 점선 표시를 비교하는 미리보기 구현을 승인했다. 공백을 이유로 연결을 끊지 않으며 최종 표시 기준은 실제 확인 후 정한다. 아래의 날짜별 일정은 초기 계획이며 현재 마감으로 재확정되지 않았다.

> 2026-10-06 추가 결정: 날짜·시각은 UTC와 한국 시간 전환을 지원한다. 전 세계 국가·지역·도시의 이름과 상세 경계를 확대 단계별로 표시해야 하며, [상세 지도 명세](../specs/2026-10-06-005-detailed-map.md)에서 MapTiler와 Google Maps를 비교한다. 사용자가 MapTiler 적합성을 확인하고 실제 기록 화면 통합 및 지도 조회에 필요한 외부 요청을 승인했다. Google Maps는 추후 확장으로 남긴다. Vercel 배포와 향후 Supabase 연동을 고려하되 현재 로그인·DB·영구 저장 기능을 추가하지 않는다. 사진 형식·개수·용량 정책은 MVP 결정 항목에서 제외하고 확장 개발 때 결정한다.

## 1. 제품 개요
**Footprint Globe**는 사용자가 Google Maps Timeline 데이터를 업로드하면, 과거 이동 기록을 인터랙티브한 **3D 지구본 위에 시각화**하는 웹 서비스입니다.

사용자는 지구본을 회전·확대·축소하며 방문 지점과 이동 경로를 탐색합니다. 특정 장소에 직접 사진을 첨부하는 기능은 MVP 이후 확장 범위입니다.

## 2. 목표
내일(10/7)까지 다음 경험이 완전히 동작하는 MVP를 완성합니다.

**Timeline JSON 업로드 → 데이터 파싱 → 3D 지구본 표시 → 이동 경로/방문지 탐색**

Google Maps Timeline은 사용자의 방문 장소와 경로를 기기 기반으로 저장합니다.

## 3. 핵심 사용자 플로우
1. 사용자가 Timeline JSON 파일을 선택합니다.
2. 앱이 데이터를 브라우저에서 파싱합니다.
3. 방문 지점과 이동 경로를 3D 지구본에 표시합니다.
4. 사용자가 지구본을 회전하거나 확대/축소합니다.
5. 위치 관측점을 선택하고 방문을 직접 지정합니다.
6. 날짜·위치 정보를 확인합니다.

## 4. MVP 기능

### 필수
- Timeline JSON 파일 업로드
- JSON 유효성 검사
- 방문 좌표 및 시간 추출
- 이동 경로 데이터 추출
- 3D 지구본 렌더링
- 드래그 회전
- 확대/축소
- 방문 지점 마커
- 이동 경로 라인
- 방문 지점 클릭
- 위치 관측점에서 사용자 지정 방문 생성
- 날짜/위치 상세 정보
- 국가·지역·도시 이름과 상세 경계의 확대 단계별 표시(지도 서비스 결정 후 구현)

`react-globe.gl`은 Points, Paths, 클릭 이벤트와 OrbitControls 기반 회전·줌을 제공합니다.

### 경로 처리
1. Timeline에 실제 경로 좌표가 있으면 그대로 사용
2. 실제 경로가 없을 때의 위치 점 연결은 기록 지점 사이의 흐름으로 구분한다. 로컬 미리보기에서는 모든 유효 관측을 시간순으로 연결하고, 긴 공백도 실선 또는 점선으로 이어 표시한다. 점선 시간차 기준은 사용자가 조절하는 시험값이며 최종 표시 정책은 실제 원본 확인 후 결정한다.

## 6. 데이터 처리

초기 MVP에서는 모든 사용자 데이터를 **브라우저 내부에서만 처리**합니다.

```text
Timeline JSON
    ↓
Parser
    ↓
Normalized Data
    ├─ observations[] (위치·시각 관측)
    ├─ recordedVisits[] (원본에 명시된 방문)
    └─ recordedPaths[] (원본에 명시된 경로)
         ↓
    3D Globe
         ↓
    관측 선택 → 사용자 지정 방문
```

공통 자료형은 `src/domain/timeline.ts`를 기준으로 한다. 파서 출력과 사용자 지정 방문·사진 상태를 분리한다. 사용자 지정 방문은 별도 ID와 데이터셋 ID, 선택한 관측점 ID를 가진다. 같은 좌표의 재방문도 서로 다른 방문으로 유지하며 원본에 없는 체류 시작·종료 시각을 만들어 넣지 않는다.

사진 자료형은 확장 개발을 위해 남겨 두며 MVP에서는 사진을 선택·처리하지 않습니다. 기존 Object URL 기반 세션 처리 설계는 추후 확장 참고이며, 실제 도입 시 형식·개수·용량 및 자원 정리 정책을 확정합니다.

## 9. 예외 처리
다음 상황에서는 앱이 깨지지 않고 오류 메시지를 표시합니다.

- JSON이 아닌 파일
- 지원하지 않는 Timeline 구조
- 위치 기록 없음
- 좌표 누락
- 경로 데이터 누락
- 매우 큰 데이터셋

경로가 없는 경우 관측 데이터와 기록된 경로를 구분한다. 로컬 미리보기의 연결은 실제 경로로 표현하지 않으며, 잘못된 기록을 제외했다면 건수와 유효 관측 사이를 연결했다는 사실을 알린다.

## 10. 성공 기준
다음 5개가 실제 데모에서 동작하면 MVP 성공으로 판단합니다.

- Timeline JSON을 업로드할 수 있다.
- 여행 기록이 3D 지구본에 표시된다.
- 지구본을 자유롭게 회전/확대/축소할 수 있다.
- 지점을 클릭해 방문 정보를 볼 수 있다.
- 확대 단계에 맞춰 국가·지역·도시 이름과 경계를 확인할 수 있다.

## 15. 개발 원칙
이번 프로젝트에서 가장 중요한 것은 기능 수가 아니라 **완성된 핵심 경험**입니다.

따라서 개발 우선순위는:

**Timeline parsing → Globe → Route → Visit interaction**

순서를 유지하고, MVP 핵심 흐름이 완성되기 전에는 사진 등 확장 기능을 구현하지 않습니다.
