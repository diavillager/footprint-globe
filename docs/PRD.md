# Footprint Globe — MVP PRD

> 2026-10-07 최신 시험 결정: 사용자가 Geoapify 대신 Wikipedia·Wikidata·Commons 연결과 검증을 요청했다. 개발 앱은 일본어·영어 Wikipedia의 지역별 좌표 문서를 대조하고 Wikidata P18·해당 문서의 자유 이용 대표 사진을 Commons에서 조회한다. Geoapify 자동 요청·fallback은 없다. 기존 MapTiler·파일별 전송 동의·원본 보존·300m 대조·장소 중심 묶기·세션 메모리 정책은 유지한다. 아래 Geoapify 설명은 이전 단계의 이력이며 공급자 관련 현행 기준은 랜드마크 명세의 Wikimedia 시험 절을 따른다.
> 2026-10-07 확장 결정: JSON 등록 시 원본 경로를 표시하고, 파일별 전송 동의 후 Geoapify로 원본 포인트 주변 300m를 덮는 작은 구역의 장소를 먼저 조회한다. 구역 중복 제거·페이지 조회·밀집 구역 세분화 후 장소 ID를 통합하고 로컬에서 원본 포인트와 대조한다. 같은 최근접 장소에 연결된 연속 기록에서 그 장소에 가장 가까운 관측을 대표점으로 정해 주변 100m 이내를 묶고 인접 공백 120분 초과·장소 변경·미연결 기록은 분리한다. 전체 원본과 재방문 identity를 유지한다. 조회 실패·수집 미완료는 후보 없음과 구분한다. MapTiler 지도에 조회된 가장 가까운 추정 장소만 말풍선으로 표시하고 클릭하면 후보·세부정보를 연다. JSON 등록 때 동의 안내를 먼저 열고 원형 진행 표시와 원본 경로/장소별 보기 전환을 제공한다. 동의 후에도 원본 경로가 기본이며 장소·사진 처리가 완료되어야 장소별 보기를 활성화하고 자동 전환하지 않는다. 위치 기록·통합 기록 분포를 사용한다. Place Details에서 연결된 Wikimedia 이미지가 있으면 사진·출처 링크를 표시하고 없으면 텍스트를 유지한다. 사용자 결정으로 파일당 요청 횟수 제한을 없앴다. 동시 최대 3건·250ms 시작 간격·동일 구역/장소 재사용·지역 조회와 원본 대조 후 연결된 장소 사진 조회·10초 제한·자동 재시도 없음이며 인증·사용량 오류 시 중지한다. 실제 방문 확정·영구 저장은 하지 않는다. [랜드마크 명세](../specs/2026-10-07-000-landmark-integration.md)를 따르며 배포 완료를 뜻하지 않는다.

> 2026-10-06 배포 결정: 사용자 지정 방문은 사진 등록과 함께 추후 확장으로 진행하며 현재 MVP와 Vercel 배포의 완료 조건에서 제외한다. 아래 방문 지정·사진 계약은 확장 참고로 유지한다. 배포는 [Vercel 명세](../specs/2026-10-06-006-vercel-deploy.md)를 따른다.

> 최신 UI 결정: MapTiler가 스크롤 없는 전체 화면을 차지한다. 초기에는 한반도 전체를 표시하며 JSON 등록 시 전체 기록 범위를 표시한다. 상단 왼쪽에 JSON 올리기·지우기·UTC/한국 시간 버튼 전환·위치 기록·기록 분포·원형 매핑 진행 표시를 가로 배치한다. 목록과 분포는 중앙 모달 창에서 확인하며 긴 내용은 창 안에서만 스크롤한다. 합성 예제 버튼과 드롭다운 UI는 제거한다. 관측 상세는 중앙 창에서 열고 실선 전용 연결을 유지하며 점선 정책은 제품 소유자가 추후 결정한다. 아래 이전 UI 설명은 이 결정 이전의 이력이다.

> 확장 설계: 방문 지정은 사진 등록과 함께 추후 구현하며, 사용자가 위치 관측점을 선택해 직접 지정한다. 원시 위치를 자동으로 방문으로 추론하지 않는다. 사진 첨부·미리보기·교체·제거는 MVP에서 제외하고 추후 확장 기능으로 남긴다. 사용자는 실제 원본을 로컬에서 보며 전체 연결 실선과 긴 공백 점선 표시를 비교하는 미리보기 구현을 승인했다. 공백을 이유로 연결을 끊지 않으며 최종 표시 기준은 실제 확인 후 정한다. 아래의 날짜별 일정은 초기 계획이며 현재 마감으로 재확정되지 않았다.

> 2026-10-06 추가 결정: 날짜·시각은 UTC와 한국 시간 전환을 지원한다. 전 세계 국가·지역·도시의 이름과 상세 경계를 확대 단계별로 표시해야 하며, [상세 지도 명세](../specs/2026-10-06-005-detailed-map.md)에서 MapTiler와 Google Maps를 비교한다. 사용자가 MapTiler 적합성을 확인하고 실제 기록 화면 통합 및 지도 조회에 필요한 외부 요청을 승인했다. Google Maps는 추후 확장으로 남긴다. Vercel 배포와 향후 Supabase 연동을 고려하되 현재 로그인·DB·영구 저장 기능을 추가하지 않는다. 사진 형식·개수·용량 정책은 MVP 결정 항목에서 제외하고 확장 개발 때 결정한다.

## 1. 제품 개요
**Footprint Globe**는 사용자가 Google Maps Timeline 데이터를 업로드하면, 과거 이동 기록을 인터랙티브한 **3D 지구본 위에 시각화**하는 웹 서비스입니다.

사용자는 지구본을 회전·확대·축소하며 방문 지점과 이동 경로를 탐색합니다. 특정 장소에 직접 사진을 첨부하는 기능은 MVP 이후 확장 범위입니다.

## 2. 목표
내일(10/7)까지 다음 경험이 완전히 동작하는 MVP를 완성합니다.

**Timeline JSON 업로드 → 데이터 파싱 → 3D 지구본 표시 → 이동 경로/방문지 탐색**

Google Maps Timeline은 사용자의 방문 장소와 경로를 기기 기반으로 저장합니다.

## 3. 핵심 사용자 플로우
1. 사용자가 Timeline JSON 파일을 선택합니다.
2. 앱이 데이터를 브라우저에서 파싱합니다.
3. 방문 지점과 이동 경로를 3D 지구본에 표시합니다.
4. 사용자가 지구본을 회전하거나 확대/축소합니다.
5. 위치 관측점을 선택합니다. 방문 지정은 사진 등록과 함께 추후 확장합니다.
6. 날짜·위치 정보를 확인합니다.

## 4. MVP 기능

### 현재 배포 범위

2026-10-06 배포 명세에서 확정한 현재 입력은 `rawSignals` 위치 관측이며, 한도는 64 MiB·100,000개 신호다. 유효 관측을 시간순으로 실선 연결하고 관측 선택·UTC/KST·목록·시간차/거리 분포를 제공한다. 연결선은 실제 이동 경로를 복원한 결과가 아니다.

원본에 명시된 방문·경로를 읽는 파서와 `semanticSegments`·`timelineObjects` 앱 입력은 미지원이다. 샘플 생성기의 지원 형식과 앱의 지원 형식은 다르다. 아래 초기 요구사항 중 방문·이동 경로 추출은 현재 배포에 구현된 것으로 보지 않으며, 지원 확대 시 별도 결정과 검증이 필요하다. 이는 원래 요구사항을 삭제하거나 지원 확대를 승인하는 변경이 아니다.

### 초기 요구사항 목록(현재 구현 여부는 위 배포 범위 기준)
- Timeline JSON 파일 업로드
- JSON 유효성 검사
- 방문 좌표 및 시간 추출
- 이동 경로 데이터 추출
- 3D 지구본 렌더링
- 드래그 회전
- 확대/축소
- 방문 지점 마커
- 이동 경로 라인
- 방문 지점 클릭
- 위치 관측점 선택과 상세 확인
- 날짜/위치 상세 정보
- 국가·지역·도시 이름과 상세 경계의 확대 단계별 표시(지도 서비스 결정 후 구현)

`react-globe.gl`은 Points, Paths, 클릭 이벤트와 OrbitControls 기반 회전·줌을 제공합니다.

### 경로 처리
1. Timeline에 실제 경로 좌표가 있으면 그대로 사용
2. 실제 경로가 없을 때의 위치 점 연결은 기록 지점 사이의 흐름으로 구분한다. 로컬 미리보기에서는 모든 유효 관측을 시간순으로 연결하고, 긴 공백도 실선 또는 점선으로 이어 표시한다. 점선 시간차 기준은 사용자가 조절하는 시험값이며 최종 표시 정책은 실제 원본 확인 후 결정한다.

## 6. 데이터 처리

초기 MVP에서는 모든 사용자 데이터를 **브라우저 내부에서만 처리**합니다.

```text
Timeline JSON
    ↓
Parser
    ↓
Normalized Data
    ├─ observations[] (위치·시각 관측)
    ├─ recordedVisits[] (원본에 명시된 방문)
    └─ recordedPaths[] (원본에 명시된 경로)
         ↓
    3D Globe
         ↓
    관측 선택 → 날짜·좌표 상세 확인
    (추후 확장: 사용자 지정 방문 → 사진 등록)
```

공통 자료형은 `src/domain/timeline.ts`를 기준으로 한다. 파서 출력과 사용자 지정 방문·사진 상태를 분리한다. 사용자 지정 방문은 별도 ID와 데이터셋 ID, 선택한 관측점 ID를 가진다. 같은 좌표의 재방문도 서로 다른 방문으로 유지하며 원본에 없는 체류 시작·종료 시각을 만들어 넣지 않는다.

사진 자료형은 확장 개발을 위해 남겨 두며 MVP에서는 사진을 선택·처리하지 않습니다. 기존 Object URL 기반 세션 처리 설계는 추후 확장 참고이며, 실제 도입 시 형식·개수·용량 및 자원 정리 정책을 확정합니다.

## 9. 예외 처리
다음 상황에서는 앱이 깨지지 않고 오류 메시지를 표시합니다.

- JSON이 아닌 파일
- 지원하지 않는 Timeline 구조
- 위치 기록 없음
- 좌표 누락
- 경로 데이터 누락
- 매우 큰 데이터셋

경로가 없는 경우 관측 데이터와 기록된 경로를 구분한다. 로컬 미리보기의 연결은 실제 경로로 표현하지 않으며, 잘못된 기록을 제외했다면 건수와 유효 관측 사이를 연결했다는 사실을 알린다.

7. UTC·한국 시간 전환으로 관측 시각 확인
8. 국가·지역·도시 이름과 경계를 확대하며 확인

## 15. 개발 원칙
이번 프로젝트에서 가장 중요한 것은 기능 수가 아니라 **완성된 핵심 경험**입니다.

따라서 개발 우선순위는:

**Timeline parsing → Globe → Route → Visit interaction**

순서를 유지하고, MVP 핵심 흐름이 완성되기 전에는 사진 등 확장 기능을 구현하지 않습니다.
