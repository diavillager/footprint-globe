# Footprint Globe

## 1. 프로젝트 개요

**Footprint Globe는 Google Timeline의 위치 기록을 지구본 위에서 살펴보는 웹 앱입니다.**

위치 기록 파일을 선택하면 기록된 장소가 점으로 표시되고, 시간순으로 연결됩니다. 지구본을 움직이며 발자취를 살펴보고 각 지점의 시각과 좌표를 확인할 수 있습니다.

**[프로덕션 바로가기 → footprint-globe.vercel.app](https://footprint-globe.vercel.app/)**

현재 제공하는 기능은 다음과 같습니다.

- Google Timeline JSON 파일 불러오기
- 상세 지도 위에 위치 기록과 연결선 표시
- 위치별 상세 정보와 시간순 목록 확인
- 기록 사이의 시간차·거리 분포 확인
- UTC와 한국 시간(KST) 전환

연결선은 **기록된 위치를 시간순으로 이은 선**입니다. 실제로 지나간 도로나 이동 경로를 복원한 것은 아닙니다. 거리 분포 역시 지점 사이의 지표면 최단 거리를 나타내며 실제 이동 거리는 아닙니다.

현재는 Google Timeline의 `rawSignals` 형식에 포함된 위치 관측 기록을 지원합니다. 모든 Timeline 내보내기 형식을 지원하지는 않습니다. 방문 장소 직접 지정과 사진 등록은 아직 제공하지 않습니다.

선택한 JSON은 브라우저 안에서 처리하며 서버에 업로드하거나 영구 저장하지 않습니다. 다만 배경 지도를 불러오기 위해 MapTiler에 요청을 보내므로 IP 주소와 열람 지역·확대 수준이 전달될 수 있습니다. JSON 본문·파일명·관측 시각은 보내지 않습니다.

## 2. 프로젝트 구조

앱 화면, 데이터 처리, 보조 도구를 나누어 관리합니다.

```text
footprint-globe/
├─ src/                    웹 앱
│  ├─ app/                 앱의 기본 화면과 스타일
│  ├─ features/preview/    지도, 위치 목록, 상세 정보
│  ├─ parser/              위치 기록 읽기와 유효성 검사
│  ├─ domain/              데이터의 공통 형식
│  └─ fixtures/            테스트용 데이터
├─ tools/                  로컬에서 사용하는 보조 도구
│  ├─ timeline-sample/     가상 샘플 생성과 구조 진단
│  └─ maptiler-check/      지도 표시 검증
├─ tests/                  기능·브라우저 테스트
├─ scripts/                로컬 실행 보조 스크립트
├─ docs/                   제품 요구사항과 참고 문서
├─ specs/                  기능별 개발 명세
└─ AGENTS.md               개발 작업과 개인정보 취급 지침
```

제품 요구사항은 [PRD](docs/PRD.md), 기능별 세부 내용은 [개발 명세](specs/), 개발 작업 원칙은 [AGENTS.md](AGENTS.md)에서 확인할 수 있습니다. 배포 설정은 [Vercel 배포 명세](specs/2026-10-06-006-vercel-deploy.md)를 참고하세요.

실제 위치 원본과 원본에서 만든 샘플은 Git에 올리지 않습니다. 개인 파일은 저장소 밖이나 Git에서 제외된 `private/` 폴더에 보관하세요.

## 3. 사용 방법

### 웹에서 사용하기

1. [Footprint Globe](https://footprint-globe.vercel.app/)에 접속합니다.
2. **JSON 올리기**를 눌러 Google Timeline 파일을 선택합니다.
3. 지도를 드래그하거나 확대·축소하며 위치 기록을 살펴봅니다.
4. 점을 누르면 해당 위치의 시각과 좌표를 확인할 수 있습니다.
5. **포인트 목록**, **시간별 분포**, **거리별 분포**, **UTC/KST** 버튼으로 기록을 다른 방식으로 살펴봅니다.
6. 확인을 마치면 **지우기**를 누릅니다.

새로고침하거나 탭을 닫으면 불러온 기록은 유지되지 않습니다.

**지원 범위**

- 입력: `rawSignals` 위치 기록을 포함한 Google Timeline JSON
- 크기: 최대 64 MiB, 원시 신호 100,000개
- `semanticSegments`, `timelineObjects` 형식과 삼성 헬스 파일은 현재 앱에서 지원하지 않음
- 좌표나 시각이 잘못된 기록은 제외하고 건수로 안내하며, 그 앞뒤의 유효 위치를 연결
- 브라우저의 WebGL 지원 필요

### 내 컴퓨터에서 실행하기

Node.js 22.12 이상과 npm이 필요합니다. 프로젝트 폴더에서 다음 명령으로 필요한 패키지를 설치합니다.

```bash
npm ci
```

지도 표시를 위해 프로젝트 루트의 `.env.local`에 MapTiler 키를 설정합니다.

```dotenv
VITE_MAPTILER_API_KEY=발급받은_지도_키
```

MapTiler 키의 허용 주소에 로컬 실행 주소를 등록한 뒤 앱을 실행합니다. 운영용 키는 로컬 주소를 허용하지 않을 수 있으므로 개발용 설정을 별도로 확인하세요. `.env.local`은 Git에 올리지 않습니다.

```bash
npm run dev
```

터미널에 표시된 주소를 브라우저에서 엽니다. 종료하려면 터미널에서 `Ctrl+C`를 누릅니다. 지도 키를 변경했다면 개발 서버를 다시 시작하세요.

검증과 빌드는 다음 명령을 사용합니다.

| 명령 | 용도 |
| --- | --- |
| `npm run check` | 타입 검사·자동 테스트·빌드를 한 번에 실행 |
| `npm run build` | 배포용 앱 생성 |
| `npm run preview` | 빌드한 앱을 로컬에서 확인 |

### 로컬 샘플 생성기 사용하기

원본 대신 개발에 사용할 작은 가상 샘플이 필요할 때 사용합니다.

1. [샘플 생성기](tools/timeline-sample/index.html)를 내려받은 저장소에서 Chrome 또는 Edge로 직접 엽니다.
2. **로컬 Timeline JSON 선택**에서 원본 파일을 선택합니다.
3. 처리·제외 건수와 경고를 확인합니다.
4. 생성에 성공하면 **가상 샘플 JSON 저장**으로 별도 파일을 저장합니다. 원본을 덮어쓰지 마세요.

이 도구는 서버 설치나 로그인 없이 로컬에서 동작하며 네트워크 요청을 보내지 않습니다. 실제 좌표·날짜·장소명·식별 정보를 가상 값으로 바꾸고, 안전하게 처리할 수 없는 기록은 제외합니다.

기록 사이의 시간 간격과 반복 관계 등은 남으므로 완전한 익명성을 보장하지 않습니다. 공유 전 실제 장소·좌표·날짜·식별 정보가 남아 있지 않은지 직접 확인하세요. 원본과 생성한 샘플은 Git에 올리지 않습니다.

샘플 생성기와 앱의 지원 범위는 다릅니다. 샘플 생성 성공이 전체 원본의 앱 호환성을 보장하지는 않으며, 실제 파일은 사용자가 앱에서 직접 확인합니다.

### 테스트·시연용 가상 여행

오스트리아·프랑스·이탈리아·일본의 가상 여행 JSON을 생성할 수 있습니다. Node.js 24에서 `node scripts/write-travel-examples.mjs`를 실행한 뒤 `private/travel-demo/`의 파일을 **JSON 올리기**로 선택하세요. 날짜·도시 이동 가정과 장소 수정 방법은 [가상 여행 안내](docs/travel-demo.md)를 참고하세요.

### 개발 브랜치의 랜드마크 기능

`codex/landmark-footprints`에서 구현 중이며 운영 사이트 배포 상태와 구별합니다. JSON을 등록하면 첫 관측 기준 100m·인접 공백 120분 이내의 관측을 자동으로 묶고 전체 여행 범위를 표시합니다. 별도 묶기 토글은 없습니다. 원본 목록·분포는 그대로 유지합니다.

여행일지에서 **동의하고 여행 장소 자동 표시**를 누르면 전체 지점의 장소를 시간순으로 자동 조회합니다. Geoapify로 대표 좌표·검색 조건이 전달되며 IP·앱 출처도 전달될 수 있습니다. JSON·파일명·시각·기록 ID는 보내지 않습니다. 300m 안의 관광 명소·볼거리·박물관 중 가장 가까운 후보를 추정 표시하며 실제 방문 확정이 아닙니다.

순번·시간·장소명 말풍선을 지도와 시간순 여행일지에 표시합니다. 지도에서는 겹침을 줄이고, 모든 지점은 여행일지 페이지에서 탐색합니다. Geoapify Place Details에 지원하는 Wikimedia 원본 이미지가 있으면 사진과 출처 링크를 표시하고, 없거나 실패하면 텍스트를 유지합니다. 사진은 Wikimedia에 직접 요청하며 Referrer를 보내지 않습니다.

사용자 결정에 따라 **파일당 요청 횟수 제한은 없습니다.** 동시 1건·300ms 간격·요청당 10초 제한·자동 재시도 없음이며 인증·사용량 오류 때 중단합니다. 장소·사진 상세 요청 수를 표시합니다. 성공·빈 결과는 파일 세션 메모리에 재사용하고 파일 교체·지우기·새로고침 때 삭제합니다. 자동 조회 중지·결과 지우기는 요청을 취소하되 이미 보낸 요청을 회수하지 못합니다. 계정 할당량과 비용은 별도로 적용됩니다.

로컬에서 실제 검색을 사용하려면 `.env.local`에 공개 브라우저용 `VITE_GEOAPIFY_API_KEY`를 설정하고 Geoapify에서 정확한 로컬 origin을 허용한 뒤 개발 서버를 재시작합니다. 기존 비교 프리뷰의 서버용 `GEOAPIFY_API_KEY`는 자동으로 재사용하지 않습니다. 키가 없어도 기존 지도·목록과 관측 묶기를 사용할 수 있습니다. 운영 환경·요금제·허용 origin은 별도로 확인해야 합니다.

검증은 `npm run check`와 Playwright·Edge가 있는 환경에서 `node tests/app-smoke.cjs`, `node tests/landmark-smoke.cjs`를 사용합니다. 랜드마크 smoke는 네 합성 여행과 모의 지도·API 응답만 사용하며 실제 API 요청을 보내지 않습니다. 기준과 남은 실제 연결 확인은 [랜드마크 명세](specs/2026-10-07-000-landmark-integration.md)를 참고하세요.

브라우저 파일 접근 권한 없이 합성 자료로 실제 지도·API를 확인하려면 [로컬 합성 연결 검증](tools/landmark-live-check/README.md)을 사용합니다. 이 별도 화면은 실제 계정 사용량을 소비하며 프로덕션 빌드에는 포함되지 않습니다.

## 4. 사용한 기술 스택

| 기술 | 역할 |
| --- | --- |
| **React · TypeScript** | 화면을 구성하고 데이터 처리 과정의 오류를 줄입니다. |
| **Vite** | 개발 서버를 실행하고 배포용 앱을 만듭니다. |
| **MapLibre GL JS** | 지구본과 위치 점·연결선을 화면에 그립니다. |
| **MapTiler** | 지명·도로·경계가 포함된 배경 지도 자료를 제공합니다. |
| **CSS** | 화면 배치와 디자인을 구성합니다. |
| **Web Worker** | 파일 처리 중에도 화면을 조작할 수 있도록 작업을 분리합니다. |
| **Vitest · Node.js 테스트 · Playwright** | 데이터 처리와 브라우저 동작을 검증합니다. |
| **Vercel** | 웹 앱을 배포합니다. |

현재는 별도의 로그인 서버나 데이터베이스를 사용하지 않습니다.
