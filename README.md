# Footprint Globe

## 1. 프로젝트 개요

**Footprint Globe는 Google Timeline의 위치 기록을 지구본 위에서 살펴보는 웹 앱입니다.**

위치 기록 파일을 선택하면 기록된 장소가 점으로 표시되고, 시간순으로 연결됩니다. 지구본을 움직이며 발자취를 살펴보고 각 지점의 시각과 좌표를 확인할 수 있습니다.

**[프로덕션 바로가기 → footprint-globe.vercel.app](https://footprint-globe.vercel.app/)**

현재 제공하는 기능은 다음과 같습니다.

- Google Timeline JSON 파일 불러오기
- 상세 지도 위에 위치 기록과 연결선 표시
- 위치별 상세 정보와 시간순 목록 확인
- 기록 사이의 시간차·거리 분포 확인
- UTC와 한국 시간(KST) 전환

연결선은 **기록된 위치를 시간순으로 이은 선**입니다. 실제로 지나간 도로나 이동 경로를 복원한 것은 아닙니다. 거리 분포 역시 지점 사이의 지표면 최단 거리를 나타내며 실제 이동 거리는 아닙니다.

현재는 Google Timeline의 `rawSignals` 형식에 포함된 위치 관측 기록을 지원합니다. 모든 Timeline 내보내기 형식을 지원하지는 않습니다. 방문 장소 직접 지정과 사진 등록은 아직 제공하지 않습니다.

선택한 JSON은 브라우저 안에서 처리하며 서버에 업로드하거나 영구 저장하지 않습니다. 다만 배경 지도를 불러오기 위해 MapTiler에 요청을 보내므로 IP 주소와 열람 지역·확대 수준이 전달될 수 있습니다. JSON 본문·파일명·관측 시각은 보내지 않습니다.

앱 화면, 데이터 처리, 보조 도구를 나누어 관리합니다.

```text
footprint-globe/
├─ src/                    웹 앱
│  ├─ app/                 앱의 기본 화면과 스타일
│  ├─ features/preview/    지도, 위치 목록, 상세 정보
│  ├─ parser/              위치 기록 읽기와 유효성 검사
│  ├─ domain/              데이터의 공통 형식
│  └─ fixtures/            테스트용 데이터
├─ tools/                  로컬에서 사용하는 보조 도구
│  ├─ timeline-sample/     가상 샘플 생성과 구조 진단
│  └─ maptiler-check/      지도 표시 검증
├─ tests/                  기능·브라우저 테스트
├─ scripts/                로컬 실행 보조 스크립트
├─ docs/                   제품 요구사항과 참고 문서
├─ specs/                  기능별 개발 명세
```

제품 요구사항은 [PRD](docs/PRD.md), 기능별 세부 내용은 [개발 명세](specs/), 개발 작업 원칙은 [AGENTS.md](AGENTS.md)에서 확인할 수 있습니다. 배포 설정은 [Vercel 배포 명세](specs/2026-10-06-006-vercel-deploy.md)를 참고하세요.

실제 위치 원본과 원본에서 만든 샘플은 Git에 올리지 않습니다. 개인 파일은 저장소 밖이나 Git에서 제외된 `private/` 폴더에 보관하세요.

## 3. 사용 방법

### 웹에서 사용하기

1. [Footprint Globe](https://footprint-globe.vercel.app/)에 접속합니다.
2. **JSON 올리기**를 눌러 Google Timeline 파일을 선택합니다.
3. 지도를 드래그하거나 확대·축소하며 위치 기록을 살펴봅니다.
4. 점을 누르면 해당 위치의 시각과 좌표를 확인할 수 있습니다.
5. **위치 기록**, **기록 분포**(시간 간격·이동 거리), **원본 경로/장소별 보기**, **UTC/KST** 버튼으로 기록을 다른 방식으로 살펴봅니다.
6. 확인을 마치면 **지우기**를 누릅니다.

새로고침하거나 탭을 닫으면 불러온 기록은 유지되지 않습니다.

**지원 범위**

- 입력: `rawSignals` 위치 기록을 포함한 Google Timeline JSON
- 크기: 최대 64 MiB, 원시 신호 100,000개
- `semanticSegments`, `timelineObjects` 형식과 삼성 헬스 파일은 현재 앱에서 지원하지 않음
- 좌표나 시각이 잘못된 기록은 제외하고 건수로 안내하며, 그 앞뒤의 유효 위치를 연결
- 브라우저의 WebGL 지원 필요

### 내 컴퓨터에서 실행하기

Node.js 22.12 이상과 npm이 필요합니다. 프로젝트 폴더에서 다음 명령으로 필요한 패키지를 설치합니다.

```bash
npm ci
```

지도 표시를 위해 프로젝트 루트의 `.env.local`에 MapTiler 키를 설정합니다.

```dotenv
VITE_MAPTILER_API_KEY=발급받은_지도_키
```

MapTiler 키의 허용 주소에 로컬 실행 주소를 등록한 뒤 앱을 실행합니다. 운영용 키는 로컬 주소를 허용하지 않을 수 있으므로 개발용 설정을 별도로 확인하세요. `.env.local`은 Git에 올리지 않습니다.

```bash
npm run dev
```

터미널에 표시된 주소를 브라우저에서 엽니다. 종료하려면 터미널에서 `Ctrl+C`를 누릅니다. 지도 키를 변경했다면 개발 서버를 다시 시작하세요.

검증과 빌드는 다음 명령을 사용합니다.

| 명령 | 용도 |
| --- | --- |
| `npm run check` | 타입 검사·자동 테스트·빌드를 한 번에 실행 |
| `npm run build` | 배포용 앱 생성 |
| `npm run preview` | 빌드한 앱을 로컬에서 확인 |

### 로컬 샘플 생성기 사용하기

원본 대신 개발에 사용할 작은 가상 샘플이 필요할 때 사용합니다.

1. [샘플 생성기](tools/timeline-sample/index.html)를 내려받은 저장소에서 Chrome 또는 Edge로 직접 엽니다.
2. **로컬 Timeline JSON 선택**에서 원본 파일을 선택합니다.
3. 처리·제외 건수와 경고를 확인합니다.
4. 생성에 성공하면 **가상 샘플 JSON 저장**으로 별도 파일을 저장합니다. 원본을 덮어쓰지 마세요.

이 도구는 서버 설치나 로그인 없이 로컬에서 동작하며 네트워크 요청을 보내지 않습니다. 실제 좌표·날짜·장소명·식별 정보를 가상 값으로 바꾸고, 안전하게 처리할 수 없는 기록은 제외합니다.

기록 사이의 시간 간격과 반복 관계 등은 남으므로 완전한 익명성을 보장하지 않습니다. 공유 전 실제 장소·좌표·날짜·식별 정보가 남아 있지 않은지 직접 확인하세요. 원본과 생성한 샘플은 Git에 올리지 않습니다.

샘플 생성기와 앱의 지원 범위는 다릅니다. 샘플 생성 성공이 전체 원본의 앱 호환성을 보장하지는 않으며, 실제 파일은 사용자가 앱에서 직접 확인합니다.

### 테스트·시연용 가상 여행

오스트리아·프랑스·이탈리아·일본의 가상 여행 JSON을 생성할 수 있습니다. Node.js 24에서 `node scripts/write-travel-examples.mjs`를 실행한 뒤 `private/travel-demo/`의 파일을 **JSON 올리기**로 선택하세요. 날짜·도시 이동 가정과 장소 수정 방법은 [가상 여행 안내](docs/travel-demo.md)를 참고하세요.

### 개발 브랜치의 랜드마크 기능

`codex/landmark-footprints`에서 구현 중이며 운영 사이트 배포 상태와 구별합니다. JSON을 등록하면 묶지 않은 원본 경로와 전체 여행 범위를 표시합니다. 매핑을 허용하면 원본 포인트 주변 지역의 장소를 먼저 모으고, 각 포인트를 가장 가까운 장소와 대조한 후 장소별로 묶습니다. 같은 장소에 연결된 연속 기록에서 장소와 가장 가까운 원본 관측을 대표점으로 삼아 주변 100m 이내를 묶으며 인접 공백이 120분을 넘으면 분리합니다. 장소 변경·미연결 기록도 묶음을 나누므로 같은 장소 재방문은 별도로 유지합니다. 별도 묶기 토글은 없습니다. 원본 목록·분포는 그대로 유지합니다.

현재 개발 브랜치의 장소 소스는 **Wikipedia·Wikidata·Commons 시험 연결**입니다. Geoapify를 자동 호출하거나 실패 시 대체 호출하지 않습니다. MapTiler 지도는 그대로 사용합니다. Wikimedia에는 API 키가 필요하지 않습니다.

JSON 등록 후 자동 안내에서 **허용하고 장소 매핑**을 선택해야 검색합니다. 원본 주변 300m를 덮는 구역 경계를 일본어·영어 Wikipedia로 전송하고 같은 Wikidata ID는 합칩니다. 원본 JSON·파일명·시각·기록 ID는 보내지 않습니다. 도시·행정구역·사건으로 분류된 문서는 제외하지만 일반 시설도 포함될 수 있고, 좌표가 없는 문서와 미등재 장소는 찾지 못합니다. 분류는 원문 좌표 유형에 따라 ‘명소·시설’, ‘산’ 등으로 표시하며 모르는 분류를 임의로 관광지로 확정하지 않습니다.

장소 이름은 기존 지역 검색 응답에 한국어 Wikidata 이름과 한국어 Wikipedia 문서 제목을 함께 요청하여 한국어 이름 → 한국어 문서 제목 → 원문 순으로 표시합니다. 한국어 이름이 없는 장소는 원문을 유지하며 임의로 번역하지 않습니다. 상세 화면에서는 현지 이름도 확인할 수 있습니다. 이름 표시만 바꾸며 장소 ID·좌표·묶음 기준은 유지합니다.

조회된 지점에만 최근접 후보의 이름·분류·시간을 말풍선으로 표시합니다. 클릭하면 중앙 상세창 왼쪽에 후보 목록, 오른쪽에 선택 장소 정보·사진·원문 링크를 표시합니다. 사진은 해당 Wikidata 항목의 P18을 우선 확인하고, 없거나 Commons에 없는 파일이면 같은 Wikipedia 문서의 자유 이용 대표 이미지로 보완합니다. Commons에서 저작자·라이선스를 확인한 사진만 사용하고 주변 다른 장소의 사진을 대신 붙이지 않습니다. 사진은 Wikimedia에서 직접 불러오며 Referrer를 보내지 않습니다.

장소별 보기의 **화면 하단 번호 띠**는 랜드마크에 연결된 지점만 시간순으로 `(1)—(2)—(3)`처럼 표시합니다. 배경 패널·제목·화살표·스크롤바 없이 연결선과 번호만 보입니다. 같은 장소의 재방문은 별도 번호로 유지하고 미연결 원본 관측은 포함하지 않습니다. 처음에는 맨 왼쪽이며 마우스나 손가락으로 누른 채 가로로 드래그하거나 휠로 넘깁니다. 드래그를 끝낼 때 번호가 선택되지는 않습니다. 번호를 누르면 해당 지점이 지도 중앙으로 부드럽게 이동하며 상세 확대 수준(줌 16)까지 확대됩니다. 이미 더 확대돼 있으면 현재 확대 수준을 유지하며, 운영체제의 동작 줄이기 설정을 따릅니다. 번호 선택만으로 상세창은 열리지 않고 지도 지점·말풍선을 클릭하면 기존 상세정보가 열립니다. 선택 번호는 초록색과 테두리로 강조하고 지도 이동·바깥 클릭·Escape 시 해제합니다.

장소별 지도의 점·말풍선은 같은 장소 ID를 하나로 통합합니다. 통합 위치는 그 장소에 연결된 대표 관측 중 장소와 가장 가까운 실제 기록 위치이며, 원본 좌표를 바꾸지 않습니다. 같은 이름이더라도 장소 ID가 다르면 합치지 않습니다. 같은 장소 안의 연결은 숨기고 A→B와 B→A 등 반복 연결은 점선 하나로 표시합니다. 점선은 실제 이동 경로가 아닌 장소 간 요약이며, 미매핑·실패 구간을 건너뛰어 연결하지 않습니다. 번호 띠에는 재방문 기록이 모두 남고 선택한 기록의 앞뒤 연결만 주황색으로 강조됩니다. 같은 장소의 다른 방문 연결까지 함께 강조하지 않습니다. 말풍선은 연결된 기록 수를 보여주며 번호 선택에 맞춰 해당 기록의 시각·번호를 표시합니다. 지도 지점·말풍선의 상세에서 해당 장소의 다른 기록도 이전·다음으로 확인할 수 있습니다. 원본 경로·관측·묶음 기준·API 조회 정책은 그대로 유지합니다.

**원본만 보기**나 안내 닫기는 장소 조회를 시작하지 않습니다. 동의 후에도 원본 경로가 기본이며 장소·사진 처리가 끝나야 **장소별 보기**로 전환할 수 있습니다. 카메라는 유지합니다. 일반 포인트는 지도 말풍선, 장소가 연결된 포인트는 중앙 상세창을 사용합니다. **위치 기록**과 **기록 분포**는 원본 기준입니다.

구역은 약 2.2km이며 언어별 최대 500개 문서를 조회합니다. 속성 응답의 continuation을 병합하고 최대 16페이지 이후 미완료는 실패로 구분합니다. 500개에 도달한 구역은 페이지 offset을 재요청하지 않고 최대 3단계까지 4분할합니다. 로컬에서 각 포인트의 300m 내 최대 10개 후보를 정렬합니다. 사진은 연결된 고유 대표 장소만 자동 조회합니다.

모든 Wikipedia·Wikidata·Commons 메타데이터 요청 시작 간격은 400ms 이상, 동시 작업 최대 3건, 지역/사진 작업당 10초 제한입니다. 파일당 횟수 제한은 없지만 429·503 또는 API의 속도 제한 오류에서 추가 조회를 중단하며 자동 재시도하지 않습니다. 요청 수는 실제 메타데이터 호출을 세고 지역 검색과 사진 정보를 나눕니다. 이미지 파일 다운로드는 별도입니다. 조회 결과는 파일 세션 메모리에만 유지하며 교체·지우기·새로고침 때 삭제합니다. **추가 조회 중단**은 결과를 보존하고, 삭제는 JSON 옆 **지우기**로 통합합니다.

검증: `npm run check`, Playwright·Edge 환경의 `node tests/app-smoke.cjs`, `node tests/landmark-smoke.cjs`. 브라우저 smoke는 모의 API만 사용하며 Geoapify와 예상하지 않은 외부 요청을 실패 처리합니다. 실제 공개 API 검증은 `node tools/check-wikimedia.mjs --live`로 완전 합성 일본 여행만 사용합니다. 실제 브라우저의 공개 구마모토성 사진 표시는 `node tests/wikimedia-live-smoke.cjs --live`로 확인합니다(지도 모의 응답, Wikimedia 실제 요청). 두 검증은 개인 파일 입력을 받지 않으며 전체 여행 결과 집계는 `node_modules/.cache/wikimedia-live-report.json`에 기록합니다. 실제 이미지 제공과 전체 장소의 정확성은 별개이며 사용자 기록의 방문 여부를 확정하지 않습니다.

이전 [Geoapify 합성 연결 검증](tools/landmark-live-check/README.md)은 과거 도구이며 실제 계정 사용량을 소비합니다. 현재 Wikimedia 시험에는 사용하지 않습니다. 상세 계약과 검증 기록은 [랜드마크 명세](specs/2026-10-07-000-landmark-integration.md)를 따릅니다.

## 4. 사용한 기술 스택

| 기술 | 역할 |
| --- | --- |
| **React · TypeScript** | 화면을 구성하고 데이터 처리 과정의 오류를 줄입니다. |
| **Vite** | 개발 서버를 실행하고 배포용 앱을 만듭니다. |
| **MapLibre GL JS** | 지구본과 위치 점·연결선을 화면에 그립니다. |
| **MapTiler** | 지명·도로·경계가 포함된 배경 지도 자료를 제공합니다. |
| **CSS** | 화면 배치와 디자인을 구성합니다. |
| **Web Worker** | 파일 처리 중에도 화면을 조작할 수 있도록 작업을 분리합니다. |
| **Vitest · Node.js 테스트 · Playwright** | 데이터 처리와 브라우저 동작을 검증합니다. |
| **Vercel** | 웹 앱을 배포합니다. |

현재는 별도의 로그인 서버나 데이터베이스를 사용하지 않습니다.

사진이 **표시 대기**로 남으면 **원형 진행 표시 → 사진이 있는 장소 목록**로 해당 위치와 상세 사진을 확인할 수 있습니다. 전체 목록에서 장소를 직접 고르면 해당 장소로 이동하며 장소 검색을 다시 요청하지 않습니다.

일반 포인트 정보는 지도 말풍선으로 표시합니다. 장소별 보기에서 후보가 매핑된 포인트만 중앙 장소 상세창을 엽니다.
