# Footprint Globe

> 2026-10-06 배포 결정: 사용자 지정 방문은 사진 등록과 함께 추후 확장으로 진행하며 현재 MVP와 Vercel 배포의 완료 조건에서 제외한다. 아래 방문 지정·사진 계약은 확장 참고로 유지한다. 배포는 [Vercel 명세](specs/2026-10-06-006-vercel-deploy.md)를 따른다.

> 최신 UI 결정: MapTiler가 스크롤 없는 전체 화면을 차지한다. 초기에는 한반도 전체를 표시하며 JSON 등록 시 기존 확대 수준을 유지한 채 첫 관측을 화면 중앙으로 이동한다. 상단 왼쪽에 JSON 올리기·지우기·UTC/KST 버튼 전환·포인트 목록·시간별/거리별 분포를 가로 배치한다. 목록과 분포는 중앙 모달 창에서 확인하며 긴 내용은 창 안에서만 스크롤한다. 합성 예제 버튼과 드롭다운 UI는 제거한다. 관측 상세 말풍선과 실선 전용 연결을 유지하고 점선 정책은 제품 소유자가 추후 결정한다. 아래 이전 UI 설명은 이 결정 이전의 이력이다.

Google Timeline의 방문과 이동 기록을 지구본으로 탐색하는 프로젝트입니다. 현재 **로컬 샘플 생성기**와 **rawSignals 실제 파일용 연결 미리보기**를 제공합니다. JSON을 브라우저에서 선택해 전체 화면 MapTiler 지도에서 실선 발자취와 관측 상세를 탐색할 수 있습니다. 방문 지정과 사진 등록은 함께 MVP 이후 확장으로 진행합니다.

화면 개발 브랜치에는 근접 연결 확대, 관측 클릭·목록 선택, UTC·한국 시간 전환이 추가됐습니다. 겹친 점을 클릭하면 후보를 각각 선택할 수 있고, 전체 관측은 20개씩 원래 순서로 탐색합니다. 날짜·좌표는 선택 화면에서만 확인하며 진단·로그로 보내지 않습니다. 시간대 변경은 원본 시각이나 정렬 순서를 바꾸지 않습니다. 사진 추가는 사용자 요청으로 MVP에서 제외하고 추후 확장으로 남겼습니다. 해외 여행을 포함한 MapTiler 상세 지도를 실제 기록 화면에 통합했습니다. 관측 선택과 UTC·한국 시간 전환, 실선 연결을 볼 수 있습니다. MapTiler를 기본으로 사용하며 지도 선택 메뉴는 제공하지 않습니다.

## 앱 공통 개발 환경

앱은 React·TypeScript·Vite·react-globe.gl·Three.js와 일반 CSS를 사용합니다. 별도 서버 DB나 상태 관리 프레임워크 없이 공통 타입으로 데이터와 화면을 분리합니다. 배경은 MapTiler Base v4를 사용합니다. 이전 [개략 육지 윤곽](docs/basemap.md) 자료는 이력으로 남습니다. 상세 지도는 MapLibre GL JS로 렌더링합니다.

Node.js 22.12 이상과 npm이 필요합니다. Node 24 환경에서 검증했습니다. Node 18에서는 기존 샘플 단위 테스트만 실행할 수 있습니다. Vite의 요구사항은 [공식 안내](https://vite.dev/guide/)에서 확인할 수 있습니다.

```powershell
node --version
npm ci
npm run dev
```

표시된 로컬 주소를 브라우저에서 여세요. 실제 기록 확인에는 아래 배포용 미리보기를 권장합니다. 기존 샘플 도구는 아래 방법대로 별도 HTML을 열어 사용합니다.

```powershell
npm run typecheck
npm test
npm run build
npm run preview
```

`npm run check`는 타입 검사·샘플 테스트·앱 테스트·빌드를 한 번에 실행합니다. 별도 lint 명령은 아직 없습니다. `npm run build`는 배포용 `dist/`를 만들며 개발 서버는 외부에 공개하지 않고 `127.0.0.1`에만 바인딩합니다. 다른 작업 공간에서는 `npm run dev -- --port 5174`처럼 별도 포트를 지정하세요.

공통 계약은 `src/domain/timeline.ts`, 완전 합성 데이터는 `src/fixtures/timeline.ts`와 `src/fixtures/preview.ts`에 있습니다. 실제 파서와 합성 대체 함수 모두 `TimelineParser`와 `ParseResult`를 따릅니다. 성공은 데이터와 집계, 실패는 고정 코드와 선택적 집계를 반환합니다. 집계가 없으면 0건이 아니라 검사 미완료입니다.

데이터 담당은 `src/parser/`의 `parseTimeline(text, datasetId)` 진입점과 검증·정규화를, 화면 담당은 `src/app/`·`src/features/`의 파일 선택·worker·화면·사진 자원을 맡습니다. 파일 읽기는 화면 측 `importFile.ts`가 worker 안에서 수행합니다. 제품 UI에 합성 예제 버튼은 없으며 합성 데이터는 자동 검증에서만 사용합니다. 공통 타입·fixture·패키지·잠금 파일 변경은 한 담당자가 조율합니다. 세부 담당 범위와 통합 순서는 공통 기반 명세를 따릅니다.

공통 계약 정리와 분리 준비 검증은 [PR #8](https://github.com/diavillager/footprint-globe/pull/8)에 정리했습니다. 이를 포함한 `main`의 동일한 기준 커밋에서 데이터·화면 작업을 분리합니다. 근접 관측의 점선은 합성 약 1m 간격에서 개선을 확인했으며 실제 기록의 유용성은 사용자 로컬 확인이 남았습니다. 상세 지도는 통합했으며 방문 지정은 아직 구현하지 않았습니다. 사진은 MVP 이후 확장입니다. 표시 시간대는 UTC·한국 시간 전환으로 확정했고 최종 연결 표시 정책·추가 브라우저 지원은 미확정입니다.

방문은 사용자가 관측점을 선택해 직접 지정하기로 결정했습니다. 방문 지정 UI는 미구현이며 사진은 MVP 이후 확장입니다. 이번 연결 미리보기는 전체 유효 관측을 잇는 시각 실험이며 실제 경로나 방문을 자동 생성하지 않습니다. 제품 전체의 지원 형식·한도·브라우저 범위를 확정한 것은 아닙니다.

추가 브라우저 검증은 Playwright와 Edge가 있는 환경에서 `node tests/app-smoke.cjs`로 실행합니다(`npm run build` 선행). 완전 합성 입력으로 개발·배포 지구본, 파일 선택, 중앙 창, UTC/KST 전환, 10,123개 관측, 잘못된 입력 복구와 지우기를 확인하며 실제 파일은 읽지 않습니다.

## MapTiler 공개 지역 검증

실제 기록 화면과 별개인 [지도 검증 도구](tools/maptiler-check/index.html)를 추가했습니다. 서울·도쿄·뉴욕·파리·런던의 행정 경계 자료와 한국어 지명, 지구본, 1m 간격 합성점·동일 좌표의 별도 선택을 Edge에서 확인했습니다. 나라별 도시 경계의 완전성을 보장하지 않습니다. 이후 사용자가 실제 기록용 지도 통합을 승인했으며 현재 앱에서 사용할 수 있습니다. 이 도구는 초기 비교용으로 남겨 둡니다.

저장소 루트의 Git 제외 파일 `.env.local`에 `MAPTILER_API_KEY=발급받은키`를 넣고 Node 22.12 이상에서 실행합니다. MapTiler 키의 허용 주소는 `127.0.0.1`로 설정합니다. 키 값은 채팅이나 Git에 공유하지 않습니다.

```powershell
node tools/maptiler-check/server.cjs
```

`http://127.0.0.1:4174`를 열고 **지도 검증 시작**을 누릅니다. 시작 전에는 외부 요청이 없습니다. 시작 후에는 MapTiler의 SDK·지도 자료를 직접 받으므로 조회 지역이 서비스에 전달되고 사용량을 소비합니다. 파일 입력·실제 Timeline 연결은 없으며 SDK telemetry·영구 캐시는 끕니다. 지도에 쓰는 브라우저용 키는 개발자 도구에서 확인 가능한 값입니다. 이 서버는 로컬 시험 전용이며 배포하지 않습니다.

**행정 경계 강조**로 색을 바꿔 볼 수 있고, **지도 종료**로 지도 자원을 해제합니다. **지도 종료**는 로컬 서버 프로세스를 종료하지 않으므로 서버 종료는 터미널의 Ctrl+C를 사용합니다. 키가 없거나 지도 요청이 실패하면 고정 오류 코드가 표시되며, 설정을 고친 후 다시 시작합니다. 지도 오류·403·429 상황의 완전한 복구와 실제 요청 로그 보존 정책은 후속 검증 사항입니다.

Playwright와 Edge가 있는 환경에서는 `node tests/maptiler-check-smoke.cjs`로 같은 공개 지역의 실시간 검증을 실행할 수 있습니다. 무료 사용량을 소비하므로 기본 `npm run check`에는 넣지 않았습니다. 서버의 비공개 파일 접근 차단, 시작 전 외부 요청 없음, 지도와 경계, 겹친 점 선택, 자원 정리, 키 누락을 검증합니다. 화면 캡처는 OS 임시 폴더의 `maptiler-check-*.png`에 남으며 실제 기록과 키를 표시하지 않습니다.

## 실제 기록으로 연결 미리보기

Windows에서는 저장소 루트에서 다음 명령으로 설치·빌드·실행할 수 있습니다. 이 프로세스에서만 스크립트 실행을 허용하며 시스템 실행 정책은 바꾸지 않습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-preview.ps1
```

스크립트는 Node 22.12 이상을 찾고, 현재 PC처럼 Codex의 Node 24가 설치되어 있으면 그것도 사용할 수 있습니다. 기본 Node 설치나 시스템 PATH를 변경하지 않습니다. npm 위치를 찾지 못하는 환경에서는 Node 22.12 이상을 준비한 뒤 `npm ci`, `npm run build`, `npm run preview`를 순서대로 실행하세요.

1. Chrome/Edge에서 `http://127.0.0.1:4173`을 엽니다. 서버는 실행한 터미널을 유지해야 하며 Ctrl+C로 종료합니다.
2. **JSON 올리기**에서 원본을 직접 선택합니다. 첫 관측이 현재 확대 수준을 유지한 채 화면 중앙으로 이동합니다.
3. 연결은 실선으로 표시합니다. 포인트를 누르면 해당 위치를 가리키는 말풍선에서 시각·좌표를 확인할 수 있습니다. 시간대는 UTC/KST 버튼으로 바꿉니다.
4. 드래그·확대·축소로 확인하고 시간차·지점 간 거리 분포를 살펴보세요. 거리는 실제 이동 거리나 도로 길이가 아닌 두 위치의 지표면 최단 거리입니다.
5. **지우기** 또는 탭 닫기로 기록 참조를 해제합니다. 원본이나 실제 경로 캡처를 공유할 필요는 없습니다.

미리보기 범위와 한계:

- 최상위 rawSignals의 position.LatLng/latLng와 timestamp를 지원합니다. 미리보기 한도는 64 MiB·원시 신호 100,000개이며 다른 Timeline 형식은 아직 지원하지 않습니다.
- 유효 좌표·시각은 모두 사용하고 시간순으로 연결합니다. 원시 기록의 Wi-Fi/활동 신호와 추가 속성은 복사하지 않습니다. 잘못된 위치는 건수로 알리고 제외하며 그 앞뒤의 유효 위치가 연결됩니다. 샘플 도구의 엄격한 제외 정책과는 별도입니다.
- 연결선은 실제로 지나간 도로나 비행 경로의 복원이 아닙니다. 현재 실선만 표시하며 점선 정책은 제품 소유자가 추후 결정합니다. 같은 위치의 점·선은 겹치고 지구 뒤편은 회전해야 보입니다.
- 관측점을 축소하지 않습니다. 지나치게 복잡해 표시 정점 2,000,000개를 넘으면 지도 대신 경고를 표시하고 집계만 제공합니다.
- 원본 파일명·개별 날짜·좌표는 진단 표나 로그에 출력하지 않지만 지구본 자체에는 위치가 드러납니다. 로컬 저장소·서버 저장·자동 전송은 없습니다. 파일 처리 worker는 교체·지우기·취소 시 종료합니다.
- 설치 시 npm 패키지는 다운로드합니다. JSON은 브라우저 내부에서 처리합니다. 상세 지도의 CSP는 api.maptiler.com 지도 리소스 요청을 허용합니다. 지도 요청으로 IP·열람 지역·확대 수준이 전달될 수 있으며 JSON 본문·관측 시각·파일명은 보내지 않습니다. 지도 선택 및 개략 지구본 전환은 제공하지 않습니다. 개발 모드는 로컬 자동 새로고침 연결을 사용합니다.
- 현재 UI는 Edge에서 합성 입력으로 검증했습니다. 실제 원본 호환성은 사용자가 직접 확인하며, WebGL을 사용할 수 없는 환경에서는 고정 오류와 집계만 표시합니다.
- Three.js·지구본·지도 데이터가 포함되어 현재 빌드에 큰 번들 경고가 있습니다. 첫 로드 비용은 남아 있으며 실제 데이터가 포함된 경고는 아닙니다.

## 로컬 샘플 생성기 실행

3. 처리 결과에서 형식, 정상 처리·제외 건수와 경고를 확인하세요. 생성에 성공했을 때만 **가상 샘플 JSON 저장**을 누를 수 있습니다.
4. 별도 파일 `timeline.synthetic.sample.json`을 저장하세요. 원본을 저장 대상으로 선택하지 마세요. 브라우저의 ‘다른 이름으로 저장’을 사용해 저장소의 `private/` 또는 저장소 밖에 보관하세요.
5. 아래 공유 전 확인을 마친 **생성 샘플만** 필요할 때 직접 공유하세요. 원본 파일은 공유하지 마세요.

도구는 원본 파일에 대한 읽기 권한만 사용하며 원본을 수정하지 않습니다. 다운로드는 원본과 무관한 고정 이름을 사용합니다. 원본 파일명, 내용, 오류의 원문은 화면이나 콘솔에 표시하지 않습니다. 선택 후 파일 입력의 이름도 지웁니다. 파일 내용은 브라우저 메모리에서만 처리하며 탭을 닫으면 도구의 참조가 사라집니다. 브라우저 확장 기능 및 OS 수준의 메모리 보안까지 제어하는 도구는 아닙니다.

외부 스크립트·폰트·분석 도구·서버가 없습니다. HTML의 Content Security Policy는 네트워크 연결을 차단하며, 도구에는 네트워크 요청 및 브라우저 영구 저장 기능이 없습니다. 오프라인 상태에서도 사용할 수 있습니다.

## 지원 범위와 중단 정책

다음 네 가지 형태에 대해 **코드에 명시된 필드만** 처리합니다. 모든 버전의 Google 내보내기를 지원한다는 의미는 아닙니다. 원시 기록 지원의 범위와 승인된 결정은 [rawSignals 명세](specs/2026-10-06-000-raw-signals-sample.md)에 정리했습니다.

| 최상위 형식 | 지원하는 대표 내용 |
| --- | --- |
| `{ "semanticSegments": [...] }` | `visit`, `activity`, `timelinePath` |
| `[...]` | 위와 같은 기기 내보내기 기록, `geo:` 좌표와 상대 분 단위 경로 시각 |
| `{ "timelineObjects": [...] }` | `placeVisit`, `activitySegment`, `waypointPath`, `simplifiedRawPath` |
| `{ "rawSignals": [...] }` | `position`의 좌표·시각 및 허용 보조 필드. 방문·경로를 새로 만들지 않음 |

- 최상위 객체에 `semanticSegments` 또는 `timelineObjects`가 정확히 하나 있고 배열이면 그 기록만 처리합니다. 두 필드가 모두 없을 때 `rawSignals` 배열을 처리합니다. 선택한 기록 외의 최상위 필드는 통째로 제외하고 건수만 알립니다. 사용자 프로필은 항상 제외하고, 기존 방문·이동 형식이 함께 있으면 `rawSignals`도 제외합니다. 기존 형식 실패를 원시 모드로 자동 우회하지 않습니다.
- 두 기록 필드가 함께 있거나, 배열 자료형이 아니거나, 지원하는 최상위 기록 필드가 없으면 중단합니다. 임의의 중첩 객체를 탐색해 기록을 추측하지 않습니다. `locations` 및 원시 GPS에서 방문지 추론은 지원하지 않습니다.
- 기록 내부에 모르는 필드, 예상과 다른 자료형, 누락 좌표, 잘못된 시각·좌표가 있으면 **해당 기록 전체를 제외**합니다. 모르는 필드명이나 값은 결과 메시지에도 반영하지 않습니다.
- 축소할 경로 배열의 지점도 먼저 모두 검증합니다. 모르는 지점 속성을 그대로 복사하지 않습니다.
- 기존 방문·이동 모드에서는 안전한 방문과 이동 기록이 모두 있어야 생성됩니다. 상세 경로가 없고 이동 시작·종료점만 있으면 그 사실을 경고합니다. **원시 기록 모드는 안전한 위치 관측값 하나 이상이면 생성**하며, 방문·확정 이동 경로가 없음을 명시합니다.
- 입력은 64 MiB 및 100,000개 기록 이하입니다. 샘플은 최대 9개 기록, 중첩 배열당 24개 항목, UTF-8 64 KiB입니다. 경로 축소 시 첫 지점과 마지막 지점을 유지합니다. 모든 기록을 검증하지만, 변환 중에는 출력 후보만 유지하여 메모리 사용을 줄입니다. 원본 JSON 전체를 읽고 파싱하는 메모리는 여전히 필요하며, 큰 파일은 잠시 화면 응답이 늦어질 수 있습니다.
- 방문·이동·상세 경로가 있으면 각각 대표 기록을 우선 포함하고, 남은 자리는 입력 순서로 채웁니다. 출력 기록의 순서는 원본과 같습니다. 제외 및 미선택 때문에 전체 여행이 이어지지 않을 수 있습니다.
- 거부된 파일을 호환시키려고 알 수 없는 값을 통과시키지 마세요. 형식과 고정된 오류 분류·건수만 알려 주면 합성 fixture와 허용 목록을 확장하는 방향으로 검토할 수 있습니다. 원본이나 원본 필드값을 붙여 넣지 마세요.

### rawSignals 모드

`rawSignals[].position` 안의 `LatLng` 또는 `latLng` 중 정확히 하나와 ISO 8601 `timestamp`를 요구합니다. 좌표 키의 대소문자와 기존 중첩 구조는 유지합니다. 숫자형 `accuracyMeters`, `altitudeMeters`, `speedMetersPerSecond`는 가상 수치 0으로, 문자열 `source`는 `UNKNOWN`으로 바꿉니다. 그 밖의 필드가 있으면 해당 기록을 제외합니다.

`wifiScan`, `activityRecord` 같은 다른 신호는 통째로 제외하므로 MAC·SSID·기기 정보가 샘플에 들어가지 않습니다. 위치와 다른 신호가 한 기록에 섞여 있어도 기록 전체를 제외합니다. 출력은 최대 9개 위치 관측값이며, 원본 순서·시간차·반복 좌표 관계를 유지합니다. 원시 위치를 연결해 경로를 만들거나 방문 장소·체류를 추론하지 않습니다.

`원시 위치 관측값: N`과 `방문 0, 이동 0, 상세 경로 0`은 이 모드에서 정상적인 결과입니다. 샘플 생성 성공이 방문·사진 기능을 바로 검증할 수 있다는 뜻은 아닙니다. 방문 기록 없는 데이터의 앱 표현은 이후 별도 검토 사항입니다.

## 파일 선택 오류 해결

- `EXCLUDED_ROOT_FIELD`: 지원 기록 배열 이외의 최상위 필드를 제외했다는 안내입니다. 생성 성공 여부는 나머지 기록 검증 결과로 결정합니다.
- `UNSUPPORTED_RAW_SIGNAL`: 위치 관측값이 아닌 원시 신호를 제외했다는 안내입니다.
- `NO_SAFE_RAW_POSITION`: 지원하는 위치 관측값이 없거나 모두 제외됐습니다. 구조 진단과 제외 사유만 공유하세요. 원본 내용은 필요하지 않습니다.
- `UNSUPPORTED_ROOT` / `ROOT_FIELD_TYPE` / `AMBIGUOUS_ROOT`: 알려진 배열을 찾을 수 없거나 자료형·선택이 불명확합니다. 기본 결과에 최상위 자료형과 두 기록 필드의 존재·배열 여부를 표시하고, 아래의 제한된 구조 진단을 덧붙입니다. 실제 필드명이나 원본 내용을 직접 복사하지 말고 도구가 표시한 진단만 알려 주세요.

위 최상위 오류에는 **구조 진단 v1**이 추가됩니다. 원본을 직접 수정하거나 구조를 이해할 필요 없이, 파일을 다시 선택하고 이 진단 부분만 공유할 수 있습니다. 알려진 필드명의 고정 목록에 대해서만 최상위/중첩 여부, JSON 자료형, 집계 건수를 표시합니다. 예를 들어 중첩된 기록 배열, 원시 좌표쌍, 편집 기록 필드를 구별하는 단서가 됩니다. 임의의 필드명·중첩 경로·문자열·좌표·날짜·식별자·배열 원소는 출력하지 않습니다. 문자열 안에 들어 있는 JSON도 열거나 파싱하지 않습니다.

진단은 최대 12,000개 노드와 깊이 10까지 검사하고, 한도에 도달하면 ‘일부만 검사: 예’를 표시합니다. 이때 없는 것으로 보이는 필드가 다른 부분에는 있을 수 있으며 건수는 전체 건수가 아닙니다. 필드 존재만으로 실제 형식을 확정하거나 새 형식을 지원하는 것은 아닙니다. 기존 치환 및 제외 정책은 그대로 유지되며, 미지원 구조는 진단 이후에도 샘플 생성을 중단합니다.

- `FILE_TOO_LARGE`: 표시된 파일 크기가 64 MiB를 초과했습니다. 이 경우 파일 내용은 읽지 않습니다. 원본을 직접 편집하거나 공유하지 말고 오류 코드와 크기만 알려 주세요.
- `FILE_READ_FAILED`: 크기는 한도 이내지만 브라우저에서 읽을 수 없습니다. 클라우드 전용 파일이면 로컬 다운로드를 완료하고 다시 선택하세요.
- `TOOL_NOT_LOADED`: 세 도구 파일이 같은 폴더에 있는지 확인하고 Chrome 또는 Edge에서 `index.html`을 다시 여세요.
- `PROCESSING_FAILED`: 읽기는 완료했지만 변환 중 예기치 않은 문제가 발생했습니다. 오류 코드만 공유하세요.

예전 버전의 ‘파일을 읽을 수 없거나 입력 크기 제한을 초과했습니다’는 여러 원인을 구분하지 못했습니다. 예를 들어 24,539 KB 파일은 이전 20 MiB 한도를 넘지만 현재 64 MiB 한도 안에 들어갑니다. 도구를 다시 열어 파일을 선택하세요. 크기 제한 통과 후에도 실제 구조의 지원 여부는 별도로 검증됩니다.

## 원본에 경로가 있는지 확인하고 이전 샘플과 비교하기

파일을 다시 선택하면 생성 성공 여부와 관계없이, JSON 읽기에 성공한 경우 **원본·샘플 비교 진단 v1**이 처리 결과 아래에 표시됩니다. 원본 내용은 브라우저 안에서만 검사합니다. 이 기능은 샘플의 치환·제외·선택 정책을 변경하지 않습니다.

- **선택한 기록 영역 / 샘플 대상 밖 영역의 구조 후보**: 알려진 방문·이동·상세 경로·위치 관측 구조와 Wi-Fi·활동 감지 신호를 집계합니다. 제외된 최상위 영역 안의 중첩 구조도 검사하지만, 임의 필드명이나 값은 출력하거나 샘플에 복사하지 않습니다.
- **기록별 처리 단계**: 변환 대상 배열에서 방문·이동·경로·위치 필드가 있는 기록 수, 검증 통과, 안전상 제외, 크기 제한으로 미선택, 최종 샘플 건수를 구분합니다. 제외 이유는 고정 코드로 표시합니다. 한 기록이 여러 종류에 해당할 수 있습니다.
- **후보와 검증은 다릅니다**: 구조 후보에는 빈 경로 배열 등도 포함될 수 있습니다. 구조 후보는 중첩을 포함한 집계이고, 처리 단계는 변환 대상 배열의 기록 단위이므로 두 건수가 반드시 일치하지 않습니다. 활동 감지 신호를 확정 이동 경로로 해석하지 않습니다.
- **검사 한도**: 최대 2,000,000개 노드, 각 최상위 값에서 깊이 32, 최상위 필드 10,000개까지 검사합니다. 여러 최상위 영역을 번갈아 검사해 큰 기록 배열 때문에 다른 영역을 전혀 검사하지 못하는 일을 줄입니다. 한도에 걸리면 ‘일부만 검사: 예’로 표시하며, 집계는 검사 범위 기준입니다. 문자열 안의 JSON은 해석하지 않습니다.
- **판단 한계**: `OUTSIDE_SAMPLE_CANDIDATE`는 샘플 대상 밖에 알려진 구조 후보가 있다는 뜻입니다. `NO_KNOWN_PATH_CANDIDATE`는 검사 범위에서 알려진 경로 구조를 찾지 못했다는 뜻이며 원본에 경로가 없음을 증명하지 않습니다. 미지원 구조는 계속 판단 보류로 남깁니다. 생성이 중단되면 최종 샘플은 0건입니다.

다시 생성할 때는 다음 순서로 진행하세요.

1. 기존 샘플을 보관하고 도구 페이지를 새로고침하거나 다시 여세요.
2. **원본 JSON**을 로컬에서 직접 선택하세요. 이전 샘플을 입력하면 원본에서 제외된 영역은 검사할 수 없습니다.
3. 새 샘플은 이전 파일을 덮어쓰지 않도록 다른 이름으로 저장하세요. 두 파일 모두 `private/` 또는 저장소 밖에 보관하세요.
4. 아래 공유 전 확인 목록을 적용한 뒤, 이전·새 샘플을 구분해서 제공하고 **원본·샘플 비교 진단 v1 전체**를 함께 복사해 주세요. 원본은 제공하지 마세요.

같은 원본으로 생성한 두 샘플은 동일할 수 있습니다. 이번 변경은 원본의 제외 영역을 설명하는 진단 보강이며, 모르는 기록을 새로 샘플에 포함하는 변경이 아닙니다. 샘플 두 개만으로는 원본에서 제외된 내용을 알 수 없어 진단 결과가 함께 필요합니다.

## 무엇이 보존되고 바뀌는가

| 항목 | 처리 |
| --- | --- |
| 필드명·중첩·JSON 자료형 | 채택한 기록에서 유지. 배열 길이는 명시적으로 축소될 수 있고, 지원 기록 배열 외의 최상위 필드는 제외됨 |
| 좌표 | 원본 지역·모양과 관계없는 유효한 가상 격자에 매핑 |
| 반복 좌표 | 같은 위경도 쌍은 방문점·이동 시작/끝·경로 지점에서 같은 가상 좌표 사용 |
| 좌표 표현 | 숫자 E7, `geo:lat,lng`, `lat°, lng°` 표현 및 문자열 소수 자릿수 유지 |
| 시각 | 선택된 기록에 공통 초 단위 이동 적용. 가장 이른 시각을 2040년 기준으로 옮김 |
| 시간 관계 | 절대 시각의 순서·차이·체류 기간·겹침 유지. 상대 `durationMinutesOffset` 유지 |
| 시간 표현 | ISO 8601의 소수 정밀도·`Z` 또는 오프셋 표기, 숫자/문자열 epoch 밀리초 구분 유지 |
| 시간대 | ISO 오프셋을 UTC로 변경하고 별도 오프셋 필드를 0으로 변경 |
| 이름·주소·placeId | `synthetic-text-...`, `synthetic-id-...`로 치환. 동일 문자열의 반복 관계 유지 |
| 보조 속성 | 활동 유형 등 문자열은 중립 값, 거리·정확도·확신도 등은 가상 수치로 치환 |

실제 이동의 모양·거리·방향은 보존하지 않습니다. 서로 동일한 원본 좌표만 같은 지점으로 취급하며 ‘근처’ 좌표를 같은 장소라고 추론하지 않습니다. 원래 좌표가 근사치로 다르면 가상 좌표도 다릅니다. 지점 간 연결과 형식 호환성 검증을 위한 샘플이며, 실제 이동 속도·거리 분석에는 사용하지 마세요.

JSON 공백·키 순서 및 숫자 리터럴의 불필요한 후행 0까지 보존하지는 않습니다. E7 숫자형 등 데이터 표현 방식과 JSON 자료형을 보존합니다. 지원하지 않는 좌표·시간 문법은 추측해서 처리하지 않습니다.

**시간 간격과 체류 기간, 반복 방문 관계, 필드 구조는 의도적으로 남습니다.** 이 정보만으로도 민감할 수 있으므로 완전한 익명성 보장을 의미하지 않습니다. 이를 공유하고 싶지 않으면 원본 기반 샘플 대신 아래 완전 합성 예제를 사용하세요.

## 공유 전 직접 확인

- 원본이 아니라 `timeline.synthetic.sample.json`을 열었는지 확인하세요.
- 장소명·주소·placeId가 `synthetic-...`이고, 계정·이메일·기기 ID·URL·메모 등 원본 식별 정보가 없는지 확인하세요.
- 방문뿐 아니라 `timelinePath`, `waypointPath`, `simplifiedRawPath`, 활동 시작·종료 좌표도 가상 값인지 확인하세요. 원시 모드라면 `rawSignals[].position`의 `LatLng`/`latLng`와 `timestamp`를 확인하세요.
- 원시 모드 샘플에 Wi-Fi·활동 감지 신호나 사용자 프로필이 포함되지 않았는지 확인하세요.
- 날짜가 가상 기준으로 이동했는지, 시간대가 UTC인지 확인하세요.
- 유지된 시간 간격·체류 기간·반복 방문 패턴을 공유해도 괜찮은지 확인하세요.
- 제외·축소 경고를 확인하세요. 생성 성공은 모든 원본 기록의 호환성을 뜻하지 않습니다.
- 샘플을 Git에 올리지 마세요. 공개 예제는 완전 합성 fixture만 사용합니다.

## 합성 예제와 테스트

테스트는 Node.js 18 이상에서 의존성 설치 없이 실행합니다. 테스트 코드가 읽는 파일은 저장소의 도구 소스뿐이며 실제 위치 파일을 탐색하거나 열지 않습니다.

```powershell
node --test tests/timeline-sample.test.cjs tests/structure-diagnostics.test.cjs tests/raw-signals.test.cjs tests/source-audit.test.cjs
```

완전 합성 예제를 파일 선택 UI에서 사용하려면:

```powershell
node tests/write-synthetic-example.cjs
```

`private/fully-synthetic.modern.json`, `private/fully-synthetic.deviceArray.json`, `private/fully-synthetic.legacy.json`, `private/fully-synthetic.rawSignals.json`이 생성됩니다. 생성기는 입력 파일을 받지 않으며 기존 파일을 덮어쓰지 않습니다. 공개 관리되는 예제의 원천은 직접 작성한 `tests/synthetic-fixtures.cjs`와 `tests/raw-signal-fixtures.cjs`입니다. 생성 JSON 자체는 Git에서 제외합니다.

추가 브라우저 검증은 Node.js 20 이상, Playwright 및 Edge가 있는 개발 환경에서 `node tests/browser-smoke.cjs`로 실행할 수 있습니다. Chrome을 사용하려면 `TIMELINE_TEST_BROWSER=chrome`을 설정하세요. Playwright는 일반 사용이나 위 단위 테스트에 필요하지 않습니다. 브라우저 검증도 합성 fixture를 메모리로 주입하며 실제 파일은 읽지 않습니다. 새 headless 브라우저 세션을 사용합니다.

## Git 보호와 후속 개발 흐름

`.gitignore`는 모든 `*.json`, 위치 내보내기 포맷, 사진, `private/`, `local-data/`를 기본 제외합니다. 현재 루트의 `package.json`, `package-lock.json`, `tsconfig.json`, `vercel.json`만 예외로 허용합니다. 추가 설정도 **정확한 개발 파일 경로만** 예외로 추가하고 예제 JSON 전체 디렉터리를 통째로 허용하지 마세요. `git add -f`는 이 보호를 우회하므로 개인 파일에 사용하지 마세요. 이미 추적 중인 파일은 `.gitignore`로 보호되지 않습니다.

후속 흐름은 다음과 같습니다.

1. 사용자가 이 도구를 실행해 샘플을 만들고 공유 전 내용을 직접 확인합니다.
2. 사용자가 공유를 결정한 가상 샘플로 앱 파서를 개발합니다. 원본 기반 샘플은 저장소에 커밋하지 않습니다.
3. 회귀 테스트용으로는 필요한 구조를 다시 작성한 완전 합성 fixture를 사용합니다.
4. 실제 원본 JSON의 호환성은 사용자가 로컬 앱의 파일 선택 기능으로 직접 검증합니다. 개발 도구·채팅·원격 저장소로 원본을 전달하지 않습니다.

현재 검증은 합성 입력 기준입니다. 실제 원본 파일의 호환성은 아직 검증하지 않았습니다.

## 상세 지도 설정과 Vercel 배포

- 운영 주소는 [footprint-globe.vercel.app](https://footprint-globe.vercel.app/)로 연결했고 HTTPS 200을 확인했습니다. MapTiler 허용 origin에도 추가했습니다. 사용자 승인으로 Production 재배포를 완료했고 실제 지도 로딩을 확인했습니다. 지도 키와 MapTiler 허용 주소는 운영 전용으로 정리했습니다. 사용자는 Preview에서 문제가 없었다고 확인했습니다.
- 로컬 `.env.local`에 `VITE_MAPTILER_API_KEY=브라우저용지도키`를 설정합니다. 기존 시험 화면의 `MAPTILER_API_KEY`도 대체값으로 읽습니다. 키를 수정하면 개발 서버 재시작 또는 재빌드가 필요합니다. 키가 없으면 설정 안내를 표시하고 JSON 등록·목록 확인은 유지합니다.
- Vercel은 Vite 프로젝트로 배포합니다. Node.js 24, 설치 `npm ci`, 빌드 `npm run build`, 출력 `dist`를 사용합니다. 로컬 검증 서버와 `/config`는 배포에 필요하지 않습니다. [Preview](https://footprint-globe-git-codex-vercel-deploy-diavillager.vercel.app/) 배포와 실제 지도 로딩을 확인했으며 Vercel 로그인이 필요합니다. 이후 사용자 요청으로 Production 재배포를 완료하고 지도 키를 Production 전용으로 변경했습니다. localhost·Preview의 MapTiler 허용도 제거했으므로 현재 Preview에서는 지도를 사용할 수 없습니다. PR 병합은 별도 승인 전이며, 원격 합성 파일 등록은 브라우저 권한 제한과 사용자의 검증 범위 결정으로 미수행입니다. 첫 배포의 환경 분류 예외와 실제 검증 범위는 [배포 명세](specs/2026-10-06-006-vercel-deploy.md)에 기록합니다.
- 브라우저 지도 키는 빌드에 포함되며 비밀값이 아닙니다. MapTiler에서 실제 운영 도메인·검증에 사용할 Preview 도메인·localhost origin을 제한해야 합니다. Supabase secret/service_role 키를 VITE 환경변수에 넣으면 안 됩니다.
- MapTiler 지도는 보안 수정 버전 MapLibre GL JS 6.4.1로 표시합니다. SDK 4.1/4.2의 MapLibre 5.24 의존성에 알려진 [attribution HTML 취약점](https://github.com/maplibre/maplibre-gl-js/security/advisories/GHSA-jrc7-96c5-q579)이 있어 그대로 채택하지 않았습니다.
- 이 구성은 PoC의 MapTiler SDK 세션 집계와 달리 **요청 수 기준**입니다. 공개 배포 전 MapTiler 대시보드에서 실제 사용량과 요금제 한도를 확인해야 합니다. 유료 예산은 확정하지 않았습니다. [공식 집계 설명](https://docs.maptiler.com/guides/account/sessions-vs-requests/)
- MapTiler 로고와 자료의 저작권 표기를 유지합니다. 한국어 이름을 우선하며 없는 이름은 지도 자료의 기본 이름을 사용합니다. 경계 자료와 분쟁 경계 필터는 공급자 스타일을 유지합니다.
- 향후 Vercel + Supabase 구성을 고려해 정규화 데이터와 화면을 분리합니다. 현재는 Supabase 의존성·계정·DB·Storage·서버 저장을 추가하지 않았습니다. 저장 범위·보존·권한 정책은 확장 개발 때 결정합니다.
- `node tests/map-integration-smoke.cjs`는 Edge/Playwright로 실제 MapTiler 요청을 사용하는 합성 통합 검증입니다. 개발 화면과 빌드 모두 확인하며 사용량을 소비하므로 기본 check에는 포함하지 않습니다. `tests/app-smoke.cjs`는 지도 응답을 합성 자료로 대체하여 외부 통신 없이 UI·파일 처리·worker 수명을 검증합니다.
