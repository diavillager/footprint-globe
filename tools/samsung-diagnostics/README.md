# 삼성 헬스 로컬 구조 진단

개인 데이터 다운로드에 위치·시각 후보가 있는지 확인하는 오프라인 도구입니다. 앱 파서·샘플 생성기와 독립적이며 삼성 내보내기의 모든 버전을 지원하거나 이동 경로를 복원하지 않습니다.

## 실행

1. 이 폴더의 `index.html`을 최신 Chrome 또는 Edge로 엽니다. 서버·설치·로그인이 필요하지 않습니다. `inspector.js`와 `ui.js`는 같은 폴더에 유지합니다.
2. **삼성 헬스 폴더 선택**을 누르고 개인 데이터 다운로드로 받은 최상위 폴더를 선택합니다. ZIP이면 먼저 로컬에서 압축을 풉니다. 원본은 저장소 밖에 보관하세요.
3. 브라우저의 폴더 제공 확인창에는 “업로드”라는 표현이나 파일명이 나올 수 있습니다. 파일을 이 로컬 페이지에서 읽도록 허용하는 절차이며 이 도구는 네트워크로 전송하지 않습니다.
4. 결과만 확인하거나 복사해서 공유합니다. CSV·JSON 내용, 전체 파일 목록, 사진은 공유하지 않습니다.
5. **취소·결과 지우기** 또는 탭 종료로 처리 스레드와 원본 참조를 해제합니다. 원본을 수정하거나 샘플을 저장하지 않습니다.

## 결과 해석

v4는 헤더 뒤의 초과 열이 모두 빈 문자열인 경우에만 해당 열을 무시하고 검사를 계속합니다. 기존 창을 새로고침하고 결과 제목의 `v4`를 확인하세요. 원본 파일은 수정하지 않습니다.

- `EMPTY_TAIL_IGNORED`: 헤더에 대응하는 모든 셀을 유지하고 그 뒤의 초과 열만 검사합니다. 초과 열이 전부 빈 문자열(인용된 `""` 포함)이면 무시하며 파일·행·셀 처리 건수를 표시합니다. 공백이나 값이 하나라도 있으면 제외합니다. 중간 빈 셀을 삭제하거나 부족한 열을 채우지 않으며 원래 행에 열 개수 한도를 먼저 적용합니다. 이후 오류로 제외된 파일의 처리 건수도 포함하지만 그 파일의 값 후보는 집계하지 않습니다.
- 남은 열수 불일치: 완전히 빈 행, 공백·빈 셀만 있는 행, 부족한 열의 헤더가 모두 빈 이름인 행, 그 외 열 부족·초과를 구분합니다. 빈 행/빈 셀 분류가 우선이며 각 파일은 한 오류 범주에만 집계됩니다.
- 따옴표 오류: 파일 끝까지 닫히지 않은 따옴표, 비인용 필드 안의 따옴표, 닫는 따옴표 뒤 공백 또는 다른 문자를 구분합니다. 정상적인 따옴표 안 쉼표·개행·겹따옴표는 오류로 세지 않습니다.
- 상세 건수는 **파일마다 처음 중단된 지점** 기준입니다. 뒤쪽에 다른 오류가 있는지 알 수 없고, 정확한 행 번호·열 개수·내용·파일별 목록은 출력하지 않습니다. 초과 빈 열이 있다는 사실만으로 마지막 쉼표가 원인이라고 확정하지 않습니다.

- `CANDIDATES_FOUND`: 알려진 좌표쌍과 시각 표현이 같은 객체 또는 CSV 행에 있습니다. 정확한 운동 경로·기간·여행 자료·앱 호환성을 뜻하지 않습니다.
- `NO_KNOWN_PAIR`: 검사 범위에서 위 조합을 찾지 못했습니다. 원본이나 다른 기기·계정에 GPS가 없다는 증명이 아닙니다.
- JSON은 중첩 객체를 순회합니다. CSV는 첫 3개 논리 행 안에서 알려진 필드가 있는 헤더를 찾고 이후 행을 검사합니다. 따옴표 안의 개행은 같은 행입니다. 버전 행·BOM·따옴표·개행을 처리하며 쉼표 구분만 지원합니다.
- v2는 좌표·시각 이외에도 `create_time`, `update_time`, `datauuid`, `deviceuuid`, `pkg_name`, `extra_data`, `day_time`, `step_count`, `calorie`로 요약·관리 CSV 헤더를 인식합니다. 이 필드들을 위치 관측 시각으로 해석하지 않습니다. CSV 헤더의 `com.samsung.health.` 또는 `com.samsung.shealth.` 접두사와 그 뒤의 `exercise.`, `activity.day_summary.`, `calories_burned.details.` 접두사는 제거한 뒤 고정 목록과 비교합니다. 그 밖의 별칭은 추측하지 않습니다.
- CSV 헤더 집계는 좌표·관측 시각·부가 자료 참조 열의 존재만 셉니다. 이후 행 검사에 실패한 파일도 포함하므로 실제 좌표나 경로의 존재를 입증하지 않습니다. 행 검사 실패 시 해당 파일의 값 후보 집계는 전부 제외합니다.
- CSV 제외 사유는 `CSV_SYNTAX`(따옴표 등 문법 오류), `CSV_HEADER`(첫 3행에 알려진 헤더 없음), `CSV_DUPLICATE`(정규화 후 중복 헤더), `CSV_WIDTH`(헤더와 행의 열 개수 불일치), `CSV_ENCODING`(NUL 또는 대체 문자 발견), `CSV_LIMIT`(행·열 한도)로 구분합니다. `CSV_HEADER`는 파일 손상을 뜻하지 않으며 미지원 구분자·필드 구성일 수도 있습니다. 인코딩을 추측해 변환하지 않습니다.
- 알려진 좌표 키: `latitude/longitude`, `lat/lng`, `lat/lon`, `latitudeE7/longitudeE7`, 문자열 `LatLng`/`latLng`. 위도 ±90·경도 ±180 범위와 숫자 표현을 확인합니다. 같은 객체에 여러 표현이 있으면 유효한 표현 하나로 후보를 세며 표현 사이 일치 여부는 검증하지 않습니다.
- 알려진 시각 키: `timestamp`, `time`, `start_time`, `startTime`, `timestampMs`. 숫자·긴 숫자 문자열·날짜 시각 모양만 검사합니다. 숫자 0도 후보입니다. 단위, 실제 달력 날짜, 시간대, 좌표와 시각의 의미상 관계는 판별하지 않습니다.
- 폴더/파일 이름은 `exercise`, `route`, `location_data`의 고정 범주 건수에만 사용합니다. 이름·식별자·임의 필드명·값·예외 원문은 결과와 로그에 내보내지 않습니다. 이름 범주는 서로 겹칠 수 있습니다.
- 모르는 필드의 하위 JSON 객체는 계속 검사하되 의미는 추정하지 않습니다. 문자열 속 JSON, 압축·인코딩 문자열, 좌표 배열, 파일 간 참조와 위 목록 밖의 별칭은 해석하지 않습니다. CSV 문자열에 들어 있는 JSON도 해석하지 않습니다. 알려지지 않은 자료는 판단 보류입니다.
- 후보 수는 중첩 객체/행 수이며 운동 횟수나 실제 관측 개수와 다를 수 있습니다. `extra_data.json` 이름만으로 위치 포함 여부를 판정하지 않습니다.

## 처리 한도와 개인정보

최대 2,000개 파일, 파일당 8 MiB, 누적 읽기 64 MiB, 합산 1,000,000개 노드, 깊이 48, CSV 파일당 512열·100,000개 논리 행(버전 행·헤더 포함)입니다. 파일 개수 초과 시 내용 읽기 전에 전체 검사를 중단합니다. 파일 크기·누적 한도 초과 파일과 미지원 확장자는 읽지 않습니다. 노드·깊이 한도는 부분 검사로 표시하며 완료된 다른 파일 결과와 구별합니다. 파일 선택 순서에 따라 한도 안에서 검사되는 범위는 달라질 수 있습니다.

JSON/CSV는 브라우저 내부 Blob Worker에서 처리하며 완료·취소·재선택 시 worker와 Blob URL을 해제합니다. CSP로 외부 연결을 차단하고 데이터 전송·분석 SDK·영구 저장을 사용하지 않습니다. 화면에 표시되는 집계도 개인 데이터의 존재에 관한 정보이므로 공유 여부는 사용자가 결정합니다.

실제 자료를 에이전트가 읽지 않는 개발 흐름을 유지합니다. 이 도구의 결과는 기존 Google Timeline 앱 입력 형식을 확대하지 않습니다. 위치 후보 발견 후에도 합성 fixture로 파서를 별도 구현·검증해야 합니다.

## 합성 검증

`node --test tests/samsung-diagnostics.test.cjs` (저장소 루트, Node 18 이상). 기본 `npm run check`에도 포함됩니다. 완전 합성 입력으로 중첩 좌표·0/E7·CSV·오류 비노출·파일/노드/깊이 한도를 검증합니다.

Node 22.12 이상과 Playwright·Edge가 있으면 `node tests/samsung-diagnostics-smoke.cjs`로 실제 `file://` 폴더 선택·worker·취소·재선택·결과 삭제·네트워크 요청 0건을 검증합니다. 테스트가 만든 임시 합성 폴더만 사용하고 끝나면 삭제합니다. 개인 파일 경로를 인자로 받지 않습니다.
