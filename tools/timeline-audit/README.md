# Timeline·GPX 로컬 진단

대용량 JSON에서 사용자가 누락 구조를 직접 찾지 않도록 전체 구조와 현재 앱의 관측 채택 범위를 검사합니다. 같은 화면에서 GPX의 구조와 비교에 사용할 좌표·시각의 유효성도 진단합니다. 기존 샘플 생성기와 지도 앱의 지원 형식은 변경하지 않습니다.

## 실행과 사용

저장소 루트에서 실행합니다.

```sh
npm run audit:build
npm run audit:preview
```

1. 터미널에 표시된 로컬 주소(기본 `http://127.0.0.1:4190/`)를 엽니다.
2. **JSON·GPX 선택**으로 사용자가 원본을 직접 선택합니다. 한 번에 한 파일을 검사하며 장소 매핑은 필요 없습니다.
3. 탐색 완료 후 **공유용 진단 보고서 저장**을 누릅니다.
4. 필요하면 `timeline-structure-report.txt` 또는 `gpx-structure-report.txt`만 공유합니다. 원본·샘플·화면의 위치 정보는 보내지 않습니다.

앱이 받지 못하는 형식도 구조 검사는 시도합니다. 보고서는 자동 전송되지 않습니다. 새 파일 선택은 이전 검사를 취소하며 **지우기**는 메모리의 보고서를 지웁니다. 사용자가 내려받은 보고서 파일까지 삭제하지는 않습니다.

지도 앱과 다른 출력·캐시 경로(`node_modules/.cache/timeline-audit-*`)를 사용하므로 이 도구의 빌드가 기존 지도 화면이나 열린 데이터 세션을 갱신하지 않습니다. 개발 서버 대신 빌드 후 preview로 사용합니다.

## JSON 검사 범위

- 최대 64 MiB의 JSON을 Worker에서 읽습니다. 표준 JSON 파싱 결과의 모든 객체·배열·값을 반복문으로 순회하며, 항목 수·깊이로 탐색을 중단하거나 배열 일부만 샘플링하지 않습니다.
- 앱과 동일한 `parseRawValue`를 실행하여 오류 필터 적용 전 rawSignals의 채택·위치 외 신호·잘못된 위치 관측 건수를 보고합니다. 앱의 100,000개 기록 한도와 rawSignals 지원 정책은 그대로입니다. 미지원/한도 초과는 채택 0건으로 오해하지 않도록 따로 표시합니다.
- 알려진 관측·방문·이동·경로 형태, 좌표/시각 형식 문자열, 이름을 해석하지 못한 필드를 전체 구조에서 집계합니다. 후보 수는 유효한 기록 수가 아니며 서로 중첩될 수 있습니다.
- 반복 구조를 `[]` 경로로 묶어 자료형과 건수를 표시합니다. 고정된 스키마 이름 외의 키는 `필드1` 같은 별칭으로 바꾸며, 원래 이름과 대응표를 출력하지 않습니다.
- 보고서의 상세 목록은 1,200개 경로·1,200개 별칭·표시 깊이 16으로 제한합니다. **탐색 자체의 제한이 아닙니다.** 상세 미등재 항목·경로 축약·별칭 한도 초과를 별도 집계합니다. 표시 깊이 이후의 구조는 한 경로에 합쳐질 수 있습니다.
- 취소·파싱 실패·메모리 등 처리 실패는 미완료로 표시합니다. 남은 항목 수를 알 수 없으면 추정하지 않습니다.

## GPX 검사 범위

- 최대 64 MiB, UTF-8(선택적 BOM)의 GPX 1.0/1.1을 진단합니다. GPX 표준 namespace와 version이 일치해야 기록 의미를 해석합니다. 다른 XML·namespace 누락/불일치는 구조를 탐색하되 미지원으로 표시합니다. GPX 확장자는 선택 편의를 위한 힌트이며 XML 내용도 판별합니다.
- namespace-aware SAX 파서를 Worker에서 실행해 모든 요소·속성을 순회합니다. 별도 노드·깊이 탐색 한도 없이 진행하되 JSON과 같은 상세 목록 제한을 두고 생략 건수를 밝힙니다. XML 중복 속성·잘못된 중첩은 오류이며 복구하지 않습니다.
- 표준 경로의 트랙·구간·트랙점, 루트·루트점, 웨이포인트를 나눠 집계합니다. 확장 영역에 같은 이름의 요소가 있어도 관측으로 취급하지 않습니다.
- 위도 `[-90,90]`, 경도 `[-180,180)`의 십진수, 명시적 시간대가 있는 지원 ISO 시각을 검사합니다. 시각 없음/불량/시간대 없음/중복 요소를 구분하고 좌표와 시각이 모두 유효한 점 수를 보고합니다. 시간대 누락을 UTC로 가정하지 않습니다. ISO 시각은 기존 앱 검증 함수의 달력·최대 소수 9자리·시간대 범위를 따르며 윤초·기타 미지원 표현을 보정하지 않습니다.
- 같은 트랙 구간 또는 루트에서 인접한 좌표·시각 유효 점의 시간차만 비교합니다. 구간 경계·불량/누락 점을 건너 연결하거나 재정렬하지 않습니다. 동일 시각·역순·양의 간격 구간과 30분 초과 건수만 보고하며 실제 시각/기간의 시작·끝은 출력하지 않습니다. 웨이포인트를 이동 경로로 연결하지 않습니다.
- 표고, fix, 위성 수, HDOP/VDOP/PDOP, GPX 1.0 speed의 존재/유효/불량을 집계합니다. 직접 scalar 필드에 자식 요소·중복 요소가 있거나 텍스트가 256자를 넘으면 불량/미지원으로 분류하며, 전체 구조 탐색은 계속합니다. HDOP를 미터 오차로 환산하지 않습니다. 앱별 정확도·속도 확장은 구조만 표시하고 의미·단위를 추정하지 않습니다.
- 알 수 없는 요소/속성은 namespace URI와 localName 조합별 별칭으로 표시합니다. 원래 이름·접두사·URI·creator·트랙명·주석·처리 지시 본문·텍스트/속성값은 출력하지 않습니다. namespace 선언은 개수만 셉니다. DTD·사용자 정의 엔터티와 비 UTF-8 선언/인코딩은 고정 오류로 중단하며 외부 스키마·스타일시트·링크를 가져오지 않습니다.
- XML 구문과 일부 GPX 필드 진단이며 XSD 전체 검증은 아닙니다. 현재 지도 앱의 GPX 입력 지원이나 실제 Timeline과의 시간 겹침/거리 비교가 추가된 것은 아닙니다. KML은 지원하지 않습니다. 자세한 계약은 [GPX 진단 명세](../../specs/2026-10-08-000-gpx-local-audit.md)를 참고하세요.

## 개인정보와 한계

파일 내용·좌표·시각·장소명·식별자·파일명·임의 필드명·오류 원문은 보고서나 콘솔에 출력하지 않습니다. 외부 요청·브라우저 영구 저장이 없으며 CSP의 `connect-src 'none'`으로 연결을 제한합니다. 원본은 변경하지 않고 검사 종료 후 Worker를 종료합니다. UI에는 값 없는 집계 보고서만 남습니다. 구조·건수도 정보이므로 완전한 익명성을 보장하지 않습니다.

**탐색 완료는 의미 해석 완료나 모든 Timeline 버전 지원을 뜻하지 않습니다.** 알 수 없는 필드는 표시하되 임의로 좌표·방문으로 해석하지 않습니다. 문자열 속 JSON/인코딩/압축 데이터는 펼치지 않으며 JSON처럼 시작하는 문자열만 보조 집계합니다. 숫자 시각이나 임의 숫자 배열의 의미는 확정하지 않습니다. 표준 JSON 파싱은 같은 객체의 중복 키 중 마지막 값만 유지하며, 이 도구는 원문 중복 키 검사기가 아닙니다. 손상된 JSON은 부분 복구하지 않습니다.

이 보고서는 파서 보완 대상을 좁히기 위한 자료입니다. 실제 위치의 정확성, GPS Logger와의 일치, 위치 튐 판정을 입증하지 않습니다. GPX/KML 비교는 별도 작업이며, 기존 가상 샘플의 거리·방향·정확도 치환을 원본 GPS 품질 검증에 사용하지 않습니다.

## 합성 검증

```sh
npm run typecheck
npm test
npm run audit:build
node tests/structure-audit-smoke.cjs
```

브라우저 검증에는 Playwright와 Edge가 필요합니다. 외부 요청을 차단하고 합성 파일만 사용합니다. JSON 200만 개 초과 항목, 200단계 중첩, 배열 끝의 형식 변화, 보고서 상세 한도, 실제 앱 파서 건수 일치를 확인합니다. GPX 1.0/1.1·namespace·다중 구간·시각/좌표 이상·선택적 필드·확장 요소·대용량·손상 XML·DTD·인코딩을 검증합니다. 두 형식 모두 민감값 모사 문자열 비출력, 취소·교체·다운로드·모바일 화면·외부 요청/저장소 미사용을 확인합니다.
