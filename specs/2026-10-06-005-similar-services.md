# 유사 서비스 조사

상태: 2026-10-06 사용자 요청에 따라 서비스 자체 분석을 수행하고 핵심 정리와 상세 분석을 작성했다. 프로젝트 비교·적용 판단은 이번 범위에서 제외한다. 기능 구현·병합 완료를 뜻하지 않는다.

## 목적과 기준

[PRD](../docs/PRD.md), [공통 기반](2026-10-06-001-mvp-foundation.md), [화면 개발 명세](2026-10-06-004-globe-ui.md)는 프로젝트 배경이다. 최신 사용자 지시에 따라 이번에는 각 서비스의 목적·사용 흐름·기능·조건을 분석하며 Footprint Globe와 비교하지 않는다. 프로젝트에 참고하거나 제외할 요소, 적용 우선순위는 이번 산출물에 포함하지 않는다.

- 작업 브랜치: `codex/similar-services`
- 출발점: 명세 준비 시 원격 main `5794ac51fb5d598c9190d979a17c145455288265`
- 현재 사용자 폴더는 브랜치 전환 없이 유지한다. 조사 브랜치를 만들기 위해 다른 진행 중 브랜치나 worktree를 변경하지 않는다.
- 실제 Timeline 원본·원본 기반 샘플·사진을 조사나 체험에 사용하지 않는다.

## 핵심 질문

1. 사용자가 위치 기록을 가져와 과거의 이동과 방문을 탐색하는 흐름을 어떻게 제공하는가?
2. 실제 기록 경로와 관측 사이 연결, 긴 시간 공백을 어떻게 구별하는가?
3. 가까운 점·같은 장소의 재방문·밀집 기록을 확대하고 선택하는 방식은 무엇인가?
4. 방문을 직접 지정하고 사진을 연결하는 과정은 얼마나 명확한가?
5. 기록과 사진을 어디서 처리·보존하며 서버 전송, 계정, 지도 요청이 필요한가?
6. 각 서비스가 중심으로 삼는 기록 단위와 결과물은 무엇이며, 어떤 사용 목적에 집중하는가?

## 조사 대상과 선정

공개 접근 가능한 후보를 먼저 탐색한 뒤 5–8개 정도를 비교 대상으로 선정한다. 개수를 채우기 위한 무관한 서비스는 넣지 않는다. 적합한 대상을 충분히 찾지 못하면 실제 조사 수와 이유를 기록한다.

- 직접 비교군: Google Timeline 내보내기나 개인 위치 기록을 가져와 시각화하는 서비스·공개 도구
- 인접 비교군: 여행 경로·여행 일지·방문 장소와 사진을 지도에서 보여주는 서비스
- 구현 참고군: 로컬 처리나 지구본·밀집 지점 탐색에 참고할 수 있는 공개 프로젝트

각 대상의 선정 이유와 서비스 유형을 적는다. 이번에는 프로젝트와의 직접 비교 여부를 평가하지 않는다. GPX·KML 등 지원을 Google Timeline JSON 지원으로 해석하지 않는다. 웹/모바일, 2D 지도/3D 지구본, 온라인 서비스/로컬 도구의 차이를 구별한다. 일반 지도 라이브러리는 서비스 분석 대상과 분리한다.

## 입력·출력

입력은 현재 프로젝트 문서와 공개된 공식 사이트·도움말·개인정보 안내·공식 저장소·공개 데모다. 조사 시점에 존재와 접근 가능성을 확인하며 과거 지식만으로 현재 기능을 단정하지 않는다.

산출물은 두 파일로 나눈다.

- `docs/research/similar-services.md`: 전문 용어와 복잡한 서술을 배제한 핵심 정리. 서비스별 용도·사용 흐름·주요 조건을 쉽게 설명한다.
- `docs/research/similar-services-analysis.md`: 출처·판단 기준·기술적 설명·확인 한계가 포함된 상세 분석.

두 문서는 다음 내용을 독자에 맞게 나누어 담는다.

- 조사일, 목적·대상 선정 기준과 조사 범위
- 서비스별 짧은 소개와 비교표
- 핵심 기능별 관찰 결과 및 주장에 바로 연결되는 출처
- 서비스별 특징과 그 해석의 근거
- 확인하지 못한 사항과 상충하는 공식 설명
- 프로젝트 비교나 기능 도입 우선순위를 포함하지 않는 서비스 자체 분석

문서는 한국어로 작성하고 기술 비전문가도 이해할 수 있게 설명한다. 서비스 개수나 점수 자체보다 사용자 흐름과 현재 제약에 대한 비교를 우선한다.

## 공통 비교 항목

| 항목 | 확인할 내용 |
| --- | --- |
| 대상·환경 | 주 사용자, 웹/앱/로컬 실행, 계정 필요 여부 |
| 가져오기 | 지원 파일 형식과 확인 가능한 버전·한도, Google Timeline 직접 지원 여부 |
| 위치·경로 | 2D/3D, 실제 경로와 추정 연결 구분, 시간 공백 표현, 필터 |
| 탐색·선택 | 확대 수준, 밀집 점 처리, 같은 장소 재방문 구분, 선택 UI |
| 방문·사진 | 자동/수동 방문, 사진 첨부·교체·삭제·탐색, 자동 배치 여부 |
| 처리·보존 | 브라우저/기기/서버 처리, 업로드·보존·삭제·내보내기, 외부 지도 통신 |
| 사용 제약 | 무료/유료 구분과 핵심 기능 제한, 조사 시점의 운영 상태 |
| 특징 해석 | 서비스의 핵심 목적, 기능 조합의 의미, 사용 조건과 확인 근거의 수준 |

가격을 기재하면 통화·요금 주기·확인일을 함께 기록한다. 소스 공개와 코드·데이터·디자인 재사용 허용은 별개이며 재사용을 제안할 때 라이선스를 확인한다. 저장소 코드나 라이브러리를 실제로 도입하지 않는다.

## 확인 방법과 근거 수준

- 검색은 후보 발견에 활용하고 핵심 주장은 공식 설명·정책·저장소 등 1차 자료로 확인한다.
- 근거를 ‘공식 문서에서 확인’, ‘공개 데모에서 직접 확인’, ‘코드에서 확인’, ‘추론’, ‘미확인’으로 구별한다. 공식 설명만 읽고 직접 체험했다고 쓰지 않는다.
- 데모 확인은 공개 예제나 완전 합성 자료만 사용한다. 새 계정 생성·유료 결제·개인 계정 로그인·외부 파일 업로드가 필요하면 그 지점은 미확인으로 남기고 이유를 기록한다.
- 특히 ‘로컬 전용’, ‘전송 없음’은 파일 선택 UI만 보고 단정하지 않는다. 지도 서버 요청과 사용자 기록 업로드를 구별하며 확인 가능한 범위만 적는다.
- 개인정보 정책과 실제 설명이 충돌하거나 지역·플랫폼·버전에 따라 다르면 차이를 기록한다.
- 접근 불가·서비스 종료·문서 부재·확인 불가능한 JSON 형식은 그대로 표시한다. 문서에 없음을 기능이 없다는 뜻으로 바꾸지 않는다.
- 원본 화면 캡처, 파일명, 위치, 시각, 장소 또는 식별자를 조사 자료·로그·외부 서비스에 전달하지 않는다. 인용·이미지 사용은 필요한 범위와 출처를 지킨다.

## 결정 범위와 제외

조사는 제품 결정을 위한 근거 제공이다. 서버 저장·로그인·공유·자동 방문 추론·EXIF 배치·지도 외부 요청을 채택하지 않는다. 최종 경로 표시·시간대·사진 한도·지원 형식도 조사 결과만으로 확정하지 않는다.

서비스 순위나 시장 규모, 사용자 수·성장률 추정, 법률적 준수 판정, 유료 구독 체험, 소스·디자인 복제, 신규 기능 구현은 제외한다. 결론에 대안과 비용·개인정보 영향이 필요하면 확인 사실과 제안을 분리한다.

## 미확정 사항

우선 비교할 특정 서비스·지역은 지정되지 않았다. 특정 후보나 선호가 추가되면 선정 기준에 반영한다. 미지정 상태에서는 핵심 질문에 직접 도움이 되는 대상을 선정할 수 있으며, 제품 정책을 바꿀 제안은 사용자 결정 항목으로 남긴다.
