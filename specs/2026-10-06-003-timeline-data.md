# 데이터 처리 분리 개발

상태: 사용자 요청으로 작성한 개발 명세. 이번 요청은 명세·작업 브랜치 준비이며 기능 구현·병합 완료를 의미하지 않는다.

## 목적과 기준

[PRD](../docs/PRD.md), [공통 기반](2026-10-06-001-mvp-foundation.md), [미리보기](2026-10-06-002-local-preview.md)를 따른다. 이미 구현된 rawSignals 파서를 다시 만드는 대신, 화면 작업과 독립적으로 입력 검증·정규화·오류 처리를 보완하고 호환성의 검증 범위를 명확히 한다.

- 작업 브랜치: `codex/timeline-data`
- 화면 작업: [화면 개발 명세](2026-10-06-004-globe-ui.md), `codex/globe-ui`
- 공통 코드 기준: PR #8 병합 커밋 `374e12f7084780545ee48680fa5490bdea7791f9`. 두 브랜치는 이를 포함한 동일한 명세 준비 커밋에서 갈라진다. 한쪽 기능 커밋 위에 다른 쪽을 쌓지 않는다.
- 명세 작성은 실제 파일 접근 허가가 아니다. 완전 합성 입력만 사용하고 실제 원본은 사용자가 로컬 앱에서 확인한다.

## 범위

1. `parseTimeline`을 기준으로 기존 지원 형식과 한도, 부분 실패 동작을 검증한다.
2. 좌표·시각 경계값과 동일 장소 재방문, 안정적인 ID·정렬, 집계 일관성을 확인하고 발견한 결함을 수정한다.
3. 합성 규모 입력으로 처리 시간·메모리 부담을 확인하고 필요할 때 기존 의미를 보존하는 개선을 한다. 원본을 조용히 샘플링하지 않는다.
4. 화면이 소비하는 계약과 실제 반환값이 같음을 검증하고 지원·미지원 범위 및 로컬 확인 절차를 정리한다.

새 Timeline 형식, 원시 신호로부터 방문·교통수단 추론, 도로 예측, 연결 표시 정책, UI·사진, 저장·전송, 샘플 생성기 정책 변경은 제외한다. PRD의 기록된 방문·경로 기능 전체를 이 rawSignals 작업으로 완료했다고 표시하지 않는다.

## 입력과 출력 계약

- 진입점: `src/parser/index.ts`의 `parseTimeline(text, datasetId): Promise<ParseResult>`.
- 텍스트와 데이터셋 ID만 받는다. File·DOM·React·Three.js·Object URL에 의존하지 않는다. CPU 작업은 화면 측 worker에서 실행된다.
- 현재 지원은 최상위 rawSignals 배열의 position.LatLng 또는 position.latLng 좌표 문자열과 ISO 시각이다. geo:/도 기호 등 구체 문법은 기존 구현과 테스트를 따른다. semanticSegments/timelineObjects 혼합 입력은 기존대로 미지원 처리한다.
- 기존 미리보기 한도는 64 MiB·원시 신호 100,000개다. 한도 확대나 지원 형식 추가는 별도 사용자 결정 없이 하지 않는다.
- 성공: `{ ok: true, data: TimelineData, counts: ImportCounts }`. 실패: `{ ok: false, code: ImportError, counts?: ImportCounts }`.
- 유효 관측을 실제 시점 순으로 반환한다. 원본 소수초 정밀도로 정렬하고 같은 시점은 원본 순서를 유지한다. 화면은 epochMs로 다시 정렬해 밀리초 미만의 순서를 손상시키지 않는다.
- ID는 데이터셋 안에서 고유하며 정렬·표시 변경과 무관하게 유지한다. 같은 좌표나 같은 시각만으로 관측을 합치지 않는다.
- recordedVisits/recordedPaths는 현재 rawSignals 추출에서 빈 배열이다. 관측 사이 연결이나 사용자 지정 방문은 파서가 만들지 않는다.

## 예외와 개인정보

- 0 좌표를 정상값으로 유지하고 위도·경도 범위 및 순서를 검증한다. 현재 지원하지 않는 E7 입력을 임의로 좌표 문자열처럼 해석하지 않는다.
- 잘못된 위치 기록은 제외 집계하고 위치 외 신호도 별도 집계한다. 유효 관측이 없으면 NO_VALID_POSITIONS다.
- 전체 검사 후 input = accepted + ignoredSignals + invalidPositions를 만족해야 한다. ignoredRootFields는 별도 필드 수다. counts 누락을 0건으로 해석하지 않는다.
- JSON 오류·미지원 형식·입력 한도는 고정 코드로 반환한다. 파일 읽기와 예상치 못한 실행 예외의 비식별 처리는 화면 측 importFile 경계가 담당한다.
- 추가 메타데이터는 결과에 복사하지 않는다. 원본 값·파일명·임의 필드명·예외 원문을 로그나 진단에 넣지 않는다. 미지원 필드를 안전하게 치환해야 하는 샘플 도구와 앱의 위치 추출 정책을 혼합하지 않는다.

## 담당 파일과 협업

주 담당은 `src/parser/`와 그 안에 추가하는 합성 테스트다. 기존 `src/features/preview/preview.test.ts`의 파서 관련 검증도 회귀 실행하되 화면 담당과 동시에 편집하지 않는다. 필요하면 독립 테스트를 parser 아래 추가한다.

`src/domain/`, 공유 fixture, 패키지·잠금·빌드 설정, 공통 문서는 공동 경계다. 변경이 필요하면 먼저 조율하고 한 담당자가 수정한다. 계약을 한쪽에서 바꾼 뒤 다른 쪽에 맞추라고 요구하지 않는다. 이 spec은 데이터 담당이 유지한다.

## 검증과 완료 기준

- [ ] 정상·잘못된 JSON·미지원·혼합 구조·빈 입력·부분 실패 결과 검증
- [ ] 0/음수/경계 좌표, 누락·잘못된 자료형·표현, 잘못된 날짜·오프셋·윤일·소수초 정렬 검증
- [ ] 동일 위치 재방문·동일 시각·순서가 뒤섞인 입력에서도 관측 보존과 ID 고유성 검증
- [ ] 현재 한도 경계와 10,123개 이상의 완전 합성 관측에서 무단 축소가 없음을 확인; 필요시 성능 측정 조건과 결과 기록
- [ ] 실제·합성 파서가 동일한 화면 소비 계약을 만족하며 부분 실패 집계와 고정 오류만 반환하는지 검증
- [ ] `npm run check` 통과, 관련 변경 시 `tests/app-smoke.cjs`로 실제 worker 통합 회귀 확인
- [ ] 지원 범위·제외 정책·검증하지 않은 형식과 실제 파일 확인 한계를 문서화

기존 테스트로 확인된 항목은 결과를 검토해 재사용하며 형식적인 중복 테스트를 만들지 않는다. 개선할 결함이 없으면 불필요한 리팩터링 대신 검증 결과를 남긴다. 실제 원본 호환성 확인은 사용자 수행 결과와 합성 검증을 구별한다.

## 진행·병합과 미확정 사항

같은 브랜치에서 의미 있는 수정마다 검증·커밋·푸시한다. 전체 범위가 완료되면 PR을 만들고 검토한다. 병합·정리는 해당 작업의 사용자 승인 범위에서만 수행한다. 데이터 PR 병합 후 화면 브랜치가 최신 main을 반영하며 별도 통합 브랜치는 만들지 않는다.

추가 입력 형식·MVP 전체 한도·지원 브라우저 확대는 미확정이다. 이 결정 없이도 기존 rawSignals 범위의 검증·보완은 진행할 수 있다. 표시 시간대·사진 정책은 데이터 파서가 확정하지 않는다.
