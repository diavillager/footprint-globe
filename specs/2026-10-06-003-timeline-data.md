# 데이터 처리 분리 개발

상태: 사용자가 2026-10-06에 구현·검증·커밋·푸시·PR 생성을 승인했다. 아래 rawSignals 검증·보완을 완료했으며 병합·정리는 별도 승인 전 대기한다. MVP 전체 완료나 실제 원본 호환성 보장을 의미하지 않는다.

[PRD](../docs/PRD.md), [공통 기반](2026-10-06-001-mvp-foundation.md), [미리보기](2026-10-06-002-local-preview.md)를 따른다. 이미 구현된 rawSignals 파서를 다시 만드는 대신, 화면 작업과 독립적으로 입력 검증·정규화·오류 처리를 보완하고 호환성의 검증 범위를 명확히 한다.

- 작업 브랜치: `codex/timeline-data`
- 화면 작업: [화면 개발 명세](2026-10-06-004-globe-ui.md), `codex/globe-ui`
- 공통 코드 기준: PR #8 병합 커밋 `374e12f7084780545ee48680fa5490bdea7791f9`. 두 브랜치는 이를 포함한 동일한 명세 준비 커밋에서 갈라진다. 한쪽 기능 커밋 위에 다른 쪽을 쌓지 않는다.
- 명세 작성은 실제 파일 접근 허가가 아니다. 완전 합성 입력만 사용하고 실제 원본은 사용자가 로컬 앱에서 확인한다.

## 범위

1. `parseTimeline`을 기준으로 기존 지원 형식과 한도, 부분 실패 동작을 검증한다.
2. 좌표·시각 경계값과 동일 장소 재방문, 안정적인 ID·정렬, 집계 일관성을 확인하고 발견한 결함을 수정한다.
3. 합성 규모 입력으로 처리 시간·메모리 부담을 확인하고 필요할 때 기존 의미를 보존하는 개선을 한다. 원본을 조용히 샘플링하지 않는다.
4. 화면이 소비하는 계약과 실제 반환값이 같음을 검증하고 지원·미지원 범위 및 로컬 확인 절차를 정리한다.

새 Timeline 형식, 원시 신호로부터 방문·교통수단 추론, 도로 예측, 연결 표시 정책, UI·사진, 저장·전송, 샘플 생성기 정책 변경은 제외한다. PRD의 기록된 방문·경로 기능 전체를 이 rawSignals 작업으로 완료했다고 표시하지 않는다.

## 입력과 출력 계약

- 진입점: `src/parser/index.ts`의 `parseTimeline(text, datasetId): Promise<ParseResult>`.
- 텍스트와 데이터셋 ID만 받는다. File·DOM·React·Three.js·Object URL에 의존하지 않는다. CPU 작업은 화면 측 worker에서 실행된다.
- 현재 지원은 최상위 rawSignals 배열의 position.LatLng 또는 position.latLng 좌표 문자열과 ISO 시각이다. geo:/도 기호 등 구체 문법은 기존 구현과 테스트를 따른다. semanticSegments/timelineObjects 혼합 입력은 기존대로 미지원 처리한다.
- 기존 미리보기 한도는 64 MiB·원시 신호 100,000개다. 한도 확대나 지원 형식 추가는 별도 사용자 결정 없이 하지 않는다.
- 성공: `{ ok: true, data: TimelineData, counts: ImportCounts }`. 실패: `{ ok: false, code: ImportError, counts?: ImportCounts }`.
- 유효 관측을 실제 시점 순으로 반환한다. 원본 소수초 정밀도로 정렬하고 같은 시점은 원본 순서를 유지한다. 화면은 epochMs로 다시 정렬해 밀리초 미만의 순서를 손상시키지 않는다.
- ID는 데이터셋 안에서 고유하며 정렬·표시 변경과 무관하게 유지한다. 같은 좌표나 같은 시각만으로 관측을 합치지 않는다.
- recordedVisits/recordedPaths는 현재 rawSignals 추출에서 빈 배열이다. 관측 사이 연결이나 사용자 지정 방문은 파서가 만들지 않는다.

## 예외와 개인정보

- 0 좌표를 정상값으로 유지하고 위도·경도 범위 및 순서를 검증한다. 현재 지원하지 않는 E7 입력을 임의로 좌표 문자열처럼 해석하지 않는다.
- 잘못된 위치 기록은 제외 집계하고 위치 외 신호도 별도 집계한다. 유효 관측이 없으면 NO_VALID_POSITIONS다.
- 전체 검사 후 input = accepted + ignoredSignals + invalidPositions를 만족해야 한다. ignoredRootFields는 별도 필드 수다. counts 누락을 0건으로 해석하지 않는다.
- JSON 오류·미지원 형식·입력 한도는 고정 코드로 반환한다. 파일 읽기와 예상치 못한 실행 예외의 비식별 처리는 화면 측 importFile 경계가 담당한다.
- 추가 메타데이터는 결과에 복사하지 않는다. 원본 값·파일명·임의 필드명·예외 원문을 로그나 진단에 넣지 않는다. 미지원 필드를 안전하게 치환해야 하는 샘플 도구와 앱의 위치 추출 정책을 혼합하지 않는다.

## 담당 파일과 협업

주 담당은 `src/parser/`와 그 안에 추가하는 합성 테스트다. 기존 `src/features/preview/preview.test.ts`의 파서 관련 검증도 회귀 실행하되 화면 담당과 동시에 편집하지 않는다. 필요하면 독립 테스트를 parser 아래 추가한다.

`src/domain/`, 공유 fixture, 패키지·잠금·빌드 설정, 공통 문서는 공동 경계다. 변경이 필요하면 먼저 조율하고 한 담당자가 수정한다. 계약을 한쪽에서 바꾼 뒤 다른 쪽에 맞추라고 요구하지 않는다. 이 spec은 데이터 담당이 유지한다.

## 2026-10-06 검증·보완 결과

### 변경과 회귀 검증

- `src/parser/timeline.test.ts`에 공통 진입점의 독립 합성 테스트 27개를 추가했다. 좌표 범위·자료형·표현, 누락·중복 좌표 키, 날짜·오프셋·윤일, 부분 실패 집계, 동시점의 원본 순서·나노초 정렬·ID 고유성, BOM, 미지원·혼합 루트, 정확히 100,000개와 초과 입력, UTF-8 64 MiB 경계·다중 바이트 문자열을 검증한다.
- 일부 유효 시각에서 정수 밀리초에 오차가 추가되는 결함을 재현했다. 예를 들어 완전 합성 시각 `2200-01-01T00:00:00.008Z`가 기존에는 `7258118400007.999`로 반환됐다. 전체 나노초를 부동소수점으로 바꾸는 대신 정수 밀리초와 작은 소수 부분을 나눠 계산해 `7258118400008`을 반환한다. 0001·2200·9999년 회귀 사례가 수정 전 실패하고 수정 후 통과했다. BigInt 정렬·원본 시각·ID·지원 문법은 유지한다. 밀리초 미만 값은 여전히 근사값이므로 `epochMs`로 재정렬하지 않는다.
- 기존 `preview.test.ts`, `importFile.test.ts`, `domain/timeline.test.ts`를 수정 없이 회귀 실행했다. 실제/합성 파서 교체, 고정 오류, 파일/실행 경계 예외 비식별화, 10,123개 관측 보존과 연결 수를 기존 검증으로 확인했다.
- Node 24.19.0 / Windows x64에서 `npm run check` 통과: 샘플 도구 66개, 앱 43개 테스트, 타입 검사·빌드 성공. 별도 lint 명령은 없다. 기존 대형 번들 경고는 남아 있다.
- 보정 후 `node tests/app-smoke.cjs`도 Edge headless의 개발·배포 모드에서 통과했다. 실제 worker에 합성 10,123개 관측을 전달하고 잘못된 입력 복구·지우기, 메타데이터·파일명 canary 비노출, localStorage/sessionStorage 미사용, 외부 요청 0건·페이지 오류 0건을 확인했다. 개발 서버의 JSON 접근 거부 메시지는 의도된 403 검증에서 발생했다.
- 변경은 파서·독립 테스트·측정 도구와 이 담당 명세에 한정한다. README에서 이미 이 문서를 연결하고 있으며, 공유 타입·fixture·설정·화면 파일과 샘플 도구 정책은 수정하지 않았다.

### 합성 규모 측정

재현 명령: Node 24에서 `node --expose-gc src/parser/benchmark.mjs`. 원본 파일이나 인수를 받지 않으며 메모리에서 합성 입력만 생성한다. 역시간순 관측을 만들고 준비 실행 1회 후 3회 측정한다. 입력 생성 시간은 제외하고 UTF-8 크기 검사·JSON 파싱·검증·정렬·결과 생성은 포함한다. 각 회차 직전 GC 후 처리 전후 메모리 차이를 기록한다. 정규화 관측 수가 입력 수와 같은지도 검증한다.

| 관측 수 | 입력 크기 | 처리 시간 3회 | 중앙값 | heapUsed 증가 범위 | RSS 증가 범위 |
| --- | --- | --- | --- | --- | --- |
| 10,123 | 약 0.7 MiB | 104 / 91 / 45 ms | 91 ms | 5.4–8.0 MiB | −0.1–8.2 MiB |
| 100,000 | 약 6.7 MiB | 754 / 518 / 482 ms | 518 ms | 87.5–87.7 MiB | 4.5–28.2 MiB |
| 100,000 | 64 MiB | 668 / 649 / 544 ms | 649 ms | 87.6–87.7 MiB | 4.2–4.8 MiB |

64 MiB 사례는 JSON 뒤에 공백을 채운 것으로, 복잡한 메타데이터를 가진 최대 크기 JSON의 비용을 대표하지 않는다. 메모리 수치는 순간 최고치나 앱 전체 사용량이 아니다. 입력 문자열, 런타임 재사용, GC, 브라우저 파일·worker 복제·지구본 비용 때문에 실제 사용량은 다르며 RSS 차이는 음수일 수도 있다. 이 측정은 성능 보장이나 한도 확대의 근거가 아니다. 측정 실행 시 기존 package.json의 모듈 형식 미지정으로 Node의 `MODULE_TYPELESS_PACKAGE_JSON` 경고가 발생하며 기능 실패는 아니다. 공통 설정은 변경하지 않는다.

### 확인한 지원 범위와 사용자 로컬 확인

- 최상위 `rawSignals` 배열에서 `position.LatLng` 또는 `position.latLng` 중 하나와 `timestamp`를 추출한다. 위도·경도 순서의 십진수 문자열, `geo:` 또는 양쪽 도 기호 표현, 최대 소수 9자리와 범위를 검사한다. E7 객체·배열·숫자나 다른 Timeline 형식을 새로 지원하지 않는다.
- 시각은 기존 4자리 연도 ISO 문법과 `Z` 또는 ±14:00 이내 오프셋, 최대 소수초 9자리를 검사한다. 지역 시간대·표시 시간대·체류를 추론하지 않는다. 관측만 있는 입력에서 기록된 방문·경로 배열은 비어 있다. 방문·경로 전용 입력과 `semanticSegments`/`timelineObjects` 혼합 입력은 미지원이다.
- 위치 외 신호와 잘못된 위치를 별도 집계하며 추가 메타데이터는 복사하지 않는다. 전체 검사 완료 때만 집계 합계를 해석한다. 잘못된 JSON·형식·크기 초과 등 조기 실패의 집계 누락은 0건이 아니다. 원본 식별값이나 예외 원문을 진단에 포함하지 않는다.
- 실제 원본은 열거나 읽지 않았다. 사용자는 [README의 로컬 미리보기 절차](../README.md#실제-기록으로-연결-미리보기)에 따라 브라우저에서 직접 선택하고 성공 여부·고정 오류 코드·집계만 확인할 수 있다. 원본이나 화면 캡처를 채팅에 공유할 필요가 없다. 합성 검증과 이번 수치 보정은 모든 실제 내보내기 버전의 호환성이나 표시 정책의 유용성을 입증하지 않는다.

## 진행·병합과 미확정 사항

같은 브랜치에서 의미 있는 수정마다 검증·커밋·푸시한다. 전체 범위가 완료되면 PR을 만들고 검토한다. 병합·정리는 해당 작업의 사용자 승인 범위에서만 수행한다. 데이터 PR 병합 후 화면 브랜치가 최신 main을 반영하며 별도 통합 브랜치는 만들지 않는다.

추가 입력 형식·MVP 전체 한도·지원 브라우저 확대는 미확정이다. 이 결정 없이도 기존 rawSignals 범위의 검증·보완은 진행할 수 있다. 표시 시간대·사진 정책은 데이터 파서가 확정하지 않는다.
