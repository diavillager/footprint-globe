# Geoapify 랜드마크 연동

작성: 2026-10-07 (한국 시간)
상태: `codex/landmark-footprints`에서 앱 통합 구현 중. 2026-10-07 사용자가 아래 자동 여행일지 흐름을 요청하고 파일당 횟수 제한 해제를 확정했다. 현재 프로덕션에 제공되는 기능이라는 뜻은 아니다.

## 2026-10-07 자동 여행일지로 변경 확정

사용자 최신 요청은 근접 묶기 자체를 조작하는 기능이 아니라 **JSON 등록 → 자동 묶기 → 랜드마크 자동 조회 → 말풍선과 여행일지로 전체 흐름 탐색**이다. 이전의 묶기 토글·묶음별 조회 버튼 정책을 대체한다.

- 첫 관측 기준 100m·인접 공백 120분·첫 관측 대표점은 유지한다. 원본 관측·목록·분포를 보존한다.
- 파일 등록 즉시 자동으로 묶고 지도 범위를 전체 기록에 맞춘다. 조회된 지점에만 가장 가까운 랜드마크 하나를 순번·시간 말풍선으로 표시한다. 클릭하면 후보 목록과 관측 세부정보를 연다. 미조회·빈 결과·실패 지점에는 상시 말풍선을 표시하지 않는다. 왼쪽 목록은 제거하고 파일 등록 때 자동으로 동의 안내를 열고 허용해야 매핑한다. 상단 기록 분포 옆 원형 진행 표시를 가리키거나 누르면 아래에 처리 수·장소/사진 성공·실패·없음·요청 수를 표시한다. 원본 목록은 위치 기록으로 이름을 변경하며 기록 분포 창 상단 좌우 옵션으로 시간 간격·이동 거리를 전환한다. 겹치는 지도 말풍선은 화면 공간에 따라 줄이며 확대·이동하면 다시 선정한다.
- 파일별 안내에서 동의하면 모든 지점을 시간순으로 자동 조회한다. 지도 클릭이나 묶음별 조회 버튼은 필요 없다. 동의 전에는 묶지 않은 원본 관측 경로를 표시한다. UTC/KST 오른쪽의 원본 경로/랜드마크 전환은 원본 관측 전체와 묶음 대표점·랜드마크 표시를 전환하며 동의나 조회 결과를 초기화하지 않는다. 미허용 상태에서 랜드마크를 선택하면 동의 안내를 다시 연다.
- 검색 조건은 관광 명소·볼거리·박물관, 300m/10개이며 가장 가까운 유효 후보를 ‘추정’으로 표시한다. 이는 실제 방문·체류 확정이 아니다. 상세에서 다른 후보를 선택할 수 있다.
- 사용자가 **‘한도 없이 전체 지점 조회’**를 확정했다. 기존 파일당 32회 제한은 폐기한다. 속도 개선 요청에 따라 동시 최대 3건·250ms 시작 간격으로 변경한다. 요청당 10초 제한·자동 재시도 없음은 유지한다. 정확히 같은 대표 좌표의 요청·결과는 공유하되 원본과 재방문 identity는 유지한다. 장소 조회를 먼저 완료하고 고유 대표 장소의 사진을 조회한다. 인증/사용량 오류 시 자동 조회를 중지한다. 그 밖의 실패·빈 결과는 구분하여 표시하고 다음 지점으로 진행한다.
- 후보를 찾으면 Place Details API를 조회한다. `wiki_and_media.image`와 `wikimedia_commons`의 원본·썸네일·File:·Commons 파일 페이지 참조를 해석한다. 파일 참조가 없고 유효한 Wikidata Q ID가 있으면 P18 대표 사진을 조회한다. Commons Imageinfo로 480px 썸네일·저작자·라이선스를 받고 파일 출처와 함께 표시한다. 임의 호스트·SVG·카테고리의 무작위 사진·Wikipedia 이름 검색은 사용하지 않는다. 사진 없음·미지원 참조·조회 실패·브라우저 로딩 실패는 각각 집계한다.
- 이미지 상세 조회도 동시성·타임아웃·취소 제어와 요청 집계에 포함한다. 같은 장소 ID의 상세는 파일 세션에서 한 번만 요청한다. 사진 다운로드는 Wikimedia로 직접 이루어지고 Referrer를 보내지 않는다. 메타데이터 요청은 commons.wikimedia.org와 www.wikidata.org로만 보내며 파일명·Q ID만 전달한다. Geoapify 키·관측 좌표·시각은 전달하지 않는다. CSP는 두 메타데이터 호스트와 upload.wikimedia.org·thumb.wikimedia.org 이미지만 허용한다. 이미지 조회 작업 전체에 10초 제한을 적용하며 하위 메타데이터 요청도 총 요청 수에 포함한다.
- 파일별 동의 안내에 Geoapify 대표 좌표 전송과 Wikimedia 사진 요청을 포함한다. JSON·파일명·시각·기록 ID는 보내지 않는다. 결과·동의·선택은 세션 메모리에만 유지하고 교체·삭제·새로고침 때 초기화한다.
- ‘자동 조회 중지·결과 지우기’는 진행 요청을 취소하고 결과를 지운다. 이미 전송한 요청은 회수할 수 없다. 계정 인증·사용량 오류 상태는 파일 세션에서 유지한다.
- 키는 공개 브라우저용 `VITE_GEOAPIFY_API_KEY`를 사용한다. 자동 조회에 파일당 비용 상한은 없으며 계정 할당량은 서비스 설정을 따른다.

## 목적과 근거

Google Timeline의 연속된 근접 관측을 지도 표시용 지점으로 묶고, 주변 랜드마크 후보를 말풍선으로 탐색하게 한다. 여행의 주요 장소를 쉽게 찾되 관측 연결을 실제 이동 경로로, 가까운 명소를 실제 방문으로 오해하지 않게 한다.

- [현행 PRD](../docs/PRD.md), [상세 지도 명세](2026-10-06-005-detailed-map.md)
- [가상 여행 데이터](../docs/travel-demo.md), [비교 프리뷰와 검증 기록](../tools/landmark-preview/README.md)
- 사용자 확정: 입력 소스는 Google Timeline, 연속 근접 관측 묶기와 랜드마크 말풍선 개발, 랜드마크 API는 Geoapify.
- 지도 표시는 기존 MapLibre GL JS + MapTiler를 유지한다. 삼성 자료, 사용자 사진 첨부, 로그인, DB, 영구 저장, 실제 경로 예측은 이번 범위가 아니다.
- 사용자가 명소 이름을 나중에 알려줄 수 있으므로 합성 여행의 현재 좌표를 확정 랜드마크의 정확한 위치로 취급하지 않는다.

## 범위와 흐름

Timeline 선택 → 로컬 파싱·시간순 정렬 → 자동 묶기·전체 지도 범위 → 파일별 동의 → 전체 지점 자동 조회 → 가장 가까운 랜드마크의 사진 또는 텍스트 말풍선 → 클릭하여 후보·세부정보 탐색.

원본 관측·시각·순서는 보존한다. 개별 관측은 원본 목록에서 계속 탐색한다. 연결선은 묶기 전후 동일한 시간 흐름을 표현하며 이번 기능 때문에 공백 연결을 임의로 끊거나 실제 도로에 맞춰 경로를 추정하지 않는다. 원본 기반 목록·분포의 계산은 표시 묶음 수로 대체하지 않는다.

현재 앱 지원 입력인 rawSignals 위치 관측을 사용한다. semanticSegments·timelineObjects 지원 확대, 내보내기 형식 변경은 포함하지 않는다. 기존 크기·건수 한도를 유지한다.

## 관측 묶기

- 시간순으로 인접한 관측만 한 묶음으로 처리한다. 다른 곳을 거쳐 같은 장소에 돌아오면 별도 묶음이다.
- 한 점씩 가까운 것만 확인해 이동 구간 전체가 연쇄적으로 한 묶음이 되지 않도록 기준점 또는 묶음 범위를 제한한다.
- 묶음에는 원본 관측 ID 목록, 시작·종료 시각, 대표 좌표, 관측 수를 유지한다. 대표 좌표 변경·필터·지도 확대가 원본 기록이나 사용자 연결의 identity를 바꾸지 않도록 한다.
- 묶음 시간 범위는 관측 시작과 끝이며, 그 사이 내내 머물렀다는 확정 체류 시간이 아니다.
- 같은 지점이라도 인접 관측 공백이 120분을 넘으면 별도 묶음이다. 묶음을 분리하는 기준과 지도 연결선을 끊는 기준은 별개이며 긴 공백의 연결선은 유지한다.
- 비교 프리뷰의 100m·120분은 최초 실험값이었으며 이후 위 사용자 답변으로 이번 구현의 기본값으로 확정됐다.

## 데이터 계약과 모듈 경계

기존 파서·정규화 모델과 분리된 표시 계층으로 구현한다. 다음은 구현 계약의 초안이며 기존 ID 규칙과 맞춰 구체화한다.

| 객체 | 유지할 정보 | 의미 |
|---|---|---|
| ObservationGroup | groupId, sourceObservationIds, representativeCoordinate, startInstant, endInstant, observationCount | 화면에서 묶은 관측, 방문 확정 아님 |
| LandmarkCandidate | provider=geoapify, providerPlaceId, name, coordinate, categories, distanceMeters, attribution | API가 반환한 주변 후보 |
| LandmarkQueryState | groupId, requestGeneration, status, candidates, fetchedAt, fixedErrorCode | 미조회·조회 중·성공·빈 결과·실패 구별 |
| LandmarkAssociation | groupId, candidateId, confirmationState | 후보 표시와 사용자 선택을 구별하는 확장 연결 |

묶기 함수는 지도 라이브러리를 참조하지 않는다. Geoapify 어댑터는 요청 생성·응답 검증을 담당하고 화면은 정규화된 후보만 받는다. 원본 ID 목록과 위치 전체 경로는 API 요청 객체에 포함하지 않는다. 후보 이름은 HTML로 실행하지 않고 일반 텍스트로 표시한다.

## Geoapify 검색과 말풍선

- Places API, tourism.attraction / tourism.sights / entertainment.museum 범주, 300m 반경, 최대 10개, 거리 근접 우선으로 구현한다.
- 좌표 유효 범위·순서와 유효한 0 좌표를 검사한다. 비정상 응답·좌표·이름 누락은 안전하게 제외한다. `-` 등 의미 없는 이름은 확정 명소명처럼 제시하지 않는 표시 정책이 필요하다.
- 가까운 순서가 유명도나 방문 확률 순서는 아니다. 카테고리와 거리를 함께 보여주고 자동 방문 확정은 하지 않는다.
- 지도 말풍선 왼쪽에는 잘리지 않는 사진, 오른쪽에는 번호·최근접 장소명·N년 N월 N일 약 HH:mm:ss (UTC/KST)를 표시한다. 클릭하면 중앙 상세창에서 큰 사진·출처/저작자/라이선스·묶인 관측 수·시간 범위·후보 명칭/거리/종류/출처를 표시한다. 후보가 없으면 원래 위치 점만 유지한다.
- 사용자는 후보 버튼을 눌러 선택하거나 해제할 수 있다. 후보 선택은 해당 파일 세션의 화면 상태이며 사진의 방문 지정 기능과 별도다.
- 지도 이동·회전·확대 중 점·선·말풍선의 좌표계를 통일한다. 말풍선이 화면 밖으로 사라지거나 가까운 점을 가려 선택을 방해하지 않도록 한다.

## 개인정보·요청·오류

Geoapify 채택 결정은 실제 사용자 위치의 무조건적인 외부 전송 승인이 아니다. 위 최신 정책에 따라 파일별 동의를 거쳐 전체 지점을 자동 조회한다. 에이전트 검증에는 합성 자료만 사용하며 실제 파일은 사용자가 직접 선택한다.

- 전체 JSON, 날짜·시각, 기록 식별자, 파일명은 외부 검색에 보내지 않는다. 필요한 대표 좌표와 검색 조건만 요청에 사용하도록 설계한다.
- 브라우저 직접 요청을 사용한다. 브라우저 키는 비밀이 아니며 origin 제한이 필요하다. 별도 서버 프록시는 추가하지 않는다. 브라우저 개발자 도구에는 요청 좌표·공개 키가 보일 수 있지만 앱은 요청 URL·응답 원문을 로그로 출력하지 않는다.
- 키·원본 값·요청 URL·API 오류 원문을 Git, 콘솔, 분석 도구에 남기지 않는다. 오류는 고정 코드로 표현한다.
- 요청은 제한된 동시성·중복 제거·중단 기능을 제공한다. 지도 이동이나 재렌더마다 전체 묶음을 자동 조회하지 않는다. 401/403은 설정 오류, 429는 사용량 제한, 타임아웃·네트워크 실패는 재시도 가능한 실패로 구별하고 자동 무한 재시도하지 않는다.
- 파일 교체·기록 삭제·컴포넌트 종료 후 이전 요청 결과가 새 기록에 붙지 않도록 취소와 세대 구분을 사용한다. 묶기 기준 변경도 캐시 키와 요청 세대에 반영한다.
- 캐시는 해당 파일 세션의 메모리에만 유지하고 파일 제거 시 원본과 연결된 참조를 해제한다. 디스크·DB 저장은 추가하지 않는다. [공식 Places 안내](https://www.geoapify.com/places-api/)에서 캐시 허용과 Geoapify·OpenStreetMap 출처 표시 요구를 2026-10-07 확인했으며 UI에 출처 링크를 표시한다. 계정별 적용 약관·할당량은 실제 사용 전에 별도로 확인한다.
- API 실패와 빈 검색 결과를 구별한다. 어느 경우에도 위치 표시·기존 연결선·파일 탐색을 사용할 수 있어야 한다.
- 서비스별 최신 요금·할당량은 배포 전에 계정에서 확인한다. 과거 프리뷰의 32회 제한은 폐기했으며 무료 사용을 보장하지 않는다.

## 비교 테스트 기록

## 사진 처리 보강

- 사진 집계는 중복을 제외한 대표 장소 ID 기준으로 조회 중·표시 대기·표시 확인·없음·미지원·조회 실패·브라우저 로딩 실패·취소를 구분한다. 지도 밖 사진의 표시 대기는 실패가 아니다. 장소 검색도 일치·빈 결과·실패를 구분한다.
- 총 요청 수에는 Geoapify와 Wikidata/Commons 메타데이터 요청을 포함하며 Wikimedia 메타데이터 횟수를 별도로 표시한다. 브라우저 이미지 파일 다운로드 횟수는 이 API 요청 집계에 포함하지 않는다.
- 사용자의 기존 549개 지점 결과는 재검증하지 않았다. 공개 예제 파일과 공개 명소 Q243으로 실제 Wikidata P18→Commons Imageinfo의 이미지 주소·저작자·라이선스 반환을 확인했다. 실제 사진 화면 검증은 합성 이미지 응답으로 수행한다.
- Commons의 thumb.wikimedia.org 주소, 파일명 공백/밑줄 동치와 썸네일 참조를 지원한다. 임의 이미지 호스트는 계속 제외한다. 이미지가 없으면 다른 후보의 사진을 대표 장소의 사진처럼 붙이지 않는다.
- 근거: [MediaWiki Imageinfo](https://www.mediawiki.org/wiki/API:Imageinfo), [Wikibase API](https://www.mediawiki.org/wiki/Wikibase/API).

- 보강 검증: `npm run check`의 158개 테스트·타입 검사·빌드 통과. 개발/프로덕션 Edge smoke에서 Wikidata→Commons 참조 해석, 사진 렌더링, 로딩 실패 집계, 파일 교체·취소와 기존 앱 회귀 검증을 통과했다. 기존 MapLibre 대형 번들 경고는 유지된다.

## 사진 표시 대기 접근 보완

- 사진이 준비된 지점이 사진 없는 앞 지점과 같은 화면 셀에 있을 때 뒤 지점의 말풍선이 제외되던 문제를 보완한다. 같은 셀과 겹침 정리에서 사진이 있는 지점을 우선하며, 각 지점의 대표 랜드마크는 여전히 가장 가까운 후보로 유지한다.
- 장소 매핑에 ‘사진 있는 장소 보기’ 버튼을 제공한다. 사진을 찾은 서로 다른 대표 장소를 차례로 선택하고 지도를 이동하며, 상세 말풍선에 사진을 즉시 로드한다. 이미 받은 장소·사진 메타데이터를 재사용한다.
- ‘표시 확인’ 집계는 실제 화면 가시성을 보장하지 않으므로 ‘불러오기 성공’으로 명확히 한다. 지도 밖·겹침 처리·지연 로딩 때문에 사진 주소를 확보해도 표시 대기로 남을 수 있다.
- 사용자의 516개 기록 원본을 열람하지 않고 같은 좌표 재방문 합성 자료로 사진 없는 앞 지점과 사진 있는 뒤 지점의 표시 우선순위 및 상세 사진 접근을 검증한다.


## 등록 안내·경로 전환·조회 속도 보완 (2026-10-07)

- 현재 요청 흐름은 로컬 파싱 → 파일별 동의 안내 → 허용 시 전체 장소/사진 매핑이다. 거절·닫기는 외부 장소 요청을 시작하지 않는다.
- 동시 3건, 250ms 시작 간격은 Geoapify 공개 Free 요금제의 초당 5건 이내에서 응답 대기를 병행하기 위한 구현이다. 계정별 할당량은 별도이며 429에서 추가 조회를 중단한다. 근거: [Geoapify 요금제](https://www.geoapify.com/pricing/).
- 진행률은 장소 처리 80%, 고유 대표 장소의 사진 처리 20%로 계산한다. 사진 성공은 주소 확보이며 실제 사진 로딩 오류는 실패로 반영한다. 빈 결과와 사진 없음은 오류와 구분한다.
- 합성 지연 테스트에서 1초 조회 6건을 3초 이내에 처리하고 최대 동시 3건·최소 시작 간격 250ms, 정확히 동일 좌표의 별도 재방문 결과 공유, 전 요청 취소와 늦은 응답 차단을 검증한다. 이는 실제 네트워크의 속도 보장이 아니다.

- 보완 검증 결과: `npm run check` 통과(자동 테스트 160개·타입 검사·빌드). 개발/프로덕션 Edge 합성 smoke에서 등록 시 안내, 동의 전 요청 0건, 경로 전환, 중앙 상세창, 사진 contain 표시, 모바일 진행 표시 아래 말풍선, 오류·취소·파일 교체를 확인했다. 실제 사용자 파일의 속도와 사진 공급률은 사용자의 로컬 확인이 남아 있다. MapLibre 번들 크기 경고는 기존과 같이 남는다.

- 경로 보기 전환에서는 중심·확대 수준·회전·기울기를 유지한다. 전체 범위 맞춤은 새 파일 등록 또는 지도 재생성 때만 수행한다. 진행 원 안의 수치는 % 기호 없이 숫자만 표시하고 선 두께는 6px로 표시한다.
- 진행 원은 인라인 기준선 여백 없이 툴바 행의 수직 중앙에 배치하여 위아래 간격을 동일하게 유지한다.
