# Geoapify 랜드마크 연동

작성: 2026-10-07 (한국 시간)
상태: 기능 개발 명세. Geoapify 채택은 사용자 확정, 아래 미확정 정책은 구현 전에 결정한다. 현재 프로덕션에 제공되는 기능이라는 뜻은 아니다.

## 목적과 근거

Google Timeline의 연속된 근접 관측을 지도 표시용 지점으로 묶고, 주변 랜드마크 후보를 말풍선으로 탐색하게 한다. 여행의 주요 장소를 쉽게 찾되 관측 연결을 실제 이동 경로로, 가까운 명소를 실제 방문으로 오해하지 않게 한다.

- [현행 PRD](../docs/PRD.md), [상세 지도 명세](2026-10-06-005-detailed-map.md)
- [가상 여행 데이터](../docs/travel-demo.md), [비교 프리뷰와 검증 기록](../tools/landmark-preview/README.md)
- 사용자 확정: 입력 소스는 Google Timeline, 연속 근접 관측 묶기와 랜드마크 말풍선 개발, 랜드마크 API는 Geoapify.
- 지도 표시는 기존 MapLibre GL JS + MapTiler를 유지한다. 삼성 자료, 사진, 로그인, DB, 영구 저장, 실제 경로 예측은 이번 범위가 아니다.
- 사용자가 명소 이름을 나중에 알려줄 수 있으므로 합성 여행의 현재 좌표를 확정 랜드마크의 정확한 위치로 취급하지 않는다.

## 범위와 흐름

Timeline 선택 → 기존 로컬 파싱·시간순 정렬 → 표시용 관측 묶기 → 지도와 연결선 표시 → 승인된 방식으로 주변 후보 검색 → 말풍선에서 후보 탐색.

원본 관측·시각·순서는 보존한다. 묶기를 해제해 기존 관측 표시로 돌아갈 수 있게 설계한다. 연결선은 묶기 전후 동일한 시간 흐름을 표현하며 이번 기능 때문에 공백 연결을 임의로 끊거나 실제 도로에 맞춰 경로를 추정하지 않는다. 원본 기반 목록·분포의 계산은 표시 묶음 수로 대체하지 않는다.

현재 앱 지원 입력인 rawSignals 위치 관측을 사용한다. semanticSegments·timelineObjects 지원 확대, 내보내기 형식 변경은 포함하지 않는다. 기존 크기·건수 한도를 유지한다.

## 관측 묶기

- 시간순으로 인접한 관측만 한 묶음으로 처리한다. 다른 곳을 거쳐 같은 장소에 돌아오면 별도 묶음이다.
- 한 점씩 가까운 것만 확인해 이동 구간 전체가 연쇄적으로 한 묶음이 되지 않도록 기준점 또는 묶음 범위를 제한한다.
- 묶음에는 원본 관측 ID 목록, 시작·종료 시각, 대표 좌표, 관측 수를 유지한다. 대표 좌표 변경·필터·지도 확대가 원본 기록이나 사용자 연결의 identity를 바꾸지 않도록 한다.
- 묶음 시간 범위는 관측 시작과 끝이며, 그 사이 내내 머물렀다는 확정 체류 시간이 아니다.
- 같은 지점의 오랜 시간 공백을 한 방문으로 합치지 않는 기준은 미확정이다. 묶음을 분리하는 기준과 지도 연결선을 끊는 기준은 별개다.
- 비교 프리뷰의 첫 점 기준 100m·인접 시각 차이 120분은 실험값이다. 제품 기본값으로 자동 채택하지 않는다.

## 데이터 계약과 모듈 경계

기존 파서·정규화 모델과 분리된 표시 계층으로 구현한다. 다음은 구현 계약의 초안이며 기존 ID 규칙과 맞춰 구체화한다.

| 객체 | 유지할 정보 | 의미 |
|---|---|---|
| ObservationGroup | groupId, sourceObservationIds, representativeCoordinate, startInstant, endInstant, observationCount | 화면에서 묶은 관측, 방문 확정 아님 |
| LandmarkCandidate | provider=geoapify, providerPlaceId, name, coordinate, categories, distanceMeters, attribution | API가 반환한 주변 후보 |
| LandmarkQueryState | groupId, requestGeneration, status, candidates, fetchedAt, fixedErrorCode | 미조회·조회 중·성공·빈 결과·실패 구별 |
| LandmarkAssociation | groupId, candidateId, confirmationState | 후보 표시와 사용자 선택을 구별하는 확장 연결 |

묶기 함수는 지도 라이브러리를 참조하지 않는다. Geoapify 어댑터는 요청 생성·응답 검증을 담당하고 화면은 정규화된 후보만 받는다. 원본 ID 목록과 위치 전체 경로는 API 요청 객체에 포함하지 않는다. 후보 이름은 HTML로 실행하지 않고 일반 텍스트로 표시한다.

## Geoapify 검색과 말풍선

- 초기 검증 어댑터: Places API, tourism.attraction / tourism.sights / entertainment.museum 범주, 300m 반경, 최대 10개, 거리 근접 우선. 이 범주·반경·개수는 구현 시작값 제안이며 제품 기본값은 아래 결정 항목을 따른다.
- 좌표 유효 범위·순서와 유효한 0 좌표를 검사한다. 비정상 응답·좌표·이름 누락은 안전하게 제외한다. `-` 등 의미 없는 이름은 확정 명소명처럼 제시하지 않는 표시 정책이 필요하다.
- 가까운 순서가 유명도나 방문 확률 순서는 아니다. 카테고리와 거리를 함께 보여주고 자동 방문 확정은 하지 않는다.
- 말풍선에는 묶인 관측 수, 관측 시간 범위, 주변 후보 명칭·거리·종류, 제공자 출처를 표시한다. 후보가 없으면 해당 상태를 표시하고 원래 위치 점은 유지한다.
- 선택·해제 UX는 제안이다. 사용자가 다른 후보를 고르거나 연결하지 않을 수 있게 하는 방안을 구현 전에 확정한다. 사진의 방문 지정 기능은 이번 기능과 별도다.
- 지도 이동·회전·확대 중 점·선·말풍선의 좌표계를 통일한다. 말풍선이 화면 밖으로 사라지거나 가까운 점을 가려 선택을 방해하지 않도록 한다.

## 개인정보·요청·오류

Geoapify 채택 결정은 실제 사용자 위치의 무조건적인 외부 전송 승인이 아니다. 실제 자료의 검색 실행 시점, 사용자 안내·동의, 전송 좌표 단위, 요청 경유 방식은 미확정이다. 결정 전에는 합성 데이터와 모의 응답으로 개발·검증하고 실제 파일에 대한 외부 검색은 실행하지 않는다.

- 전체 JSON, 날짜·시각, 기록 식별자, 파일명은 외부 검색에 보내지 않는다. 필요한 대표 좌표와 검색 조건만 요청에 사용하도록 설계한다.
- 브라우저 직접 요청과 서버 경유 중 하나를 확정해야 한다. 브라우저 키는 비밀이 아니며 origin 제한이 필요하다. 서버 경유는 좌표를 우리 서버도 받으므로 기존 브라우저 내부 처리와 다른 데이터 흐름이다.
- 키·원본 값·요청 URL·API 오류 원문을 Git, 콘솔, 분석 도구에 남기지 않는다. 오류는 고정 코드로 표현한다.
- 요청은 제한된 동시성·중복 제거·중단 기능을 제공한다. 지도 이동이나 재렌더마다 전체 묶음을 자동 조회하지 않는다. 401/403은 설정 오류, 429는 사용량 제한, 타임아웃·네트워크 실패는 재시도 가능한 실패로 구별하고 자동 무한 재시도하지 않는다.
- 파일 교체·기록 삭제·컴포넌트 종료 후 이전 요청 결과가 새 기록에 붙지 않도록 취소와 세대 구분을 사용한다. 묶기 기준 변경도 캐시 키와 요청 세대에 반영한다.
- 캐시는 우선 메모리 내에서 설계하고 파일 제거 시 원본과 연결된 참조를 해제한다. 디스크·DB 저장은 승인하지 않는다. 보존·재사용 정책과 서비스 약관은 실제 적용 전에 확인한다.
- API 실패와 빈 검색 결과를 구별한다. 어느 경우에도 위치 표시·기존 연결선·파일 탐색을 사용할 수 있어야 한다.
- 서비스별 최신 요금·할당량은 배포 전에 계정에서 확인한다. 프리뷰의 32회 제한을 제품 예산이나 무료 보장으로 사용하지 않는다.

## 비교 테스트 기록

실행일: 2026-10-07. 기준 코드: `4939add`, 상세 결과 문서: `6555b08` 및 `32fb037`. localhost의 MapTiler / Geoapify 별도 빌드에서 완전 합성 자료만 사용했다. 프로덕션 배포는 하지 않았다. 키·허용 origin 설정 제약으로 localhost를 사용했으며 비용 초과가 확인된 것은 아니다.

### 자료와 방법

- 오스트리아: 비엔나 2023-08-03~10, 잘츠부르크 08-08 당일 왕복.
- 프랑스: 안시 2024-07-31~08-03, 샤모니 08-03~06.
- 이탈리아: 볼차노 2024-08-06~13, 밀라노 08-13~14. 프랑스 종료 지점에서 이어지는 가상 이동 포함.
- 일본: 후쿠오카·사가 2025-10-22~25, 구마모토 10-25~28, 후쿠오카 10-28~29.
- 이동 시간·경유점·관측 위치는 창작이며 실제 여행 복원이 아니다. 유럽 +02:00, 일본 +09:00 표현을 사용했다.
- 첫 점 기준 100m, 인접 시각 차이 120분 이내로 묶었다. 관측 시간 범위 10분 이상인 묶음에서 120m 이상 떨어진 지점을 최대 8개씩 선택했다. 최종 제품의 방문 판정 정책이 아니다.
- MapTiler: 일반 POI 역검색, 최대 10개 후 거리 300m 이내로 제한.
- Geoapify: 관광 명소·볼거리·박물관 범주, 반경 300m, 최대 10개.
- 같은 32개 좌표를 사용했지만 검색 범주·순위 방식은 다르다. 정확도 벤치마크나 국가 전체 품질 평가가 아니다.

| 가상 여행 | 원본 합성 관측 | 조회 지점 | MapTiler 후보 | Geoapify 후보 |
|---|---:|---:|---:|---:|
| 오스트리아 | 2,564 | 8 | 65 | 58 |
| 프랑스 | 1,839 | 8 | 64 | 46 |
| 이탈리아 | 2,715 | 8 | 69 | 58 |
| 일본 | 2,446 | 8 | 56 | 45 |

후보 합계는 지점 간 중복을 포함하며 방문 수·정답 수가 아니다. MapTiler의 일본은 프리뷰 7곳 49개와 같은 코드의 별도 단일 요청 1곳 7개를 합산했다. 앞선 인증 실패가 로컬 서버 32회 한도에 포함되어 마지막 1곳을 별도 검증했다. 서비스별 성공 요청은 32회이며 초기 인증 실패는 Geoapify 2회, MapTiler 1회다. 최종 일본 화면의 PREVIEW_CAP은 제공자 할당량 초과가 아니라 로컬 한도였다.

### 관찰과 결정

MapTiler는 식당·상점·병원·편의점·역과 의미 없는 이름도 반환했다. Geoapify는 관광 범주를 제한하기 쉬웠지만 작은 기념비·흉상·계절 행사도 반환했다. 일본의 10월 합성 여행 지점에 크리스마스 마켓이 검색됐으며, 현재 POI 데이터가 여행 당시 명소였음을 보장할 수 없다. 어느 API도 근접만으로 방문을 확정하지 않는다.

2026-10-07 사용자가 **Geoapify를 랜드마크 검색 제공자로 채택**했다. MapTiler 일반 POI 검색을 함께 구현·유지하는 것은 이번 제품 범위에서 제외하며 비교 프리뷰는 근거 자료로 보존한다.

기 수행 검증: 타입 검사, 자동 테스트 131개, 두 프리뷰 빌드, 두 화면 × 네 여행의 모의 응답·말풍선, 실제 API 성공, 캐시 재조회, localhost의 키·개인 자료 경로 차단. 기존 앱 회귀 빌드 통과, MapLibre 번들 크기 경고 잔존. 이 결과는 새 기능의 구현 완료·실제 파일 호환성·명소 정확도 검증이 아니다.

## 개발 순서와 완료 기준

1. 묶기 거리·시간 기준, 후보 표시/선택, 외부 요청 정책을 확정하고 이 문서에 기록한다.
2. 순수 묶기 로직과 후보 모델·Geoapify 어댑터를 합성 테스트로 구현한다.
3. 기존 지도에 묶음·연결선·후보 말풍선을 통합하고 모의 응답으로 검증한다.
4. 확정한 개인정보 안내·요청 제한·취소·실패 처리를 적용한다.
5. 합성 네 여행으로 프리뷰에서 검증한다. 실제 기록은 사용자가 로컬에서 선택하며 승인된 요청 정책 범위만 적용한다.
6. 전체 목표 완료 후 PR을 생성·검토한다. 병합·배포·브랜치 정리는 별도 승인 범위에서 진행한다.

검증 체크리스트:

- [ ] 근접 연속 관측, 경계 거리, 경유 후 재방문, 긴 공백, 0 좌표, 동일 시각의 결정적 처리
- [ ] 원본 관측 보존, 시간 순서·ID·목록·분포 유지, 필터·기준 변경 시 잘못된 연결 방지
- [ ] 후보 없음·중복·다국어·의미 없는 이름·비정상 좌표·악성 HTML 문자열의 안전한 처리
- [ ] 인증 실패·사용량 제한·오프라인·느린 응답·파일 교체·취소·중복 요청 처리
- [ ] 회전·확대·줌 한계·촘촘한 위치·반응형 화면에서 점·선·말풍선 정렬과 선택 가능
- [ ] 사용자 승인 없는 좌표 전송 0건, 로그·키 노출 0건, 파일 삭제 후 참조 정리
- [ ] 최신 계정 할당량·약관·출처 표시 확인 및 test/typecheck/build 통과

## 구현 전에 남은 결정

- 묶기 거리의 기본값·사용자 조정 가능 여부, 대표 좌표 선택, 긴 관측 공백의 묶음 구분.
- 자동 후보 말풍선 표시 범위, 사용자 후보 선택·해제 방식, 기념비·예술품·계절 행사 포함 범위.
- 실제 좌표 외부 조회의 동의·안내·실행 시점, 브라우저 직접 요청 또는 서버 경유.
- 조회 반경·개수·동시성·총량·캐시 수명과 재시도 기준.

이 결정이 없어도 합성 데이터 기반 로직과 화면 개발은 가능하다. 실제 기록의 외부 조회와 프로덕션 통합 완료 판단은 결정 전 보류한다.
