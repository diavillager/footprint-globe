# Timeline·GPX 기간 선택 등록과 대표 경로

상태: 2026-10-08 사용자가 새 명세 작성·구현, 단일 파일 교체, UTC/KST 선택, Timeline 두 출처의 보완 구조를 승인했다. `codex/landmark-footprints`에서 진행한다. 배포·병합·실제 원본 읽기는 범위 밖이다.

## 등록 흐름

파일 하나 선택(JSON/GPX) → 로컬 분석 → 전체 유효 기록 범위와 날짜별 건수를 달력에 표시 → 시작/종료 날짜 선택 → 원본만 보기 또는 허용하고 장소 매핑 → 선택 기간의 대표 경로 표시.

- 분석 결과는 등록 대기 상태에 보관한다. 확정 전 점·선·지도 자동 이동·장소 검색을 하지 않는다. 배경 지도는 기존대로 유지한다. 취소/닫기는 해당 등록을 폐기한다. 새 파일을 고르면 기존 기록·매핑 결과를 교체한다.
- 날짜 기준은 등록 창의 UTC/KST이고 최초에는 현재 표시 시간대를 따른다. 시간대 변경 시 선택을 초기화해 날짜 의미가 몰래 달라지지 않게 한다. 시작·종료일 모두 포함한다. 달력 클릭과 날짜 입력, 전체 기간 선택을 제공한다. 기록이 없는 기간은 등록할 수 없다.
- 등록 뒤 상단 UTC/KST는 표시만 바꾼다. 선택 기간과 날짜별 경계는 등록 때의 기준으로 고정한다. 다른 기간은 기간 다시 선택으로 재등록하며 매핑 재동의를 받는다.
- 원본 파일의 지원하는 유효 좌표·시각 기록 전체 범위와 선택 기간 건수를 명시한다. 날짜 경계는 연결·묶기 경계이며 원본을 수정하거나 일별 파일로 영구 저장하지 않는다.

## 입력과 원본 보존

- 한 번에 한 파일, 최대 64 MiB. 기존 rawSignals 및 semanticSegments의 timelinePath(point + ISO time 또는 startTime 기준 durationMinutesOffset)를 지원한다. 둘이 함께 있어도 각 출처를 별도로 보존한다. 상대 시각은 명시된 시작 시각/오프셋으로만 계산하고 누락 시각을 추정하지 않는다.
- GPX 1.0/1.1은 진단 도구의 namespace·좌표·시각 검증을 공유한다. 유효한 시각을 가진 트랙점/루트점/웨이포인트를 읽고 트랙 구간·루트 경계를 보존한다. 시각 없는 점은 경로 관측으로 쓰지 않는다. 부적합 점의 양옆, 역순, 웨이포인트끼리는 자동 연결하지 않는다. HDOP를 정확도로 변환하지 않는다.
- 관측/경로점 합계 100,000개까지 지원하며 초과는 명시적으로 중단한다. metadata 값·파일명·오류 원문은 로그/채팅에 출력하지 않는다. 무효 좌표·시각 건수와 미지원 기록을 집계한다. 원본 rawSignals 관측, 상세 경로 관측, 기록된 방문과 대표 경로는 구별한다.
- GPX와 Timeline을 동시에 표시하거나 데이터 간 오차 비교를 수행하지 않는다. KML·timelineObjects 등 기존 레거시 형식의 앱 입력은 범위 밖이다.

## 대표 경로

- 상세 경로의 신뢰 가능한 인접 두 점 사이 시간 구간에 상세 경로를 우선하고, 이 구간 밖의 원시 관측으로 보완한다. 시간 범위가 겹치는 두 상세 구간은 임의 우승자를 정하지 않고 해당 충돌 구간을 제외한 원시 관측으로 fallback한다. 원시 관측이 없다면 충돌한 상세 점은 고립 기록으로 유지하고 연결을 만들지 않는다.
- 원시 관측을 원본에서 삭제하지 않는다. 출처별 원본 기록을 목록에서 확인할 수 있고 대표 경로에는 출처를 보존한다. 방문 대표 좌표로 우회선을 만들지 않는다.
- 무효 점·역순·30분 초과 공백은 상세 경로의 지원 구간으로 간주하지 않는다. 날짜/원본 구간 경계·동일 시각 충돌·숨긴 점 양옆을 넘겨 연결하지 않는다. 원시 관측 fallback도 원래 인접 관계를 확인한다.
- 서로 다른 출처의 연결은 시간·거리·연속성을 검사한다. 사용자가 2026-10-08 확정한 기준은 간격 5분 이내·거리 200m 이내·속도 300km/h 이하이며 시간 역순은 연결하지 않는다. 동일 시각은 좌표가 같을 때만 연결 가능하다. 숨긴 점을 넘는 출처 전환도 차단한다.
- 오류 의심 검사는 기존 합의 기준을 사용한다. 출처/구간을 건너 오류 의심의 앞뒤 문맥을 합성하지 않는다. 날짜 선택과 오류 숨김 뒤 대표 경로 및 장소 매핑 대상을 함께 갱신한다. 제외된 원시 관측이 상세 경로 우선 구간에 다시 끼어들지 않게 한다.
- 화면 경로는 대표 경로 하나다. 상세 경로 우선은 표시 정책이며 정확성 보증이 아니다. 기존 ‘원본 경로’ 버튼은 혼합 출처일 때 ‘기록 경로’로 명확히 표시하고 원본 전체는 위치 기록에서 확인한다. 장소별 보기/번호 띠는 선택 기간의 대표 경로만 매핑한 결과를 사용한다.

## 검증과 한계

합성 raw-only·semantic-only·혼합·GPX, 월/윤년/UTC-KST/자정 소수초 경계, 중복 구간·내부 무효/공백·전환 연결·원본 보존·날짜 분리·취소/교체·미허용 상태의 지도/조회 차단·원본만 보기·선택 기간 매핑을 검증한다. 3개월 기록과 1시간 미만 GPX를 합성한다. 모의 지도/장소 API로 브라우저 검증하며 실제 원본을 사용하지 않는다.

GPX 확장 정확도, 모든 Timeline 변형, 방문 사실의 진위, 실제 도로 복원은 보장하지 않는다. 전체 원본 텍스트를 저장하지 않으며 정규화된 지원 기록과 세션 상태만 메모리에 유지한다. 기존 [GPX 진단](2026-10-08-000-gpx-local-audit.md)과 [위치 검사](2026-10-07-001-location-quality.md) 명세의 제한은 별도 변경이 없는 한 유지한다.

## 2026-10-08 GPX 공백 점선 표시 보완

사용자는 지하철 등으로 GPS 기록이 비는 구간에서도 다음 지점을 찾을 수 있도록 점선 표시를 요청했다. 기존 연결 중단은 실선·장소 묶기 정책으로 유지하고 별도 표시용 `gapConnections`를 제공한다.

- GPX의 원래 인접한 유효 점 사이 30분 초과 공백, 같은 트랙의 연속 구간 경계를 점선으로 잇는다. 기본 표시하며 실제 지하철 탑승·GPS 단절 원인을 자동 확정하지 않는다.
- 같은 등록 날짜 안에서 시간 순서가 맞을 때만 표시한다. 다른 트랙/루트, 웨이포인트, 역순·동일 시각, 무효 기록이나 숨긴 기록을 건너는 연결, 시각 충돌, 날짜 경계에는 점선을 만들지 않는다. Timeline의 경계 정책은 바꾸지 않는다.
- 색상 `#087e78`, 두께 3px, 불투명도와 기하 생성은 해당 보기의 실선과 같고 점선 패턴 `[2,2]`만 다르다. 장소별 보기에서는 표시용 통합 지점에 끝점을 맞추며 선택 강조도 기존 색상·두께를 따르고 점선을 유지한다.
- 원본/실선 연결/매핑용 경계를 수정하지 않는다. 점선 위에 새 관측·방문·장소 조회 대상을 생성하거나 그룹을 합치지 않는다. 지도 요약에 공백 연결 건수와 점선을 안내하고 이용 안내에서 실제 이동 경로가 아니라는 의미를 설명한다.
- 합성 GPX로 긴 공백·동일 트랙 구간·날짜 경계·별도 트랙·무효/숨김/역순/충돌·웨이포인트와 장소별 보기의 끝점 보존을 검증한다. 실제 GPX는 읽지 않는다.
