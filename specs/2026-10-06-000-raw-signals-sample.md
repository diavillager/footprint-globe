# rawSignals 로컬 샘플 지원

상태: 2026-10-06 사용자 승인 범위를 구체화한 구현 명세.

## 목적과 근거

사용자가 공유한 비식별 진단에는 최상위 `rawSignals` 배열이 있지만 기존 방문·이동 배열은 확인되지 않았다. 실제 원본은 읽지 않는다. 사용자는 원시 기록만 가상화하고 방문·경로를 추론하지 않는 지원 추가 및 spec 작성에 동의했다.

기존 도구의 로컬 처리, 허용 목록, 형식 보존, 별도 다운로드, Git 제외 원칙을 유지한다. 이 명세는 앱에서 원시 좌표를 방문지로 해석하는 정책을 정하지 않는다.

## 입력과 선택

- 최상위 객체에 `semanticSegments`와 `timelineObjects`가 없고 `rawSignals`가 배열일 때 원시 기록 모드를 사용한다.
- 기존 방문·이동 형식이 함께 있으면 기존 선택 규칙대로 처리하고 `rawSignals`는 제외한다. 기존 형식 검증 실패를 원시 기록으로 자동 우회하지 않는다.
- `rawSignals` 외의 최상위 필드(사용자 프로필 포함)는 기존 규칙대로 통째로 제외하고 건수만 알린다.
- 원시 모드의 채택 대상은 `{ position: { ... } }`이다. `position`에는 `LatLng` 또는 `latLng` 중 정확히 하나와 ISO 8601 `timestamp`가 필수다.
- 허용 보조 필드는 숫자 `accuracyMeters`, `altitudeMeters`, `speedMetersPerSecond`와 문자열 `source`다. 알 수 없는 필드·잘못된 자료형·좌표·시간이 있으면 기록 전체를 제외한다.
- `wifiScan`, `activityRecord` 등 위치 관측값 외의 신호는 기록 전체를 제외한다. 위치와 다른 신호가 한 기록에 함께 있으면 역시 제외한다. Wi-Fi MAC, SSID, 기기 식별자를 복사하거나 의미를 추론하지 않는다.

## 치환과 출력

- 최상위 `rawSignals`와 채택한 기록의 키 이름·대소문자·중첩·자료형을 유지한다. `LatLng`를 `latLng`로 이름 변경하지 않는다.
- 좌표는 기존 가상 좌표 매핑을 사용한다. 반복 좌표는 같은 가상 지점으로 연결한다. 실제 모양·거리·방향은 보존하지 않는다.
- 모든 채택된 `timestamp`에 공통 초 단위 이동을 적용한다. 시간차·정밀도·입력 순서를 유지하고 오프셋은 UTC로 바꾼다.
- 보조 숫자는 0, `source`는 `UNKNOWN`으로 치환한다. 원본 수치나 출처 문자열을 통과시키지 않는다.
- 검증된 위치 관측값이 하나 이상이면 샘플 생성이 가능하다. 이 조건 완화는 원시 기록 모드에만 적용한다. 기존 모드는 방문과 이동이 모두 필요하다.
- 최대 9개 위치 관측값을 입력 순서로 선택한다. 방문지·경로·활동 레코드를 생성하지 않는다. 방문/이동/상세 경로 건수는 0이며 별도 원시 위치 건수를 표시한다.
- 출력은 원본과 별개의 JSON이다. 64 MiB 입력, 100,000개 기록, 64 KiB 출력 한도는 유지한다.
- 위치 관측값이 없거나 모두 제외되면 `NO_SAFE_RAW_POSITION`으로 중단하고 제한된 구조 진단을 제공한다. 원본 값·임의 필드명·파일명·오류 원문은 출력하지 않는다.

## 사용자 안내와 한계

원시 위치 샘플임을 명시하고, 방문 정보와 확정 경로를 포함하지 않는다고 알린다. GPS 관측 순서가 곧 실제 이동 경로라는 의미는 아니다. 시간 간격과 반복 위치 관계는 남는다. 생성 성공은 실제 원본의 앱 호환성이나 모든 rawSignals 버전의 지원을 뜻하지 않는다.

## 검증 기준

완전 합성 데이터로 대소문자 좌표 키, 가상화, 반복 관계, 시간차·정밀도, 구조·자료형 보존, 원본 객체 불변성, 보조 필드 치환, Wi-Fi/활동/미지원 신호 제외, 위치 없는 입력, 잘못된 좌표·시각, 모호한 좌표 키, 입력·출력 한도, 기존 세 형식의 회귀를 확인한다. 브라우저에서 파일 선택·다운로드·안전한 오류와 외부 요청 0건을 확인한다.

실제 원본 선택과 호환성 확인은 사용자가 로컬 도구에서 수행한다.

## 형식 참고

### 2026-10-08 전체 구조 진단 보완

대용량 원본에서 사용자가 누락을 일일이 찾지 않도록 별도 로컬 진단 도구를 추가한다. 기존 샘플의 지원 형식·치환·제외 정책은 바꾸지 않는다. 앱의 지원 형식이나 위치 오류 탐지 정책을 확대하는 변경도 아니다.

- 사용자가 선택한 최대 64 MiB JSON을 로컬 Worker에서 처리하고, 파싱된 트리의 전체 항목을 순회한다. 기존 진단의 노드·깊이 제한이나 배열 표본 탐색을 적용하지 않는다.
- 앱 파서와 같은 함수를 재사용하여 실제 채택/제외/실패를 집계하고, 별도 구조 탐색에서 알려진 형태와 미해석 필드를 표시한다. 앱 파서의 기존 100,000개 기록 제한은 유지한다.
- 원본 값·파일명·임의 필드명·오류 원문은 출력하지 않는다. 고정 스키마 이름 이외의 키는 별칭으로 바꾸고 대응표를 공유하지 않는다. 외부 요청·영구 저장을 추가하지 않는다.
- 상세 보고서만 1,200개 경로·1,200개 별칭·표시 깊이 16으로 제한하며 생략 건수를 밝힌다. 탐색 완료와 해석 완료를 구별한다. 취소·실패는 미완료이며 남은 건수를 추정하지 않는다.
- 문자열 내부 JSON과 압축 표현은 해석하지 않는다. 표준 JSON 파싱의 중복 키 마지막 값 유지 한계를 밝힌다. GPX/KML 비교와 실제 GPS 오류 판정은 범위 밖이다.
- 합성 데이터로 대규모·깊은 구조·배열 끝의 변형·미지원 루트·실제 파서 건수 일치·원본 불변성·안전한 별칭과 출력·브라우저 취소/교체/다운로드·외부 요청 및 저장소 미사용을 검증한다.

사용 절차와 구현 한도는 [전체 구조 진단 안내](../tools/timeline-audit/README.md)를 따른다. 사용자의 실제 파일 보고서는 후속 파서 보완의 근거이며, 아직 확인되지 않은 입력의 호환성을 완료로 선언하지 않는다.
