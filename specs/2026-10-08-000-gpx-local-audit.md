# GPX 로컬 구조·비교 준비 진단

상태: 2026-10-08 사용자가 명세 작성과 구현을 승인했다. 기존 JSON 진단 화면에 통합하며 현재 `codex/landmark-footprints` 브랜치를 유지한다. 실제 파일 접근·지도 앱의 GPX 지원·배포·병합 승인은 아니다.

## 목적과 범위

GPS Logger GPX와 Timeline을 비교하기 전에, 사용자가 방대한 원본에서 필드를 직접 찾지 않고 기록 구조와 좌표·시각의 사용 가능 범위를 확인한다. [기존 로컬 진단](2026-10-06-000-raw-signals-sample.md)의 메모리 처리·값 없는 보고서 원칙과 [위치 검사](2026-10-07-001-location-quality.md)의 원본 보존 원칙을 따른다.

- 기존 `tools/timeline-audit` 화면에서 JSON 또는 GPX 하나를 선택한다. 파서와 보고서는 형식별로 분리하고 선택·취소·교체·지우기·저장 동작을 공유한다.
- JSON 진단, 앱 파서의 혼합 Timeline 거부, 위치 오류 판정·매핑 대상은 변경하지 않는다.
- GPX는 구조 진단만 한다. 실제 지도 표시, GPX/Timeline 시간 대응·거리 비교, GPX를 정답으로 삼는 오류 제거, KML 지원은 후속 범위다.

## 입력과 출력

- 최대 64 MiB, UTF-8 XML(선택적 BOM). GPX 1.0/1.1의 표준 namespace와 일치하는 version을 확인한다. namespace 없는 XML·불일치·다른 XML은 구조만 탐색하고 지원 GPX로 판정하지 않는다. UTF-16/기타 선언은 고정 오류로 중단한다.
- Worker 안에서 namespace-aware SAX 파서를 사용해 전체 요소·속성을 순회한다. 배열 표본이나 깊이/요소 수 탐색 상한을 두지 않는다. 메모리/파싱 실패·취소는 미완료다. 64 MiB 파일 한도는 유지한다.
- `trk/trkseg/trkpt`, `rte/rtept`, `wpt`의 구분과 구간 경계를 보존한다. 표준 namespace의 정확한 경로에 있는 요소만 기록으로 집계한다. 같은 이름의 확장 요소는 관측으로 오인하지 않는다.
- 좌표 속성의 존재·숫자 문법·범위, 시각의 존재·유효성·시간대 누락, 중복 time 요소, 좌표와 시각을 모두 갖춘 점을 유형별로 집계한다. 유효한 0 좌표를 누락으로 취급하지 않는다.
- 원본 순서에서 같은 트랙 구간/루트의 바로 인접한 유효 점만 시간 비교한다. 잘못되거나 시각 없는 점과 구간 경계를 건너 비교하지 않는다. 동일 시각·역순과 양의 간격 구간(1초 이하, 5초 이하, 30초 이하, 60초 이하, 5분 이하, 5분 초과), 그중 30분 초과 공백 건수를 보고한다. 이는 집계용이며 새 연결/제외 정책이 아니다.
- 고도·측위 상태·위성 수·HDOP/VDOP/PDOP와 GPX 1.0 speed의 존재/유효·불량을 집계한다. HDOP를 미터 정확도로 환산하지 않는다. 확장 요소의 의미·단위는 추정하지 않고 구조만 표시한다.
- 출력 `gpx-structure-report.txt`는 고정 라벨·별칭·집계만 포함한다. 원본 파일명·좌표·날짜/시각·표고·속도·namespace URI·작성 앱/기기·트랙명·메타데이터·임의 요소/속성명·오류 원문을 출력하지 않는다. URI+localName으로 이름을 구별한 뒤 파일 내 별칭으로 치환하고 대응표는 공유하지 않는다.
- 상세 목록 1,200개 경로·별칭, 표시 경로 깊이 16을 한도로 두고 상세 생략 건수를 밝힌다. 탐색 완료는 XML의 모든 의미 해석이나 XSD 전체 검증 완료를 뜻하지 않는다.

## 보안·예외·수명

원본을 읽는 것은 사용자가 선택한 브라우저 Worker에 한정한다. 외부 요청·영구 저장·자동 전송은 없다. DTD/사용자 정의 엔터티는 거부하며 외부 스키마·스타일시트·링크를 가져오지 않는다. XML 오류 원문은 버리고 고정 오류 코드만 노출한다. 손상 XML을 자동 복구하지 않는다. GPX 1.1의 일반적인 시각을 검사하되 시간대 없는 시각·윤초 등 지원하지 않는 표현을 임의 보정하지 않는다.

작업 종료/교체/취소 시 Worker를 종료한다. UI에는 집계 보고서만 남고 지우기·새로고침·탭 종료 시 제거한다. 사용자가 저장한 보고서는 별도 파일이다. 구조·건수 자체의 정보가 남으므로 완전한 익명성을 주장하지 않는다.

## 검증

완전 합성 GPX로 1.0/1.1·기본/접두 namespace·확장 namespace·트랙/루트/웨이포인트·다중 구간·빈 파일·0 좌표·범위/시간대/시각 이상·같은 시각/역순/긴 공백·선택적 품질 필드·깊은/대용량 구조·상세 한도·손상 XML·DTD/엔터티·값/이름 canary 비출력을 검증한다. 브라우저에서 파일 선택·다운로드·취소·교체·고정 오류·JSON 회귀·외부 요청 및 저장소 미사용을 확인한다. 실제 GPX는 사용자가 로컬로 검사한 보고서로만 후속 확인한다.

## 참고와 미확정 사항

- [GPX 1.1 공식 명세](https://www.topografix.com/GPX/1/1/), [GPX 1.0 XSD](https://www.topografix.com/GPX/1/0/gpx.xsd).
- [saxes](https://github.com/lddubeau/saxes): namespace-aware XML 구문 파싱에 사용한다. XSD 전체 유효성 검증기는 아니며 DTD는 이 도구에서 거부한다.
- GPS Logger가 내보낸 실제 확장 namespace/필드와 시각 커버리지는 아직 미확인이다. 그 의미와 실제 두 데이터의 시간 대응 기준은 보고서 확인 후 결정한다.

## 구현·검증 결과

- 기존 JSON 진단 화면에 파일 선택과 보고서 수명을 통합하고 GPX의 파서·집계·텍스트 보고서를 별도 모듈로 구현했다. `gpx-structure-report.txt`로 다운로드한다. 표준 scalar의 텍스트가 256자를 넘거나 자식 요소가 있으면 불량/미지원으로 집계하고 구조 탐색은 계속한다.
- `npm test`: Node 66개, Vitest 183개(신규 GPX 15개 포함) 통과. 마지막 보고서 문구/읽기 오류 보완 후 진단 테스트 26개와 typecheck를 재검증했다.
- `npm run audit:build`와 별도 출력 디렉터리의 지도 앱 빌드 성공. 기존 MapLibre 번들 500 kB 경고는 남아 있다. 기존 지도 미리보기의 dist는 갱신하지 않았다.
- `node tests/structure-audit-smoke.cjs`: 합성 JSON/GPX의 선택·보고서 다운로드·취소·교체·잘못된 XML·DTD·인코딩·모바일/데스크톱 화면을 확인했다. 페이지 오류·외부 요청 0건, localStorage/sessionStorage/IndexedDB 비사용 확인.
- 실제 원본이나 공유받은 구조 보고서를 fixture로 저장하지 않았다. 실제 GPX 호환성과 두 기록의 비교는 사용자의 로컬 보고서 확인이 남아 있다. 배포·원격 푸시·병합은 하지 않는다.
