# 확대 단계별 국가·지역·도시 지도

상태: 2026-10-06 사용자 요청과 작성 승인에 따른 조사·설계 초안. 상세 지도 요구사항은 확정됐으나 서비스 선정, 비용, 외부 요청, 렌더러 변경은 아직 승인되지 않았다. 이 문서 작성은 외부 지도 연결 구현 승인이 아니다.

## 목적과 관련 요구사항

[PRD](../docs/PRD.md)와 [화면 개발 명세](2026-10-06-004-globe-ui.md)의 지구본 탐색에 전 세계 국가·지역·도시 이름과 상세 경계를 확대 단계별로 표시한다. 사용자는 주요 도시 이름만 있는 오프라인 개략 지도보다 상세 지도를 요구했으며 외부 지도 서비스 검토를 허용했다.

현재 앱의 배경은 `src/assets/land.ts`의 개략 육지 윤곽이다. 관측과 연결은 Three.js의 별도 표시 층에 그린다. 현재 구현에 국가·행정구역 경계 및 도시 이름이 있다고 안내하지 않는다.

## 확정 범위와 미확정 범위

- 확정: 전 세계를 대상으로 국가·지역·도시의 이름과 경계를 확대 단계별 표시. 원본 관측·실제 기록 경로·추정 연결·방문 ID는 지도 자료와 분리한다.
- 미확정: 지도 서비스/요금제, 외부 요청 허용, 자료의 갱신·캐시, 언어 fallback, 경계 관점, 도시 경계의 행정 단계별 수용 기준, 렌더러 교체 여부.
- 사진은 사용자 결정으로 MVP에서 제외하고 추후 확장으로 옮겼다. 지도 도입을 Timeline 업로드나 좌표 기반 검색 허가로 확대하지 않는다.
- 도시 이름(점 라벨)과 도시 행정 경계(선/면)는 별도다. 이름이 보인다는 사실로 도시 경계를 충족했다고 판정하지 않는다.

## MapTiler·Google Maps 비교 보강 — 사용자 요청

해외 여행 기록을 포함해 전 세계 지도를 표시하는 것을 평가 기준으로 삼는다. 지도 이름/도로의 배경 표시, 직접 스타일을 제어할 수 있는 행정 경계, 사진처럼 표현되는 3D 지형은 서로 다른 기능이다. 전 세계 배경 지원이 모든 도시 경계의 완전성을 뜻하지 않는다.

Google API의 정식 이용은 API 키와 결제 계정 설정을 요구하며, 일반 소비자용 Google 지도 앱이 무료라는 사실과 구별한다. 지도 로드와 추가 Places·검색·경로 API는 별도 과금 항목이다. 지도만 쓰는 낮은 사용량에서는 Google도 비용 0이 가능하므로 Google이 항상 더 비싸다고 결론 내리지 않는다. [Google Usage and Billing](https://developers.google.com/maps/documentation/javascript/usage-and-billing)

### 해외 지도와 상세 경계

MapTiler Planet은 전 세계 지도를 제공하고 국가·지역·도시 이름과 행정 경계용 벡터 레이어를 문서화한다. SDK는 globe projection도 지원한다. 이는 지구본과 확대별 경계 스타일을 함께 설계할 수 있다는 근거다. 다만 한국과 해외 도시의 세부 경계 누락률은 아직 실제 타일로 확인하지 않았다. [전 세계 자료](https://www.maptiler.com/planet/), [스키마](https://docs.maptiler.com/schema/planet/), [지구본 지원](https://www.maptiler.com/news/2025/01/3d-globe-maps-using-a-javascript-sdk/)

### 현재 코드와 연결하는 방법

- MapTiler: 현재 지구본에 래스터 타일을 추가하는 방식은 관측 코드 재사용에 유리하다. 그러나 상세 경계의 단계별 스타일·라벨 충돌 제어가 중요하면 MapTiler SDK/MapLibre 계열 벡터 렌더러로 옮기는 편을 평가해야 한다. 파서·ID·시간대 로직은 유지 가능하지만 표시·클릭·근접 정밀도는 다시 검증한다. 이식 비용은 코드 구조에 따른 판단이며 성능 실측 결과가 아니다.
- Google 배경을 현재 지구본에 표시: 공식 Map Tiles API의 2D 타일을 사용하는 후보가 있다. API 키·세션 토큰·동적 출처 표시를 구현해야 하고 지도 이미지에서 도시 경계를 별도 데이터로 추출할 수 있다고 가정하지 않는다. 비공식 Google 타일 URL을 사용하지 않는다. [Tiles API](https://developers.google.com/maps/documentation/tile/overview), [출처·캐시 정책](https://developers.google.com/maps/documentation/tile/policies)
- Google 렌더러로 전환: Maps JavaScript의 기본 지도 또는 별도 3D Maps에서 마커·선을 표시할 수 있다. 3D Maps는 사진 기반 3D 환경에 적합하지만, 2D DDS 경계 기능을 같은 3D 화면에 그대로 적용할 수 있는지는 확인되지 않았다. 현재 Three.js 렌더링을 교체하는 검증이 필요하다. [3D Maps 기능](https://developers.google.com/maps/documentation/javascript/3d/overview)

### 평가 결론과 결정 대기

**권고는 MapTiler를 우선 검증 후보로 유지하는 것이다.** 개인용 시험의 카드 없는 무료 시작, 지구본 지원, 벡터 경계·이름 스타일링이 이 프로젝트와 맞는다. 다만 모든 해외 도시와 한국 상세 경계를 충족한다고 아직 보장할 수 없으므로 서비스 확정은 아니다.

Google은 익숙한 배경 지도나 사진 기반 3D가 우선이면 유효한 후보이며 무료 사용량도 있다. 그러나 현재 요구사항인 직접 제어 가능한 한국·해외 도시 경계를 한 방식으로 제공하려면 한국 DDS의 명시적 공백을 해결해야 한다. 양쪽 모두 실제 기록 기반 외부 지도 요청을 사용하면 열람 지역이 드러날 수 있다는 전송 검토는 남는다.

사용자는 이번 비교를 확인한 뒤 도입을 결정하기로 했다. MapTiler PoC 승인 질문에 대한 답변을 추측하지 않으며, 현재는 계정 생성·결제·지도 연결·패키지 교체를 하지 않는다. 이후 승인되면 실제 여행 기록과 무관하게 서울·도쿄·뉴욕·파리·런던의 이름과 도시 경계 및 날짜변경선 전환을 검증한다. 이는 공개 검증 지역 제안이며 실제 사용자 여행지를 추정한 것이 아니다.

## 제안하는 검증 순서 — 채택 전

1. MapTiler를 첫 평가 후보로 제안한다. 무료 개인/PoC 조건으로 이름과 경계의 실제 커버리지를 확인할 수 있는지 먼저 검증하고, 충족하지 못하면 Google의 지도·경계 지원 범위와 대체 경계 자료를 비교한다. 추가 후보인 Mapbox Boundaries는 비용·접근 조건을 별도 확인한다. 계정 생성, 가입, 결제, 공급자 문의는 자동 수행하지 않는다.
2. 현재 react-globe.gl의 타일 배경 유지와 벡터 렌더러 도입을 비교한다. 전자는 관측 코드를 보존하지만 래스터 라벨 크기·경계 스타일의 제약이 있고, 후자는 확대별 라벨 충돌 처리를 활용할 수 있지만 관측·경로 렌더링의 이식 검증이 필요하다. 기존 Three.js 객체를 그대로 새 렌더러에 넣을 수 있다고 가정하지 않는다. Mapbox 공식 문서는 globe의 custom layer 제약을 명시한다.
3. 서비스 및 합성 화면의 외부 요청 승인 후, 직접 정한 공개 검증 지역으로 PoC를 만든다. 실제 Timeline은 사용하지 않는다. 키는 저장소에 넣지 않고 개발 환경에서 주입한다.
4. 합성 검증 결과, 도시 경계 누락, 월 비용 추산, 키 제한 및 실제 요청 목록을 사용자에게 제시한 다음 실제 기록용 연결 여부를 결정한다.

## 입력·출력과 표시 설계 제안

입력은 선택된 지도 설정, 카메라 범위·확대 수준과 읽기 전용 TimelineData다. 지도 서비스로 보낼 정보와 브라우저 안에만 남길 정보를 별도 경계로 둔다. 출력은 지도 배경·이름·경계와 기존 관측/연결의 중첩 표시이며, 지도에서 얻은 장소 정보를 원본 기록이나 자동 방문으로 기록하지 않는다.

초기 PoC의 확대 단계는 다음처럼 평가한다. 숫자는 확정 제품 정책이 아니며 실제 렌더러·자료의 확대 범위에 맞춰 조정하고 기록한다.

| 단계 | 표현 목표 | 평가 기준 |
| --- | --- | --- |
| 지구 전체 / z0–4 상당 | 국가 이름·국경 | 뒤편 라벨 미표시, 라벨 겹침 억제, 관측 대비 확보 |
| 지역 / z5–8 상당 | 1차 행정구역 이름·경계, 주요 도시 | 국가별 행정 단계 차이를 별도 매핑 |
| 도시 / z9–12 상당 | 도시 이름·행정 경계 | 도시 이름만 있고 경계가 없는 경우 누락으로 기록 |
| 근접 / z13 이상 상당 | 제공되는 상세 경계·이름 | 1m·10m·100m 관측, 동일 좌표, 경계와 경로의 구별 |

행정 단계 숫자를 전 세계에서 동일한 의미로 해석하지 않는다. 지도 자료에 없는 경계를 좌표 주변 원이나 임의 polygon으로 만들지 않는다. 이름의 한국어 우선/현지어 fallback 및 분쟁 경계 표시 방식은 도입 전 결정한다. 사용자 이동 연결의 점선과 지도 분쟁 경계의 점선은 별도 색·범례를 사용해야 한다.

## 외부 요청과 개인정보 — 승인 필요

현재 앱의 외부 요청 0건 정책을 유지한다. 서비스 검토 승인만으로 CSP·외부 도메인 허용을 바꾸지 않는다.

타일 API는 확대 수준과 x/y 타일 주소를 요청한다. 따라서 원본 JSON을 보내지 않더라도 실제 관측을 따라 이동하는 화면의 타일 요청으로 열람 지역이 서비스에 드러날 수 있다는 것이 API 구조에 따른 판단이다. IP와 요청 시각 등의 네트워크 메타데이터도 외부 요청에 수반된다. 이를 단순히 “사용자 데이터 외부 전송 없음”으로 설명하지 않는다. [MapTiler 타일 요청 구조](https://docs.maptiler.com/cloud/api/tiles/)

도입 승인 시 검토할 허용 목록은 지도 스타일·타일·글리프·스프라이트 등 지도 표시 리소스다. Timeline 본문, 관측 ID·시각·전체 좌표 배열, 사진·파일명·EXIF, 방문 상태를 요청 본문·검색 query·분석 이벤트에 넣지 않는다. 역지오코딩, 위치 검색, 자동 분석, 지도 SDK telemetry는 별도 승인 없이 활성화하지 않으며 실제 네트워크로 확인한다. 공급자가 저장하는 요청 로그의 범위·보존 기간은 아직 조사 완료되지 않았고 서비스 채택 전 확인해야 한다.

브라우저용 키는 클라이언트에서 볼 수 있다. 비밀 서버 키를 번들에 넣지 않는다. 운영 도메인과 로컬 개발 origin에 한정한 키 제한, 사용량 알림·상한, 만료/회수 방식을 확인한다. [MapTiler 키 안내](https://docs.maptiler.com/guides/credentials/api-key/)

## 예외와 실패 처리 제안

- 키 없음·권한 실패·quota 초과·오프라인에서는 고정 코드와 지도 사용 불가 안내를 표시하고 로컬 관측 목록을 보존한다.
- 상세 경계 누락과 네트워크 실패를 구별한다. 실패한 타일을 임의의 경계로 대체하지 않는다.
- 외부 지도 사용을 끄거나 앱이 종료되면 요청·이벤트·렌더러를 정리한다. 실패 시 무한 재시도와 무제한 타일 캐시를 만들지 않는다.
- 사용자에게 관측·사진의 보존과 외부 지도 캐시를 구별해 안내한다. 공급자 약관 및 캐시 보존 정책 검토 전 영구 캐시는 추가하지 않는다.

## 검증과 완료 기준

- [ ] 서비스·렌더러·비용 상한·키·전송 범위 결정 및 해당 문서 반영
- [ ] 실제 기록과 무관한 공개 검증 지역의 국가·지역·도시 경계 및 이름 커버리지 확인
- [ ] 한국·일본·미국·유럽 등의 상이한 행정 단계, 날짜변경선·극지방·섬·경계 누락 확인
- [ ] 확대 단계 전환, 라벨 충돌, 선택 대상 가림, 근접 점·선 정렬 및 회전 검증
- [ ] 같은 좌표의 별도 관측·방문 ID 유지, 원본 경로와 추정 연결 구별
- [ ] 승인된 요청 외의 네트워크 통신과 민감한 본문·URL·로그 없음 확인
- [ ] 키 없음·오프라인·403·429·타일 누락·WebGL 실패 및 종료 시 자원 정리 검증
- [ ] 자동 합성 검증과 사용자 실제 기록의 로컬 확인 결과 구별

현재 위 항목은 수행 완료가 아니다. Edge를 기존 검증 기준으로 사용하며 추가 브라우저 지원은 미확정이다.

## 사용자 결정 및 인계

다음 결정은 제안 후보의 합성 PoC에 대한 승인과 사용할 지도 계정/키 제공 방식이다. 실제 기록 화면의 타일 요청 허용, 예산, 경계 언어·관점은 따로 확정해야 한다. 답변이 없으면 이를 추측해 도입하지 않는다.

화면 작업 브랜치 `codex/globe-ui`에서 이어간다. 패키지·잠금·공통 설정 변경은 데이터 작업과 조율한 뒤 한 담당자가 수행한다. 상세 지도·방문 지정·데이터 통합·사용자 로컬 검증이 남아 있으면 전체 화면 목표 완료나 PR 병합 가능 상태로 보고하지 않는다. 사진은 MVP 이후 확장이므로 현재 완료 조건에서 제외한다.
