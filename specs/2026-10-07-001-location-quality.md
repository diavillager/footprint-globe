# 위치 오류 의심 검사와 표시·매핑 분리

상태: 2026-10-07 사용자가 아래 정책을 확정했으며 구현·합성 검증을 완료했습니다. 실제 파일에서의 유용성 확인은 사용자의 로컬 확인으로 남습니다. 배포·병합은 범위 밖입니다.

## 목적과 기존 흐름

실제 화면의 위치나 지역 이름만으로 오류를 확정하지 않습니다. 현재 지원 입력은 `rawSignals.position`이며 파서는 좌표·시각을 검증하고 정확한 나노초 순서로 정렬합니다. 기존 앱은 모든 유효 인접 관측을 연결하고, 전체 관측으로 Wikimedia 지역 조회 → 후보 대조 → 장소 묶기 → 표시용 통합을 수행했습니다.

기존 [랜드마크 명세](2026-10-07-000-landmark-integration.md)의 긴 공백 연결 유지 정책을 아래 연결 정책으로 대체합니다. 100m·120분 장소 묶기와 50m 표시용 통합은 오류 판정 기준과 별개입니다. PRD의 원본 보존·실제 이동과 추정 연결 구분 원칙을 따릅니다.

## 확정된 탐지 기준

다음 조건을 모두 만족할 때만 오류 **의심**으로 분류합니다.

- 이탈 직전과 복귀 직후에 각각 최소 2개 관측이 1분 이상 이어지며, 각 경계 관측의 100m 이내에 머뭅니다. 연속 관측을 검사하며 30분 초과 공백은 지속성 근거로 사용하지 않습니다.
- 출발·복귀 관측은 200m 이내입니다.
- 사이의 단일 또는 연속 관측은 출발 위치에서 모두 1km 이상 떨어져 있습니다.
- 이탈 관측의 첫 시각부터 마지막 시각까지 5분 이하, 출발부터 복귀까지 10분 이하입니다.
- 출발→첫 이탈, 마지막 이탈→복귀의 두 속도 모두 300km/h 초과입니다. 시간 차가 0 이하이면 속도 근거로 쓰지 않습니다.
- 동일 시각 위치 충돌과 겹친 구간은 자동 제외하지 않습니다.

고속·원거리라는 이유만으로 제외하지 않습니다. 지속적인 고속 이동, 장거리 편도 이동, 긴 체류 뒤 재방문에는 위 조합이 성립하지 않습니다. 최초 복귀 또는 근거리 중간 관측에서 검사를 끝내며, 조건에 맞게 기록을 건너뛰어 묶지 않습니다.

### 정확도

저장소의 rawSignals 지원 필드에 `accuracyMeters`가 존재합니다. 해당 필드가 유한한 0 이상의 숫자일 때만 선택적으로 원본 값 그대로 보존합니다. 문자열·음수·null·누락은 값이 없는 것으로 처리하며, 좌표·시각이 유효하면 관측 자체는 유지합니다. 값을 생성하거나 0으로 보정하지 않습니다.

정확도는 단독 제외 사유가 아닙니다. 이탈 거리 및 진입·복귀 속도의 근거에서 제공된 양끝 정확도 반경을 차감(최소 0)하여 의심 판정을 약화하는 방향으로만 사용합니다. 지속성·복귀는 실제 관측 좌표로 확인합니다. 이 차감은 통계적으로 보장된 오차 한계가 아닙니다. [Android Location.getAccuracy](https://developer.android.com/reference/android/location/Location#getAccuracy())는 수평 정확도를 미터 단위 추정 반경으로 정의하지만, 모든 Timeline 내보내기가 동일한 신뢰도 의미를 보장한다는 주장은 하지 않습니다. 샘플 생성 도구가 치환한 0 역시 정확한 위치라는 증거로 취급하지 않습니다.

## 연결 정책

- 인접 관측 간 공백이 **30분 초과**이면 연결하지 않습니다(정확히 30분은 유지).
- 동일 시각의 관측 묶음 안에서 1km 이상 떨어진 좌표 쌍이 있으면 해당 시각 묶음 전체를 충돌로 표시하고 어느 쪽도 자동 숨기지 않습니다. 중간 좌표가 끼어도 검사하며, 서로 다른 나노초 시각을 같은 시각으로 오인하지 않습니다. 불확실한 관측의 앞뒤 연결을 끊습니다.
- 숨긴 관측의 앞뒤를 새로 연결하지 않습니다. 연결은 원본에서 인접했던 두 관측 중 유효한 경계에만 생성합니다.
- 개별 복원 뒤에도 남은 숨김·공백·충돌 기준을 다시 검사합니다. 완전히 복원하면 원본 인접 연결을 복구할 수 있지만 긴 공백·충돌은 계속 끊습니다.
- 같은 연결 중단 경계로 장소 방문 묶음을 분리하고 표시용 통합선도 생성하지 않습니다. 같은 장소의 여러 기록을 표시용으로 합치더라도 끊긴 구간의 연결을 되살리지 않습니다.

## 데이터와 UI

원본 `TimelineData.observations`는 수정하지 않습니다. 별도 `QualityReport`에 원본 ID별 의심 근거·시각 충돌을 보관합니다. 가져오기 worker에서 한 번 판정하고, 복원 시 판정을 다시 수행하지 않습니다. 별도 projection이 표시·매핑용 관측, 허용된 연결, 연결 중단 경계, 제외 ID를 생성합니다.

- JSON 등록 때 **오류 의심 지점 숨기기 기본 켬**입니다. 검사 후 제외된 관측으로만 지역 조회 계획을 만들고, 기존 파일별 동의 뒤 매핑합니다.
- 원본 경로는 표시 대상의 개별 관측, 장소별 보기는 같은 대상의 장소 중심 통합입니다. 전체 원본은 위치 기록 목록과 숨기기 해제로 확인합니다. 분포 계산은 원본 인접 관측 기준을 유지합니다.
- 위치 검사에는 원본·의심·숨김·복원·충돌 건수와 연결 중단 건수, 원인, 개별 복원/복원 취소를 표시합니다. 위치 기록 목록에서도 원본별 사유와 복원을 제공합니다. 숨겨진 관측을 목록에서 선택하면 원본 좌표를 팝업으로 확인할 수 있고, 그것만으로 매핑 대상은 변경되지 않습니다.
- 숨기기·복원으로 실제 제외 ID가 바뀔 때만 기존 매핑을 중단하고 결과·후보·사진·번호 띠를 초기화합니다. 원본 경로로 돌아가고 자동 조회하지 않습니다. 위치 검사에서 ‘현재 지점으로 장소 매핑 안내 열기’ 후 허용해야 다시 조회합니다.
- 파일 교체·지우기·새로고침 시 판정과 복원 상태를 폐기합니다. 새 외부 전송이나 영구 저장은 없습니다.

## 검증과 한계

실제 JSON을 읽거나 출력하지 않고 합성 데이터로 정상 이동, 단일·연속 튐, 안정성 부족, 진입 또는 복귀 속도 부족, 30분 경계·긴 공백, 동일 시각 충돌, 실제 고속철도·항공 이동, 긴 체류·재방문, 정확도 유효성·누락, 개별/부분 복원, 장소 조회 전 제외, 번호 띠·매핑 초기화와 재동의를 검증합니다. 100,000개 관측 검사도 확인합니다.

임계값은 사용자가 승인한 보수적인 초기 휴리스틱이며 실제 데이터로 정확도를 검증한 모델이 아닙니다. 낮은 속도로 발생한 위치 오류, 복귀가 없는 오류, 전후 근거가 부족한 오류, 오래 지속된 오류는 남을 수 있습니다. 실제로 짧게 고속 왕복했다면 의심으로 표시될 수 있으므로 원본 확인과 복원을 제공합니다. 관측 연결은 실제 도로·이동 수단을 추정하지 않습니다.

## 2026-10-07 미탐지 진단과 불필요한 초기화 수정

사용자 로컬 확인 결과(원본 10,123개, 의심·숨김·복원·충돌 각 0개, 긴 공백 17곳)는 초기 판정으로 해당 사례를 탐지하지 못했음을 보여줍니다. 실제 JSON에 접근하지 않았으므로 미탐지의 구체적 원인은 아직 특정하지 않습니다. 3km 이탈·복귀의 각 이동에 1분이 걸리는 합성 사례는 300km/h 조건을 충족하지 않아 탐지되지 않음을 확인했습니다. 임계값은 승인된 값을 유지합니다.

- 체크 상태가 아니라 실제 제외 ID 집합으로 매핑 세션을 유지·초기화합니다. 의심 0개, 전체 복원, 숨기기 해제 상태의 복원 변경처럼 대상이 같은 조작은 결과·동의·장소별 보기·선택을 유지하며 새 요청하지 않습니다. 대상 변경 시에는 기존 수동 재매핑 정책을 유지합니다.
- 위치 검사에서 탐지 대상이 없으면 빈 ‘관측을 선택하세요’ 목록 대신 미탐지 안내를 표시합니다.
- ‘탐지되지 않은 이유 확인’은 1km 이상 인접 변화에서 검사한 이탈 시작 후보별 최초 미충족 조건을 집계합니다. 정확도 차감 후 거리, 진입 속도, 이탈 전 지속성, 복귀 구간, 복귀 속도, 복귀 후 지속성, 시각 충돌을 구분합니다. 후보 집계는 오류 관측 수가 아니며 탐지된 연속 구간 내부는 중복 검사하지 않습니다. 진단은 worker/브라우저 메모리에만 두고 새 전송·저장은 추가하지 않습니다.
- 사용자 화면의 메모리 기록을 보존하기 위해 현재 4175 서버·dist는 갱신하지 않고 별도 로컬 복사본에서 검증합니다.

추가 검증: 격리된 소스 복사본에서 `npm run check`(66 + 154 = 220개 테스트·타입 검사·빌드)와 Edge 개발/빌드 `location-quality-smoke.cjs`를 통과했습니다. 의심 0개 및 전체 복원 상태에서 체크 전환 후 세션·장소별 보기·번호 띠 유지와 추가 요청 없음, 실제 제외 ID 변경 시 기존 초기화 흐름을 확인했습니다. 사용자 확인용 수정본은 별도 로컬 Preview `http://127.0.0.1:4185/`에서 제공합니다. 기존 4175 서버와 빌드 산출물은 유지하며 실제 데이터는 읽지 않았습니다. 다음 확인은 이 수정본에서 장소 매핑 없이 원본 JSON을 직접 등록한 뒤 ‘위치 검사 → 탐지되지 않은 이유 확인’의 집계만 확인하는 것입니다. 탐지 기준 변경은 이 근거를 검토하고 사용자와 확정한 뒤 진행합니다.

### 복귀 패턴을 끝까지 평가하는 추가 진단

사용자가 제공한 집계는 이탈 시작 후보 309건 중 정확도 반영 후 거리 부족 36건, 진입 속도/시간 차 조건 미충족 268건, 이탈 전 지속성 부족 5건이었습니다. 이는 자동 판정의 최초 탈락 조건이며, 복귀 관련 0건은 뒤 단계를 검사한 후보가 없었다는 뜻입니다. 이 정보만으로 268건을 실제 오류로 지정하거나 속도 기준을 낮추지 않습니다.

동일한 이탈 시작 후보를 대상으로 진단용 추가 평가를 수행합니다. 속도·정확도 조건에서 멈추지 않고 관측 좌표에 따른 1km 이탈, 200m 이내 복귀, 5분 이내 이탈 구간·10분 이내 왕복, 전후 각각 100m·1분 이상 지속성과 시각 충돌을 확인합니다. 전후 지속성·짧은 복귀가 모두 맞는 후보 수, 그중 정확도 차감 후 거리까지 맞는 수, 그중 양쪽 속도가 각각 100·200·300km/h를 초과하는 수를 표시합니다. 각 항목은 겹치며 합산하지 않습니다. 100·200은 비교 진단일 뿐 적용된 판정 기준이 아닙니다. 후보가 추가로 숨겨지거나 매핑 대상에 반영되지 않습니다.

진단의 좌표·시각·ID는 외부로 내보내지 않으며 집계만 UI에 표시합니다. 밀집 관측의 반복 검사에는 2,000,000회 루프 작업 한도를 두고, 완료하지 못한 후보는 미충족으로 계산하지 않고 ‘처리 한도로 미검사’로 따로 표시합니다. 기존 자동 판정에는 이 진단 한도를 적용하지 않습니다. 새로고침·재등록은 사용자가 직접 수행하며 현재 열린 탭을 자동 갱신하지 않습니다.
