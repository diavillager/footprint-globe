# MVP 병렬 개발 공통 기반

상태: 공통 계약 정리와 분리 준비 검증 완료. PR #8의 병합·브랜치 정리를 2026-10-06에 사용자가 승인했다. 실제 병합 상태는 PR에서 확인하며 MVP 완료를 의미하지 않는다.

## 목적과 관련 요구사항

[PRD](../docs/PRD.md)의 로컬 파일 처리·지구본 탐색·사진 연결 흐름을 데이터 처리와 화면 작업으로 나누기 위한 기반이다. 사용자는 사진을 붙일 방문을 직접 지정하기로 결정했다. 모든 유효 관측을 잇는 미리보기는 구현됐으며, 실선/긴 공백 점선 비교는 [로컬 미리보기 명세](2026-10-06-002-local-preview.md)를 따른다. 최종 제품 표시 정책은 미확정이다.

## 이번 범위

- React·TypeScript·Vite 앱 실행, 타입 검사, 합성 테스트, 배포용 빌드 환경
- React나 지구본 라이브러리에 의존하지 않는 공통 자료형
- 화면 담당이 실제 파서 없이 사용할 완전 합성 데이터와 비동기 대체 함수
- PRD 결정 반영, 파일 담당 범위와 병합·검증 순서

기존 rawSignals 파서·지구본 미리보기는 유지하고 공통 계약으로 연결한다. 이번 마무리는 입력 형식 확대, 근접 확대, 사진 첨부, 방문 지정 UI와 worktree 생성을 포함하지 않는다. 기존 샘플 생성기의 지원·치환·제외 정책은 변경하지 않는다.

## 공통 계약

코드 기준은 [timeline.ts](../src/domain/timeline.ts)다.

| 자료형 | 의미와 소유권 |
| --- | --- |
| TimelineData | 데이터셋 ID, 위치 관측, 원본 방문, 원본 경로. 데이터 담당이 반환하고 화면은 읽기 전용으로 소비 |
| Observation | 별도 ID, 십진수 위도·경도, 원본 시각 표현 및 비교용 epoch 밀리초 |
| RecordedVisit / RecordedPath | 원본이 명시한 기록. 추정 연결이나 사용자가 지정한 방문과 혼합하지 않음 |
| ManualVisit | 사용자가 관측점을 선택해 지정한 방문. 방문 ID·데이터셋 ID·관측점 ID로 연결 |
| PhotoAttachment | 방문 ID·데이터셋 ID와 세션 내 Object URL. 화면 담당이 생성·해제 책임 |
| ParseResult | 성공 여부에 따른 결과와 고정 코드·집계 건수. 원본 값·필드명·파일명·예외 메시지를 진단에 넣지 않음 |

파서 경계는 `(text, datasetId) => Promise<ParseResult>`이며 실제 진입점은 `src/parser/index.ts`의 `parseTimeline`이다. Promise 자체가 별도 스레드를 만드는 것은 아니다. 화면 측 `preview.worker.ts`가 호출하며 `importFile.ts`가 파일 크기 검사·읽기·고정 오류 변환을 맡는다. 화면은 파일 선택, 데이터셋 ID 발급, worker 생성·종료·이전 응답 무시를 책임지고 데이터 측은 JSON 판별·검증·정규화를 맡는다. 입력 자체를 콘솔·서버에 전달하지 않는다.

공통 `ParseResult`는 실제 미리보기의 형태로 통일한다. 성공은 `{ ok: true, data, counts }`, 실패는 `{ ok: false, code, counts? }`다. 이전 준비용 `diagnostics` 배열과 별도 `PreviewResult` 형식은 사용하지 않는다. 오류 코드는 INVALID_JSON, UNSUPPORTED_FORMAT, INPUT_LIMIT, NO_VALID_POSITIONS, FILE_READ_FAILED이며 마지막 코드는 파일/실행 경계의 안전한 실패다. 실패에 counts가 없으면 미검사 또는 검사 미완료이며 0건이라는 뜻이 아니다.

`ImportCounts`는 현재 rawSignals용 집계다. input은 전체 신호, accepted는 유효 위치, ignoredSignals는 위치 외 신호, invalidPositions는 잘못된 위치, ignoredRootFields는 미사용 최상위 필드 수다. 전체 검사 후 input = accepted + ignoredSignals + invalidPositions이며 ignoredRootFields는 별도 단위다. 다른 형식으로 확대할 때 이 집계를 임의로 재해석하지 않고 공통 계약을 조율한다.

관측 시각의 원본 표현은 정밀도·시간대 확인을 위해 메모리에 유지하며 화면 표시 시간대는 후속 결정이다. `epochMs`만으로 밀리초 미만의 순서를 확정하지 않는다. ID는 데이터셋 안에서 고유하고 필터·정렬·표시 단순화 중 유지한다. 새 파일 선택은 새 데이터셋이며 파일 간 ID 복원이나 사진 영구 보존은 제공하지 않는다.

관측점 ID는 방문 ID와 다르다. 같은 좌표의 다른 시각 기록을 합치지 않는다. 사용자 지정 방문에 임의의 체류 기간을 넣지 않는다. 사진의 URL은 데이터셋 교체·사진 제거·컴포넌트 종료 시 해제해야 한다. 해당 동작은 화면 구현 단계에서 검증한다.

## 합성 데이터

[합성 fixture](../src/fixtures/timeline.ts)는 사용자 파일이나 생성 샘플을 복사하지 않고 작성한다. 0 좌표, 다른 위치, 같은 좌표로의 재방문, 긴 시간 공백을 포함한다. 경로·원본 방문 배열은 비어 있으며 자동 연결하지 않는다. 수동 방문 예제는 같은 좌표의 두 관측에 서로 다른 ID를 연결한다.

`syntheticParser`는 입력을 해석하지 않는 화면 개발용 대체 함수다. 실제 파일 선택에 연결하지 않는다. 원본 형식별 parser fixture는 데이터 담당이 기존 완전 합성 입력을 활용해 추가한다.

별도로 작성한 기록된 방문·경로 예제와 빈 입력 실패 결과도 제공한다. 이는 화면 상태 개발용이며 원시 관측점에서 경로를 추론하거나 실제 입력 형식의 지원을 확정한 것이 아니다. 화면의 합성 체험 결과도 파서 호출 없이 생성해 데이터 구현과 독립적으로 확인한다.

## 파일 담당 범위

| 담당 | 주 수정 범위 | 경계 |
| --- | --- | --- |
| 데이터 처리 | `src/parser/`와 그 테스트 | 기존 rawSignals 구현·한도를 시작점으로 검증·정규화 보완. `parseTimeline` 공통 계약 유지, UI·지구본·File·사진 URL에 의존하지 않음 |
| 화면·통합 | `src/app/`, `src/features/`, `src/main.tsx`, `tests/app-smoke.cjs` | 파일/worker 수명 관리, 지구본·연결 표시, 이후 승인된 방문 지정·사진 기능. 독립 합성 결과로 개발하고 실제 파서도 공통 진입점으로 연결 |
| 공통 변경 조율 | `src/domain/`, `src/fixtures/`, 패키지·잠금·빌드 설정, PRD·README·spec | 한 담당자가 변경하고 양쪽이 같은 계약 버전을 사용 |

현재 `codex/mvp-foundation`의 공통 작업 PR을 검토하고 사용자 승인 범위에서 main에 병합한 뒤, 두 작업이 그 병합 커밋에서 출발한다. 각 담당은 자기 범위에서 수정별로 커밋·푸시하고 전체 목표가 완료될 때 PR을 준비한다. 데이터 처리 변경을 먼저 검토·승인 후 병합하고 화면 작업에서 최신 main을 반영해 통합한다. 통합 수정은 화면 브랜치를 재사용한다. 공통 파일 변경이 필요하면 양쪽을 임의로 바꾸지 않고 한 담당자가 조율한다. worktree 생성과 병합·정리는 각각 사용자 승인 범위에서 수행하며 별도 통합 브랜치를 기본으로 만들지 않는다.

## 실행과 검증

앱은 Node 22.12 이상을 요구하며 Node 24 환경에서 검증한다. 의존성 버전은 package-lock.json으로 고정한다. 샘플 도구는 계속 설치 없이 브라우저에서 실행할 수 있다.

- 앱 타입 검사, 합성 계약 테스트, 프로덕션 빌드
- 기존 샘플 도구 전체 회귀 테스트
- 같은 파일 소비 코드에 실제/합성 파서를 교체 주입해 성공·부분 실패·빈 데이터·크기 초과·읽기 실패 검증
- 브라우저에서 실제 파서의 합성 파일 처리, 독립 합성 체험, worker 복구·지우기, 두 연결 표시·점선 개별 확인과 외부 요청 0건 검증
- 실제 원본·생성 샘플·사진의 Git 제외와 빌드 결과 제외 확인

앱은 로컬 미리보기 파일 선택을 제공한다. public 디렉터리 자동 복사를 끄고, 개발 서버도 private/local-data와 JSON·사진·환경 파일을 직접 제공하지 않도록 제한한다. 개발 서버 통신은 로컬 코드 제공 용도이며 실제 데이터를 서버 요청으로 보내는 기능은 허용하지 않는다.

## 남은 결정과 인계

- 현재 출발점: rawSignals 위치, 64 MiB·100,000개 신호, 잘못된 위치 제외, 유효 관측 전체 연결. 미리보기 정책을 MVP 전체 지원 보장으로 확대하지 않는다. 추가 형식은 지원 결정과 별도 합성 검증이 필요하다.
- 화면 담당 인계: 가까운 관측점 사이의 점선이 현재 확대 범위에서 보이지 않는 한계. 데이터 누락이나 해결 완료로 취급하지 않는다. 근접 렌더링 개선은 별도 범위를 정한 후 진행한다.
- 사용자 결정 필요: 실제 시각을 화면에 표시하기 전 표시 시간대, 추가 브라우저 지원 범위, 최종 실선/점선 정책. 현재 미리보기는 절대 시각을 표시하지 않으며 브라우저 자동 검증은 Edge 기준이다.
- 사진·방문 구현 시 세션 보존과 Object URL 정리, 데이터셋 교체·동일 장소 재방문 연결을 화면 담당이 검증한다. 자동 방문 추론과 영구 저장을 추가하지 않는다.

위 사항은 독립 개발용 공통 계약 검증을 막지 않지만 해당 기능을 구현하기 전 해결해야 한다. 공통 기반 준비 완료는 근접 표시 문제 해결, 모든 실제 JSON 호환성, MVP 완료 또는 병합 승인을 뜻하지 않는다.
